# Band 00A10000-00A4FFFF: XLive, network console and movie bases (packet cc13-sweepA1)

Worker cc13-sweepA1, 2026-10-12. A naming and reconstruction sweep of the non-gameplay code in
00A10000-00A4FFFF. The band divides at 00A38D80: below it is AI and Lua AI bindings (gameplay,
left for cc9); above it is the XLive online system, its voice/session/matchmaking/QoS parts, the
network console classes, small STL copies, the movie decoder bases and the iometrics telemetry
library.

Status words: **named** (ledger record plus Ghidra rename and evidence comment), **tagged** (library
row in `config/tags`, applied in Ghidra), **defined** (Ghidra function created from the listing under
the write lock), **reconstructed** (C++ in `src/network_online_cc13.cpp`), **build-tested** (compiles
in `scripts/build.ps1`). Nothing here is fixture-tested, ABI-compatible or game-validated, and
nothing is wired into the game hosts. Every name is a hypothesis; the only recovered identifiers are
the log strings quoted below, the XHV2 method order and the voice-mask and error-text strings.

## Method

1. Listed the untagged, unnamed `FUN_` in the band from the index and decompiled all 299 in the
   non-gameplay range live (`local/sweepA1_dec.py`).
2. Scanned the PE on disk for vtables pointing into the band (`local/sweepA1_vt.py`) and split them by
   constructor writes. Only the telemetry and iostdnet classes carry RTTI; the game classes do not.
3. Assigned sub-object methods by the ECX set-up at every direct call site (`local/sweepA1_ecx.py`):
   the constructor 00A47EE0 builds its parts with `LEA ECX,[ESI+184h/1AE8h/1C24h/2098h]`, and every
   method of each part is called with the same offset.
4. Found code that no Ghidra function contains: rel32 call and jump targets, `.rdata` pointers and
   thunk targets in the band (`local/sweepA1_gaps.py`, 93 hits). Nine were interior targets or data and
   were skipped; 84 were defined with `tools/ghidra_define_function.py` from linear-sweep bounds checked
   against INT3 padding, plus 00994100 and 00994110 outside the band.
5. Named through `bsp.py ledger add-name` and applied with `tools/ghidra_annotate.py --apply`
   (previous values in `local/ghidra-annotations-20261012T114222Z.json`); tags through
   `ghidra_tag.apply` on this doc's rows only (`local/ghidra-tags-sA1-*.json`).

**Network mode.** Slot +1A0h stores +60h. `BSP_MainMenu_RequestSessionStates` (005E6F70) passes 1 and
`BSP_MultiMenu_RefreshOnlinePlayerList` (00689310) passes 0. Mode 1 together with `game+218Ch` makes
the client enumerate servers by broadcast to port 3EBh ("EnumeratingServers %d", " GameFound - HA:
...", 00A39900) and the host answer with a 14Ch-byte reply carrying L"GameName" (00A3D540), and it
skips arbitration (00A43220). Mode 1 is therefore read as system link; the names `IsLiveMode` and
`IsSystemLinkMode` stay provisional.

**Vtable 00D24878** has 110 slots. 54 of them had no Ghidra function and were defined here. Each
slot's ledger evidence starts with its offset ("Slot +ACh: ..."). Highlights:

- +04h Startup(game), +08h Shutdown (XOnlineCleanup), +0Ch Update (per-frame pump), +74h last error
  text, +80h the player list for the current mode, +88h/+8Ch begin/cancel a session search;
- +A4h..+E4h voice: restart, incoming voice packet (10-byte frames through XHV2
  SubmitIncomingChatData), add/remove remote talker, mute flags, voice masks, reset;
- +158h/+15Ch join/remove a player through the client (00A39C50, 00A396E0, 00A39F00) or the host
  session (00A49B90, 00A4B180); +168h arbitration; +16Ch host CSession::Create; +170h delete;
- +184h WriteSessionStats (`BSP_OnlineStats_WriteSessionStats`), +188h a stats-only XSession
  (flags 706h, purpose provisional);
- 30 slots are stubs (RET, RET n, return 0/1, FLDZ), named `..._Nop_SlotNN`, `..._ReturnTrue_SlotNN`,
  `..._ReturnFalse_SlotNN`;
- byte-identical pairs: +40h/+44h (00A47A60/00A47A80), +18Ch/+190h (00A433F0/00A43460), and the
  non-slot pairs 00A4B250/00A4B460 and 00A4AFD0/00A4B410. Each pair keeps one name plus `_Copy`.

**Voice masks.** Table 00D24734 holds twelve pointers. Read from the installed PE, they are
`voice_mask_none`, `voice_mask_anonymous`, `player_sun`, `player_jed`, `player_jenna`,
`player_sarama`, `player_angul`, `player_machiko`, `player_jinx`, `player_amran`, `player_roosta`
and `player_vorsh`.

**Error text (slot +74h, 00A44EC0).** The text starts as "Unknown". When flag +124h is set and the error
is non-zero, the text is "live_err_update_required". Otherwise the error selects it:

- 80151000h and 80151004h give connection_lost;
- 80151001h cannot_access_service, 80151003h servers_too_busy, 80151005h duplicate_logon and
  80151006h invalid_user;
- 80155100h invalid_session_id, 80155109h "Session Match overflow" and 60192009h sys_link_no_cable_err;
- 0 erases the string (00A44840, std::string erase, now tagged);
- 80151002h and every other value give live_err_unknown.

The jump table is at 00A44FF4.

## Voice chat (+1C24h)

The engine at voice+78h is called by XHV2 vtable offsets: +04h Release, +0Ch/+10h
Start/StopLocalProcessingModes (with the mode words at 00D24A34/00D24A30), +14h
StartRemoteProcessingModes, +20h/+24h Register/UnregisterLocalTalker, +28h/+2Ch
Register/UnregisterRemoteTalker, +30h GetRemoteTalkers, +34h IsHeadsetPresent, +38h IsLocalTalking,
+3Ch IsRemoteTalking, +44h GetLocalChatData, +48h SetPlaybackPriority and +4Ch SubmitIncomingChatData.
Every call in the band fits that order. Talkers are 38h-byte records (XUID, then per user slot a
priority, a mute-list word and a game-mute word) in a 380h-byte array (16 records). A non-zero mute
word sends priority -1. `BSP_XLiveSystem_UpdateFriendsAndVoice` (00A46480) sends MT_VOICECHANGE: E8h in
the 00E0AB68 name table, built by 00A42FB0 with vtable 00D03278.
