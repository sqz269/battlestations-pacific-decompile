# Native MPKG name enumeration, BF

`00BB98F0` is the numeric MPKG provider `+14h` method: it loads the archive pointer from provider `+14h` into ECX and tail-jumps to `00BB97B0`. The latter receives the original directory and extension string headers, flag DWORD and actual output `0Ch` string vector on the stack, and returns with `RET 10h`. Its central directory is an ordered array of `24h` rows at archive `+28h`, with signed count at `+2Ch`. It calls the existing `00BEE340` filter on each row's name header and the **original** directory, then `004CDC20` to append the complete stored name. It does not clear, sort or deduplicate the output.

The function copies the directory to a temporary pooled string, appends `/` if the temporary's last byte differs, then discards it. The filter never receives this modified temporary. The last-byte read is unconditional, so an empty directory can read before its data buffer; such invalid native input has no defined source parity claim. The slash temporary is released before the directory temporary; exceptional cleanup uses reverse construction order. The caller supplies the actual pooled string services, original numeric filter pattern data at `00E17BF0`, and valid raw archive/provider storage. No archive installation or gameplay run was performed.

The two complete native envelopes match disk and live bytes and every saved instruction owner: `00BB98F0..00BB98F8` (8 bytes, 2 instructions, SHA256 `ba0187b768c21f5b75aa5df70de8d5cf6a2b6fcbb96333043b46624d1721ebaa`) and `00BB97B0..00BB98EF` (319 bytes, 109 instructions, SHA256 `0164b11c0dbcc07f24e5d53d65d5502ae5ef9d909000476e824f2e646fca9b90`). The report verifies 11 direct CALLs inside BB97B0. BB98F3 is a tail JMP, recorded separately. Source was compiled as an explicit MSVC Win32 translation unit; shared CMake registration and the combined build remain with the primary integrator. Original FH3/SEH, malformed storage and actual archive behavior are not established.
