# Actual VFS enumeration visitor (BF)

This source packet adds an enumeration-specific actual-manager route. `00BDD990` receives ECX actual A0h manager and four stack words (directory, extension, flags, output list), RET10h. It constructs the actual 14h `D6846C` visitor through `00BDBE20`: current vtable at `+0`, copied pooled extension at `+4/+8`, low flags byte at `+C`, caller-owned actual intrusive result list pointer at `+10`. It passes the directory **without normalization or aliases** to `00BDD0A0`, then `00BDB6E0` releases the extension and writes base identity `D68380`. The output list is owned by the caller, including its sentinel and nodes.

`00BDD0A0` sets manager+18 to `FFFFFFFF`, copies the directory, and visits the actual manager+3C mount tree in iterator order. Empty virtual prefixes match all; a nonempty prefix must be shorter than the name, equal case-insensitively over its counted length, and followed by `/`. A matching mount passes the copied relative suffix to the visitor's current `+4` entry. The `D6846C` `+8` entry is `00BDBEB0`, a constant false, so this visitor continues across every matching mount. Other visitor profiles are already handled by separate existing source routes; this new `00BDD0A0` interface explicitly covers only the enumeration profile.

At `00BE1130`, callback ECX is the 14h visitor and the two stack arguments are actual mount payload and suffix. It captures the current mount provider at payload+8, current numeric provider table+14 target, flag byte, and extension header. That target must fill an actual 0Ch vector of eight-byte names. The source requires `NativeVfsProviderEnumerationDispatch::enumerate_entry` for the captured entry; unsupported entries cannot return empty success. Each vector element is copied into a by-value pooled header and passed to `00BE0FC0`, which searches the caller's actual 0Ch linked list by recorded length and case-insensitive comparison. A missing name is appended before the sentinel through the existing 004CE6F0 node-copy and 004CE780 count-growth bodies, preserving the first spelling and provider/mount order. A duplicate calls the required native diagnostic sink with the name (or actual `0109CEF0` empty data). The by-value string is released afterward. The provider vector is shrunk/freed after iteration. This does not convert results into a projected `std::vector`.

The provider dependency is material. The current numeric D641F8 MPAK table+14 is `00BB5F40`, with a concrete `NativeMpakRuntime::enumerate_entry` operation. Physical D69168 table+14 is `00BF47E0`, FileStore D689E8 table+14 is `00BE6480`, and MPKG D64390 table+14 is `00BB98F0`. The repository has projected `PhysicalDirectory::enumerate_00bf47e0_fragment` and `FileStore::enumerate_00be6480`, but no actual-provider source implementations for those three captured entries. A production binding must add those exact raw operations or report an unsupported target; a physical-only, projected-provider, or empty-vector substitute would change package discovery. The caller must also supply readable original numeric table data and an actual duplicate-diagnostic sink. `NativeVfsRuntimeBindings` covers other provider/stream slots but exposes no general enumeration slot; this packet does not edit that shared binding.

Original ABI and evidence: `00BDBE20` is ECX visitor, four stack words, EAX visitor, RET10h; `00BDB6E0` is ECX visitor, RET0; `00BDD0A0` is ECX manager, stack directory/visitor, RET8; `00BE1130` is ECX visitor, stack payload/suffix, RET8; `00BE0FC0` is ECX actual result list with a by-value eight-byte string, RET8. Program `/battlestationspacific.exe` was verified before live reads. All six complete disk/live envelopes match saved listing and contiguous decoding: BDD990 113 bytes/32 instructions, BDBE20 141/46, BDD0A0 672/226, BDB6E0 88/27, BE1130 205/71, BE0FC0 224/79; each instruction belongs to its saved function. The report contains 54 verified direct CALL rows (42 within these bodies, 12 external). A saved `00CC63C3` candidate was excluded because the live listing is not a CALL to `00BDB6E0`. Numeric visitor/provider calls are indirect and are documented as captured target evidence, not fabricated direct rows.

`src/native_vfs_enumeration.cpp` passed explicit MSVC Win32 translation-unit compilation in this worktree. `cmake/startup.cmake` was not edited because its shared registration may be leased; the primary must append this TU and run the full build after integrating the provider routes. The source interface is partial at unsupported provider profiles and original FH3/SEH, returning invalid-parameter continuations, malformed storage, and game/archive behavior. Vector's `0073CB10` output-list owner/pop and startup scan remain separate.
