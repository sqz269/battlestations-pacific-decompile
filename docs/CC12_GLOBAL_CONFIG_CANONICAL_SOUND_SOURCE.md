# Canonical GlobalConfig lifetime access and Sound string storage

The eight-file Source change makes the semantic GlobalConfig getter accept the existing borrowed `SoundLifetimeAccess` and carries the application's VFS string service through Sound startup and configuration. The normal MSVC Win32 build compiled the five changed translation units, linked the application, and passed all three existing CTests. This extends previously reconstructed Source; it adds no Original-function count or game-validation credit.

`get_global_config_00432650` now uses `CapturedSoundLifetimeSection`. It captures the first manager's section, enters and increments it once, performs a separate second manager lookup before evaluating the volatile registration argument, then decrements and leaves the captured section before the final publication reload. The wrapper can borrow the existing semantic domain or the actual `01090AA0` publication cell. It creates no private lifetime owner. Native evidence and the distinction between this semantic getter and the unfinished application's raw GlobalConfig producer remain documented in [the binding readiness review](CC12_GAME_GLOBAL_CONFIG_RAW_BINDING_READINESS.md).

The application's `SoundServices` supplies `app.vfs_->borrow_raw_services().strings`. That same reference reaches `GameSoundRuntime::startup`, `construct_sound_system_00a88770`, the resource-owner factory, configuration initialization, the Lua fragment, class factories and both temporary native names. Each temporary name retains the storage reference used for allocation and releases through it. Existing defaults preserve ordinary calls that omit the explicit storage argument; the application path supplies it explicitly.

## C++ interface limits

`GlobalConfigContext::lifetime` changes from a reference to a two-pointer borrowed value. Its Win32 layout grows from 16 to 20 bytes while the getter's decorated function name is unchanged; later fields move from offsets 4/8/C to 8/C/10. All clients that construct or access this context require recompilation. Three public Sound functions gain a trailing `NativeStringStorage&`; defaults preserve source-call syntax but change their function types, decorated names and argument counts. There is no old-symbol compatibility thunk. These Source interfaces are not the original game's register or stack ABI. The independent [C++ ABI review](CC12_CANONICAL_SOUND_CPP_ABI_REVIEW.md) records the caller and COFF evidence and verifies all 12 consumers of the changed headers were rebuilt. The application map binds the new Sound providers; the GlobalConfig public helper roots have no application-map entries, limiting their evidence to emitted COFF and static-library membership.
