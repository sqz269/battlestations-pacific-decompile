# OCT18B library binding audit A: Lua and zlib

Audit date: 2026-10-18/19. Audit only: no game run, source adapter change, vendor-body reconstruction, or new test. The current rebuild creates fresh stock-library objects and recompiles callbacks. Original executable calling conventions are evidence about the original, not a requirement to run original code in the rebuild.

The stock Lua binding has **known differences beyond `LUA_COMPAT_LSTR=2`**: the original allocator is different, the original base table omits `dofile`, and the original math table omits `random`/`randomseed`. The inspected zlib entry paths have stock 1.2.1 behavior and a compatible public Win32 stream layout. Neither finding proves the universal absence of other private edits.

## Layout and lifetime details

The current raw zlib consumers read/write the public `z_stream`, not `inflate_state`/`deflate_state`. On MSVC Win32, original field use matches stock `zlib.h`: next_in +00, avail_in +04, total_in +08, next_out +0C, avail_out +10, total_out +14, msg +18, state +1C, zalloc +20, zfree +24, opaque +28, data_type +2C, adler +30, reserved +34; total 38h. The constructor explicitly allocates 38h and zeros allocator slots. `inflateInit2_` also allocates an internal 1BA8h-byte state; stock `inflate.h` derives that size from its 26 DWORD-sized prefix fields, lens[320], work[288], and 1440 four-byte codes. This is corroboration of the selected stock layout, not permission to reuse an arbitrary old internal state. The source already asserts 32-bit pointers and stream size 38h.

The game refill reads total_out deltas, writes next_in/avail_in and next_out/avail_out, and chooses flush 4 only when the remaining compressed source is zero and decoded remaining fits the output space; otherwise flush 2. Reset retains the wrapper's input/output buffer cursors while restoring source position and counters. The raw source adapter preserves this; the separate `src/inflate_stream.cpp` projection adds failure/no-progress handling and documents its differences. Original destruction releases its source before ending/freeing the decoder. These are wrapper contracts, not evidence of a patched inflate core.

Lua requires a separate distinction: `NativeLuaObjectStorage` is 14h and `NativeLuaStateStorage` is 4C8h with `state_04` pointing to a stock Lua state. Offsets such as owner+4C4h and its 18h tracked slots describe that **game owner**, not `lua_State`. The sampled original interpreter uses top +8, base +0C, global-state pointer +10, CallInfo +14, stack +20, and 16-byte TValue with type tag +8; the stock Win32 double build supplies those shapes. The current protected adapters explicitly depend on additional private state fields through the same compiled headers. No whole-image alias/provenance proof excluding every other original raw interpreter access is claimed. Original callback/API register ABI remains a historical binary caveat only; freshly compiled source callers need no replacement body for it.

## Priority and verification limits

1. **Known Lua behavior differences:** source-table omissions and custom allocator must remain visible in fidelity claims. The long-string patch alone does not reproduce the original Lua environment. Added stock RNG functions can change CRT RNG state if called; neither their use nor their removal by later scripts was runtime-tested here.
2. **Current private Lua coupling:** preserve the pinned private headers and same-runtime protected adapter. This dependency is already implemented, not a reason to reconstruct stock Lua.
3. **Numeric and environment semantics:** preserve explicit float narrowing, parsing/formatting policy, file/module environment, and deliberate IO/OS guards. Coordinate CRT details with the companion reports.
4. **Zlib wrappers:** the existing fresh-state stock binding is coherent. Preserve status/length handling, raw-vs-zlib mode, reset quirks and buffer/source ownership; do not elevate successful valid-data fixtures into allocation-failure or malformed-stream proof.

Validation for this audit is static source/PE/live-analysis inspection and `python tools/verify_report_calls.py docs/OCT18B_LIBRARY_BINDING_A_LUAZ.md`: **11 call claims checked, 0 failed**; 4 prose claims unchecked and 3 expected warnings for whole-library ranges spanning functions. The unchecked items concern indirect callback transfer, source loading, an absence screen and checksum closure; their evidence is described above rather than claimed as a direct-call verifier pass. No C++ changed, so no new build was required; the primary runs the shared build. Previously recorded fixture/native proofs remain attributed to their original reports, including `docs/NATIVE_RAW_INFLATE_STREAM.md`, `docs/ARCHIVE_COMPRESSION_BUFFER.md`, and the Lua adapter reports. This audit adds no runtime, ABI-equivalence or gameplay claim.
