# Native resource-registry construction

This packet reconstructs complete B19C30[55], B1AA70[104] and B1B6E0[18], **177 original bytes**, using actual raw registry storage and the existing allocation/reset providers. The sentinel and derived constructor retain their full instruction streams with direct call bindings. The base constructor explicitly replaces its original FH3 wrapper with a source C++ catch boundary around the original normal-path operations. It does not claim native SEH, a drop-in binary ABI or game validation.

The source is [native_resource_registry_construction.cpp](../src/native_resource_registry_construction.cpp), with [public contracts](../include/bsp/native_resource_registry_construction.hpp) and [audit](../reports/native_resource_registry_construction_audit.json). The prior construction discovery remains evidence; this packet does not implement its separate getter or base scalar leaves.

## Actual storage and providers

The owner is the actual 10h-byte registry prefix: original profile DWORD+0, preserved DWORD+4, current sentinel pointer+8 and count+0Ch. The raw 1Ch-byte sentinel has left+0, parent+4, right+8, key/factory payload+0Ch..17h, color byte+18h, nil byte+19h and padding+1Ah..1Bh. Construction leaves owner+4 and all sentinel payload/padding unwritten. No semantic registry cast, pool creation or lifetime domain is introduced.

The sole allocation bridge receives the original pushed 1Ch and passes `{object, native_bytes=1Ch, host_bytes=1Ch}` to completed `singleton_lifetime_allocate`. Its actual malloc/new-handler retry and bad-allocation exception behavior remain that provider's contract. It is a fixed direct provider binding, not an allocation callback or an always-success policy. This source does not implement the original operator-new exception object ABI.

The added constructor EDX argument borrows a stable reference to the actual mutable F8D41C publication cell. The reference identity and captured owner binding must remain stable for the whole call, including source exception cleanup. The pointer value stored in the publication may be current and mutable. Successful construction does not write publication. Cleanup uses completed `reset_native_resource_registry_00b19760`: first clear that actual cell, then write CE3818 to captured owner+0. There is no owner or sentinel free in this cleanup.

## Complete instruction and cleanup schedule

B19C30 consumes no input and returns EAX with RET. It allocates1Ch, tests EAX and conditionally writes link+0=0. It separately forms EAX+4, tests that 32-bit result and conditionally writes it, then does the same at EAX+8. Finally it writes color1 and nil0. The naked body preserves the native wraparound and each test; a hypothetical returned null skips only the first write, then reaches address4. That is not an accepted null sentinel. No such allocator failure or hardware-fault case is runtime-proved here.

B1AA70 originally installs a native FH3 frame and arms state0 at B1AA93 before storing D5E594 at B1AA9B and calling B19C30 at B1AAA1. The new source constructor enters its catch-protected call before the private raw body performs either operation. That raw body captures owner in EDI, forms owner+4 in ESI with LEA, preserves the original ECX=ESI before allocation, stores the original D5E594 identity and calls the complete sentinel provider. It writes returned EAX to owner+8, sets that returned node's nil byte, then reloads current owner+8 before **each** parent+4=self, left+0=self and right+8=self store. It sets EAX=captured owner before clearing count+0Ch. The helper saves/restores ESI/EDI and returns; original 32-bit owner/node arithmetic and incidental alias ordering stay in assembly.

The 104-byte original base body contains 20 retained normal-path instructions (56 bytes after contiguous extraction) and 11 native FH3 bookkeeping instructions. The removed bookkeeping establishes/removes FS:[0], stores the native EH owner spill, arms the native state and restores the saved FS link. It is accounted for separately, not declared byte-identical to the compiler-generated source wrapper.

Original handler CBC6B8 loads FuncInfo DF4994 and jumps to BF6B43. The map at DF498C has one action: state0 to -1 through CBC6B0, which reloads `[EBP-10h]` and tail-calls complete B19760. The source catch directly calls that completed reset with the stable captured bindings and rethrows. In the actual compiled source frame, EDX is saved at `[EBP-14h]` and ECX at `[EBP-18h]` before state0 is armed and the helper is called. The catch at section+4F pushes those two saved locations, calls the actual reset and rethrows through `__CxxThrowException(0,0)`. It does not read the helper's potentially changed ESI/EDI. The full compiler handler and .xdata$x catch-all/try/unwind records bind that exact catch location. The source boundary excludes aliases into the private native/source EH spills, arbitrary hardware-fault cleanup, original FH3 stack layout and original throw/volatile-register identity. No sentinel cleanup is invented for a failure after allocation.

B1B6E0 captures owner in ESI, calls the complete base constructor using the added EDX reference, then writes D5E59C to captured owner only after normal return. It returns that owner in EAX and restores ESI with plain RET. It has no additional exception handler. D5E594 and D5E59C are the original two-DWORD profile identities, not host virtual tables; their cells and physical stores are pinned. This packet does not call either profile.
