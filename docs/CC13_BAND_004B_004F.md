## Part A outcomes

### A1. Settings +98h is a list of packages to disable

Verified in the listing:

- `0043E940` (download-manager virtual +14h, `BSP_DownloadManager_DisableOnly`) sets every
  record's enabled byte `+10h` to `blocked(+12h) == 0`, then calls virtual `+8`
  (`set_enabled_by_name`) with `false` for each listed name. The list therefore names packages to
  switch **off**.
- `0043EA80` keeps a list entry when its characters run out first while they still match some
  record name. That is a case-sensitive **prefix** test, not an exact-name test. A null list entry
  reads as the empty string `00E17BF0`, and an unmatched entry is replaced by the last one and popped.

`src/profile_commit.cpp` was unleased, so the correction was made in the code (commit `e382364da`):

- `GameSettingsBlock::downloaded_content` is now `disabled_downloaded_content`. The archive section
  is still `DownloadedContent`, which is the image's own key. The field is renamed in
  `include/bsp/game_settings.hpp`, `src/game_settings.cpp`, `src/settings_archive_reader.cpp`,
  `src/settings_initial_state.cpp` and `src/game_native_settings_application.cpp`.
- The host methods are renamed to `keep_known_package_prefixes_0043ea80` and
  `disable_listed_packages_virtual_14`, with comments that state the prefix and disable semantics.
  This covers `include/bsp/profile_commit.hpp`, `src/profile_commit.cpp` and
  `include/bsp/profile_dlc_runtime.hpp` / `.cpp`. The references in the comments of
  `include/bsp/band_0040_cc13.hpp` were updated to match.
- `docs/PROFILE_COMMIT.md` gained a paragraph on the change.
- There was no matching logic to change. `profile_commit.cpp` forwards the vector to host calls,
  and the prefix matcher itself is modelled in `band_0040_cc13.cpp`
  (`filter_known_names_0043ea80`). Behaviour is unchanged and the build passes.

### A2. 00A47EE0 is the XLiveSystem constructor

`00992A50` (from `BSP_Game_OnInit`) pushes `2218h`, calls `00A47EE0`, and stores the result at
`[00F8A300]` and `[00F8A2FC]`. The body calls the base constructor `00994080`, installs vtable
`00D24878` and builds the voice, session and matchmaking parts. The tag row in
`config/tags/00a40000.jsonl` was a `rename` row (`CG_array_ctor_helper_00a47ee0`, evidence `e0031`).
It is now an `action: "reviewed"` row named `BSP_XLiveSystem_Construct`, with the new evidence key
`cc13_sweep4B_xlive_system_ctor`; `ghidra_tag.py` neither renames nor bookmarks a reviewed row. The ledger
name `BSP_XLiveSystem_Construct` is applied in Ghidra.
