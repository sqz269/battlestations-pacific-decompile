## Reconstructed (build-tested only)

`include/bsp/band_0041_cc13.hpp`, `src/band_0041_cc13.cpp`, registered in `cmake/startup.cmake`
(bsp_core): `avoid_zone_name_applies_to_layer_0041d380`. The native function
(`__stdcall(entity, float* layer, int id)`, `RET 0Ch`) answers whether an avoid zone applies to a
layer: no entity or a mismatched id gives false; a name beginning "AvoidZone" applies; a name
beginning "AvoidZoneG" applies only for `sscanf("AvoidZoneG %s %d #%03d")` with a word starting "all"
and a group equal to the truncated layer (CVTTSS2SI at 0041D3B9). Two native behaviours are not
modelled and are stated in the header: the 8-byte word buffer can overflow, and a missing group
number leaves the entity pointer in the compared slot. No caller of 0041D380 is in the index; the
function is a contract for whoever binds avoid-zone layers.

  The sub_attack draws (009E4F90, 009EABE0, 009E9E50) are on stream 1, as

  00D03E80) as unnamed; docs/CC13_BAND_004B_004F.md calls the 004F1870/004F1890 pair UnitOwnerEntity,
  and the names follow it. If that lane settles the class name differently, rename both.

  base and 1Eh as the device level above it (both answer for every gun class). Adding them would let
  `unit_class_row` answer for gun instances.

  lane; the native has no indexed caller, so check the call sites before wiring it.
