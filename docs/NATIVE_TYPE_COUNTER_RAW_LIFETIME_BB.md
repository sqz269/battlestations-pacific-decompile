# Type-ID counter on the shared raw lifetime manager (BB)

`TypeIdCounterLifetime` now retains a borrowed `SoundLifetimeAccess`. Existing semantic callers can still pass their `SingletonLifetimeDomain`; production composition can pass the application's actual `01090AA0` publication. Both routes use the same source getter and the original `0109DB7C` counter cell. No second manager, projected-to-raw cast, descriptor reset or guard mutation is introduced.

`006FAC20` returns the first `0109DB7C` load on the fast path. On a miss, `CapturedSoundLifetimeSection` resolves the first manager, captures its section+10, enters and increments recursion, then rechecks the counter cell. If still empty, it allocates an actual eight-byte owner, writes `CFB6C4` then next-ID zero, and publishes it. It resolves a **second** manager before reloading and registering the current counter publication (including null if allocation returned null). The captured first section is released before the final cell reload. A replacement manager cannot change which section is left. The retained guard preserves source C++ exception cleanup; original FH3/SEH identity is not claimed.

`006FAD40` consumes the popped eight-byte owner and flags. It clears the same `0109DB7C` cell unconditionally, writes base identity `CE3818`, frees the popped owner only when flags bit0 is set, then returns its original address. It does not unregister, reset the monotonic ID policy, or alter any process-wide descriptor guard. The first DWORD of native table `00CFB6C4` is `006FAD40`. The raw singleton deletion binding `type_id_counter_lifetime` dispatches the popped `CFB6C4` owner through this existing method; a missing binding remains a source contract failure. This binding must outlive raw manager drain.

Original ABI: `006FAC20` takes no arguments, returns EAX and RET0; `006FAD40` takes ECX owner and one stack flags DWORD, returns EAX original and RET4. These C++ methods are source interfaces, not binary ABI replacements. Disk and live Ghidra bytes match for `[006FAC20,006FACD5)` (181 bytes, 48/48 saved instructions owned) and `[006FAD40,006FAD69)` (41 bytes, 11/12 saved instructions owned). `006FAD60` (`ADD ESP,4`) is decoded and contiguous but has **no containing saved function**; it is an explicit attribution exclusion awaiting primary listing repair. The report preserves 25 verified direct callers of the getter plus five direct calls within these two bodies. The table pointer is data evidence rather than a CALL row.

This packet only changes counter lifetime and its raw-manager deletion route. `LightTypeBootstrap` still uses the same counter instance and process descriptor guards. Executable VFS composition, physical file opening and game behavior remain outside this source build.
