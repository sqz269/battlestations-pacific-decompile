# Band 009F0000-00A3FFFF: gameplay naming pass (cc13-gp9f)

Packet cc13-gp9f named and tagged the raw `FUN_` functions (no tag, no ledger name) that
`tools/raw_ownership_cc13.py list cc9` assigns to cc9 in 009F0000-00A3FFFF, and reconstructed a few
anchored leaves in new files. It is a metadata pass: no cc9 host file was edited, nothing was wired
into a host, and no game was run. The earlier sweeps of these bands are docs/CC13_BAND_0090_00BF.md
(0099-009F: plane/bot tasks, STL tags only) and docs/CC13_BAND_00A1_00A4.md (00A10000-00A38D80 left
for cc9); this pass reuses their segment maps.

Every name is a hypothesis, not a recovered symbol. Evidence for each address is in its ledger record
(`python tools/bsp.py lookup <addr>` or the shards `config/names/009f0000.jsonl` .. `00a30000.jsonl`).

## Method

1. `python tools/bsp.py ghidra export` for all 396 addresses (one batch), then local scripts in
   `local/` (ignored): `gp9f_dump.py` (compact pseudocode), `gp9f_refs.py` (one pass over the disk
   image for rel32 CALL/JMP targets and absolute dwords, so unreferenced functions and vtable slots
   are known), `gp9f_vt.py` / `gp9f_dw.py` (vtable dwords), `gp9f_strs.py` (string literals and named
   callees), `gp9f_docs.py` (doc mentions).
2. Assembly was read (`bsp.py disasm-raw`) for every reconstructed function with x87 math or a
   register ABI, and for the planner GetType/IsType constants.
3. Decisions were written as TSV, checked for collisions (`gp9f_apply_ledger.py --dry`), applied with
   `ledger.upsert`, then to Ghidra with `tools/ghidra_annotate.py --apply --addresses ...` (227 names
   and evidence comments) and `tools/template_shapes/st1_apply.py` (169 tag renames), both under the
   write lock.
4. After naming, every address was cross-checked against `src/` and `include/` comments
   (`gp9f_srcctx.py`); five names were corrected (next section).

## Findings

- **AI command vtable slots.** The ten slots of `docs/AI_COMMAND_OBJECT.md` now have bodies for every
  class: `+8h` IsType (each class accepts its own id and its family's), `+20h` CloneForGroup, `+1Ch`
  a slot nothing reads. CloneForGroup rebuilds the same class for the new owner, except that
  CAUTIOUSMOVE clones as MOVETO (`00A10540` writes vtable `00D22ABC`) and CAUTIOUSATTACK as
  MOVETOATTACK (`00A12D40` writes `00D22BBC`): a cloned command drops the cautious route. The only
  clone caller found is `00A2BD50` (`BSP_AiGroup_CopyCommandFrom`), itself reached only from the
  unreferenced `00A22920`.
- **Stripped debug slots.** Every `+1Ch` body refreshes leader poses and, for DEFENDPOSITION and
  RETREAT, computes the wedge threat direction or the retreat direction into a local that is
  discarded; the cautious-approach sub-object's slot 1 (`00A12580`) walks the route points without a
  store, and the planner slot `+28h` (`00A1FC30` Capture, `00A25CB0` Defend, no-op `00A1EEE0` in the
  base) scores capture points and frees the text. These read as debug drawing compiled out; the names
  carry `DebugDrawStripped` and the evidence says provisional.
- **Planner IsType quirk.** The Capture planner's GetType answers 3 (`00A1F480 MOV EAX,3`) but its
  IsType `00A1F490` tests `id == 1`, the Attack planner's id. Whether any caller asks a planner's
  IsType was not established.
- **Developer AI reports.** `00A09810` ("aiVStable.txt"), `00A0A280` ("aiVStable_%s_to_%s.txt"),
  `00A0B420` ("aiVStable_%s_from_%s.txt"), `00A0C1F0`, `00A0DC10` (parses "availableAttackerClasses",
  "targetClasses", "resourceLimit", "overWeighFactor") and `00A0FA70` ("aiGroupsTargetValue.txt") have
  no rel32 or absolute reference in the image. `00A31000`, the group overlay with its helpers
  `00A2D580`, `00A2CDD0`, `00A2F6F0`, is the unreached overlay `docs/SHIP_AI_OPEN_ITEMS.md` already
  describes. `00A0D1D0` (`BSP_AiGroup_MatchFinalWeight`) is live (called by `00A23980`) and carries
  debug prints gated by `00F8AB01` with a Hungarian comment string ("az uj csapat es a regi csapat
  resourcekoltsege miatti mahinalas", the adjustment for the resource cost of the new and old team).
- **Unreferenced code.** 97 of the 396 functions have no rel32 or absolute reference at all (STL copies,
  debug writers, `00A13280` auto-close-attack, `00A185E0` order-selling, `00A2BE70` order-retreat,
  `00A22920` split-groups-by-class, `00A2C0A0`/`00A2C0D0`/`00A2C100` Shift/Ctrl/Alt tests, ...). Their
  evidence says "Unreferenced".
- **RNG.** `00A0F680` and `00A08020` draw record jitter from stream 1 (`BSP_Random_UniformFloatRange((void*)1, ...)`),
  `009FA620` and `009FB190` draw aim wander and phase from stream 1, `00A2CCF0` draws through
  `BSP_RandomThreads_DrawUnsignedFraction`. Recorded in the evidence only; nothing here is wired.
