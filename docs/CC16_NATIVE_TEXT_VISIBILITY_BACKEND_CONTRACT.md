Concrete permitted leaves exist, but the live hierarchy/primary-node borrow and derived dispatch are not supplied. No backend class, Source patch, new owner/registry/callback type, default handler or readiness boolean is proposed.

The other methods must honor their supplied captured target, same receiver and raw byte. Core performs the ancestor AL bitwise-AND and current+70 reload after a getter; AL2 clears accumulator1. No bool normalization belongs in the backend. Core invokes current+3C at its real notification epoch. Neither retains the native payload or companion or proves GUI kind, generation or whole-call custody. data_at checks ranges/mapped bands and may throw. These APIs can be used only while preparing a genuine retained scope covering the actual edges. Do not silently call them, bind references, hash/allocate or add host admission in a pure/stable table resolver or live FP path. The eventual method may consume already validated retained actual profile views; this is a contract, not an implemented lookup or a new whitelist. ## Verified Layer getter adapter

The actual Layer profile D5BE38 has +38=AA38E0 and +3C=A9E100; +34=AC4450 still belongs on the existing outer OTHER transport. AA38E0 is7B/two instructions:

    MOV AL,byte ptr [ECX+F5]
    RET

The public declaration in oct18_tail_c.hpp and naked definition in engine_seg11_35_66_cc13.cpp are BOTH uint8_t __fastcall gui_layer_visible_00aa38e0(const void*). For MSVC Win32 the required named Source invocation is:

    return bsp::oct18_tail_c::gui_layer_visible_00aa38e0(actual_widget);

The sole argument is ECX and result is raw AL; no EDX/dummy/stack argument or RET cleanup is required. Passing it through a cdecl/stack-only adapter is incompatible. The virtual backend's own this is not the widget argument. Preserve every raw byte instead of converting to bool. This is declaration/definition/listing agreement conditional on genuine receiver storage, not a new emitted-code probe, whole Original ABI/fault/NoThrow/runtime proof. The source module is already registered in core; no CMake edit is needed.
