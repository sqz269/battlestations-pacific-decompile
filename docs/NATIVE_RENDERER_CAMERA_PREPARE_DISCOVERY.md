# Native renderer camera preparation: readiness discovery

Full **B285A0 is not yet a ready raw camera/renderer packet**. Its 544-byte body has a concrete, nonvirtual camera-getter chain, but the current implementation still reaches a finite-only private frustum square-root path and the existing node owner uses companion pointers in native hierarchy words. Independent ambient-color and plane/frustum leaves can proceed now; the new plane-set and clip-plane providers remove their respective dependencies.

This read-only worktree starts at `72f74c08` (full hash in the report). [Fresh evidence](../reports/native_renderer_camera_prepare_discovery.json) pins the original full parent, getter/math/constructor/writer spans and current source contracts. Each live query used `bsp.py ghidra`, which verifies configured `C:/Users/sqz269/bsp.gpr` and `/battlestationspacific.exe`. The installed executable SHA-256 is `b682a82c52f81f957b2c70222077305a933f72481686c88843077f714b956dd6`. Provider readiness below records current source and primary authorization; no build or fixture was rerun in this discovery. Ghidra, source, shared metadata and the sealed plane-set artifacts remain unchanged.

Original ABI is ECX renderer, stack camera, RET 4, with no outer guard or own EH frame. Relative to the stack after `SUB ESP,114h` and four saved-register pushes, the live argument is at +128h, loop index at +10h, transposed product at +14h, output plane at +54h, inverse-view temporary at +64h, multiplication output at +A4h and inverse-projection temporary at +E4h.

The full parent order is material. B285B3 sets render state 98h to zero, then loads the camera argument. It calls inverse-VP B70510 even though its returned pointer is unused, then frustum B70710. B250B0 copies all sixteen records to renderer +17C0; a separate raw DWORD load/store copies source count +140 to renderer +1900. The support byte +1B51 is tested before zero stores to active/pending +19EC/+19F0. If supported, the loop reads the current renderer plane count and tests flags twice: skip when bit 4 is set, otherwise admit when bit 2 is set.

Each admitted plane fetches current view, inverts it, fetches current projection, inverts it, and calls 413920 with **inverse-projection as left and inverse-view as right**. Destination/right arguments are already on the native stack while the projection getter and general inverse execute. Sixteen `REP MOVSD` words copy the result; six `MOVSS` swaps transpose it without floating arithmetic. B656F0 returns the current renderer plane record, B65BA0 transforms it, and B23E50 receives the current pending slot and stack plane. Only after normal return is the **current** +19F0 incremented; driver HRESULT failure is not a stop condition. The loop reloads current count. At completion, the current pending count forms `DWORD((1 << (count & 31))-1)` for state 98h; after that setter returns, pending is reloaded into active +19EC. There is no sixteen-plane cap in this body. Skipping hardware planes does not skip the earlier dirty camera getters.

Finally, the current camera's raw +184 owner is read. Nonnull calls B84C60, yielding owner +8, and 4FB850 converts that float4 to a stack color before setting state 22h. The native converter retains the double-255 scale on the x87 stack across RGB conversions, consumes it on alpha, and writes bytes +2,+1,+0,+3 in order. Each channel calls BF7420 and clamps the signed low EAX to 0..255. A copied boolean mode or an aggregate integer result written only at the end would lose current selector/partial-store/overlap behavior.

The camera storage proof is stronger than the old semantic classes alone: B71A80 installs D62CF0 and the current `NativeCameraTailStorage` has checked offsets for all matrices, flags, planes and actual fog owner. `NativeCameraOwner` establishes the tail's typed lifetime in the same 45Ch pool slot and binds its projection/frame views to those exact fields. `SystemFogOwner` proves `fields_08` at +8 and a raw-owner overload for the camera +184 slot. These support actual tail/float-array borrowing; they do **not** make `CameraFrameState*` an original camera pointer.

There is a separate hierarchy incompatibility. [native_node_construction.hpp](../include/bsp/native_node_construction.hpp) explicitly stores `CameraTransform*` companions in `parent_30`, `first_child_34`, and `next_sibling_3c`. Original B6DB70 loads raw parent +30, checks **that object's +5C**, recursively refreshes it, and multiplies local +B0 by **that object's +F0**. A raw B6DB70 cannot dereference an existing companion as a native node. Null-parent or already-valid-cache fixtures cannot close this boundary. A future raw getter packet must require genuine raw hierarchy words, or separately establish an exact mapping/integration contract that preserves the original observations; it must not cast the companion-backed storage to a raw node hierarchy.

Current dependency classification:

- Ready actual renderer providers: `native_renderer_cached_states` B24460 and `native_renderer_clip_planes` B23E50. Both borrow `NativeRendererSynchronizationGlobals`. Plane-set4 `bc7d3e21` supplies raw B250B0/B65080/B656F0/B65700; its sealed files are pinned separately while primary integrates them.
- Reusable arithmetic schedules: `camera_inverse.cpp` and `camera_multiply.cpp` wrap private naked kernels using only `.data()` addresses. They accept genuine `CameraMatrix` objects; they are not exported original-entry providers and their old tests are not a fresh whole-library proof. `camera_projection.cpp`'s copy is a typed loop of ordered x87 pairs; its builder is a semantic scalar interface. `camera_frame_state.cpp`'s general inverse is a private raw kernel, while plane transformation is a typed temporary wrapper. Promotion can reuse verified instruction evidence while giving each required full raw body an explicit interface.
- The current **frustum** implementation still calls private `length_kernel`, which replaces BF7030 with `FSQRT`. It cannot establish full CRT behavior. This does not imply the CRT remains unreconstructed: current `system_camera_axes` exports `camera_vector_length_00419440` and `native_crt_sqrt_st0_00bf7030` with actual `CameraAxesCrtAccess`; `legacy_crt_math` supplies complete C27489. Reuse that concrete chain, including actual +0109DD78 dispatch, +00E16BD0 matherr policy and errno binding. Do not invent a success-only square root or arbitrary exception callback.
- Current `native_render_batch_keys` exports the ST0-input BF7420 selector and complete BF7456 fallback. BF7420 takes the actual volatile 0109EEA4 address and rereads it per invocation. This is ready for a raw ambient converter; the older `convert_camera_ambient(..., bool)` is not the current-global contract.
