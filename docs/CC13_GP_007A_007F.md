# CC13 gameplay band 007A0000-007FFFFF (cc13-gp7a)

Worker cc13-gp7a (cc13 lineage), 2026-10-12, branch `agent/cc13-gp7a`. This is a metadata pass over cc9's
gameplay band, with a small set of leaf reconstructions in new files. cc9 approved cc13 metadata and new-file
passes over its raw bands. Nothing here was run in the game, and nothing is wired into a host.

Status words follow AGENTS.md:

- **Named** means a ledger name (`config/names/007a..007f*.jsonl`) that `tools/ghidra_annotate.py --apply`
  applied in Ghidra, with its evidence as the plate comment. Prior Ghidra values are in this tree's
  `local/ghidra-annotations-20261012T2247*.json` and `...T2307*.json`.
- **Reconstructed, build-tested** applies only to `src/band_007a_cc13.cpp`.

Names are hypotheses from cc9's docs, strings, Lua and archive field names, vtable slots, message ids
(the MT_ table at `00E0AB68`) and callers. They are not recovered symbols.

window `007D0000`-`007D3FFF` and the two addresses cc9-lua52 holds, `007BBA10` and `007C0910`. No functions

## Method

1. I built the raw list from the current index (`local/ag7_list.py`) and exported the 347 decompiles that
   were missing (`ghidra_export.py decompile`).
2. I took a compact dump (strings inlined, callers, and the vtable slots of unreferenced functions), then
   merged it with every doc line that cites each address (`local/ag6_dump.py`, `ag6_docmap.py`,
   `ag6_merge.py`). These are cc13-gp6b's scripts, copied into this tree with an `a` prefix.
3. I read the bodies in address order with the neighbours' names (`bsp.py range`). Vtables were dumped with
   `ag6_vt.py`, message ids were mapped to MT_ names with `ag7_mt.py`, and trivial bodies were read from the
   PE bytes with capstone (`local/g7a_dis.py`).
4. I applied the names through `ag7_apply.py`, which runs `bsp.py ledger add-name` with duplicate-name,
   raw-only and cc9-exclusion checks, and then through `ghidra_annotate.py --apply` under the write lock.

The conventions follow docs/CC13_GP_0071_0078.md:

- Session messages are named `BSP_SessionMessage_<MT>_<Construct|Write|Read|IsType>`.
- Duplicate bodies carry an address suffix.
- "provisional" in the evidence marks a reading that is not settled.

## Notable findings

1. **The `+DECh` actuator block, decoded.** It is a block of channels. Each channel has an enabled byte
   (+0h), a target byte (+1h), a float value (+4h) and a dirty byte (+8h), and the block has a dirty byte at
   +11h. The channels sit at:
   - +28h: channel B, the gear. `007B8860` sets it instantly, with the value 1.0 or 0.0.
   - +44h: channel C. `007B8D10` and `007B8D40` test it at 1.0 and 0.0, `007B8DA0` retracts it, `007B8DC0`
     extends it and `007B8DE0` resets it to zero.
   - +60h: a third channel. `007B8840` sets its target.

   The block is saved and loaded with the archive fields `targst` and `curst` (`007DE880`/`007DE900`,
   `007DEA60`/`007DEB70`) and stepped by `007DE9A0`. **`007B8D40` tests channel C (+44h), not the gear
   channel (+28h).** SHIP_AI_OPEN_ITEMS.md already cites `+DEC+44h`.
2. **The base bot task's slot `+50h` (`007B4140`) is `MOV EAX,1; RET`.** CC13_ROCKET_TASK.md says that the
   base answers 0. The bytes answer 1. The other base defaults of `00D05708` read from the bytes are:
   - `+8h` 0; `+20h` true; `+28h` false; `+44h` false; `+48h` 0; `+5Ch` 0;
   - `+64h` `RET 4`;
   - `+14h` "not defined".
3. **`007B95E0` reads the squadron's `+3BCh`, which `007EE790` rewrites with the number of active wingmen.**
   Those are the members after the leader whose per-slot float `+9C4h[[00F876B8]*8]` is non-negative. The
   predicate is therefore "a leader with active wingmen", not "a leader of a squadron with members". The
   rename `BSP_Plane_IsLeaderWithActiveWingmen` records this. The finding refines the TurnRollLeader row of
   CC13_AUDIT_PLANNER_ROLL.md.
4. **The plane's engine list is at `+C98h`.** The engines are polymorphic: the base vtable is `00D08640` and
   the rotor vtable is `00D0865C`. Their slots are:

   | slot | role | rotor |
   |---|---|---|
   | 0 | init | `007EBF10` |
   | +4h | restart | |
   | +8h | reset | `007E1C60`, which shows the static rotor |
   | +0Ch | stop the engine | `007DDF10` hides the blur |
   | +10h | step the rpm | GameTuning `+17Ch` |
   | +14h | spin | `BSP_Matrix_BuildRotationZ` |
   | +18h | blur blend | Rotor/StillOnlySpeed and Rotor/BlurredOnlySpeed |

   `007DE600` stops every engine. `007B8EF0` (`BSP_Plane_LosePower`) is that call followed by `+C39h = 1`,
   which is PLANE_DEATH_MODES.md's powerlost tail. `007DE5B0` is the "any engine burning" scan that
   GUN_AIM_TERMS.md cites.
5. **`+C50h` is the plane-neighbours object.** BOT_PROBE_007F0280.md already says so. As a result,
   `007B9740` (the dogfight "no" arm) clears the neighbours' target observer `+B0h` (`007E2070`). Their
   update slot `+0Ch` is `007E2010`, as PLANE_GUNFIRE.md describes, and the line-of-sight query is
   `007DF360`.
6. **`007EF8F0` is a map-bounds clamp.** It copies the point, then clamps:
   - x to `[world+711Ch + 1, world+7128h - 1]`;
   - z to `[world+7130h + 1, world+7124h - 1]`.

   Each bound is stored to a float first, and a NaN passes through. The squadron's pass-C stop target
   (CONSTRUCT_WORLD.md) therefore equals the squadron's position whenever the squadron is inside the map.
7. **`007E1D80` compares whole strings.** `BSP_CommandLine_MatchesToken` (`004C2DF0`) calls
   `004BEB60(0, size, text, strlen(text))`. That is a whole-string equality, not the prefix compare that its
   ledger evidence ("compares strlen(text) characters") suggests. The part index is:
   - `aileron_l` 0 and `aileron_r` 1;
   - `elevator`, `elevator_l` and `elevator_r` 2;
   - `rudder` 3;
   - anything else 5.
8. **Plane flight controller `+44h` and `+78h`.** `007D80C0` latches `ctl+44h` (the body forward speed of
   SQUADRON_LAND_TASK.md 5da) into `+7Ch` and stores `(+44h - old) / dt` at `+78h`, the forward
   acceleration. When dt == 0 it clears the rate and copies the zero vector `00F87574` into `+60h` and
   `+54h`.
9. **The scene-path class family.** The path machinery is split across these classes:
   - `00D053A4` is the `vector<float[3]*>` class (Point3PtrArray). Its slots `+8h`/`+0Ch`/`+10h`/`+14h`
     add, insert, erase and clear; `+18h`/`+1Ch` load and save; `+20h` allocates a point.
   - `00CE63E8`/`00D053D8` is the path component built by `007B28C0`. It has world-space wrappers for the
     centroid, the polyline distance and the nearest index.
   - The sources are `00D05318` (simple), `00D0534C` (authored, `pathID`/`entity`) and `00D05440` (owned
     points). The `"pathIntf"` loader `007B3000` picks one through `007B2EC0` (`"simple"`).
   - `00D0546C` sends MT_PATH_SET/ADD/INSERT/DELETE (D9h..DCh) and answers the entity's net id.
   - `NetPath` (`00D054D0`) is the MT_PATH_CREATE entity.
10. **Paratrooper.** The MParatrooper and paratrooper-class methods match CC13_SOLDIER_TRAFFIC.md row by row. Their vtables are
    `00D05060`, the subobject `00D04FD4` and the class `00CFA604`.

5. 'Non-Returning Functions - Discovered' was disabled (`list_analyzers`), and no analysis pass ran.

what its ledger evidence states: the path copy into `+49Ch`, `BSP_MovCam_SetTarget`, then `+384h = 6` and
