# Native FileBlock foundations and unmount integration BM

Six complete ordinary bodies (2021 native bytes) now have actual-storage Win32 C++ implementations registered in `bsp_core`: identifier preparation and byte splitting, gate-list node allocation/count growth/iterator erase, and name-based VFS unmount. The [integration report](../reports/native_fileblock_integration_bm.json) pins worker commits, original ABIs, source hashes, evidence receipts and the combined build at `48b9789f677cd17bb2a51129b3b43ce864622b70`.

Identifier preparation preserves the exact invalid-character scan, numeric-token abbreviation and ordered 64-byte substring fallback. Its result is not generically clamped to 32 bytes. Splitting appends nonempty tokens to the existing actual vector and preserves completed-temporary cleanup. Gate helpers keep the late input-byte read, unsigned count bound with owning native-style length-error payload, returning validation callbacks and post-free current-count read. Unmount scans the actual priority tree and removes the first provider-name/mount-prefix match; it decrements the captured provider before consulting its current virtual table at zero, then erases using the same captured iterator storage. Unknown escaping failures retain a stable acquired frame.
