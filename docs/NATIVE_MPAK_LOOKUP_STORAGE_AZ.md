# Actual MPAK lookup storage (AZ)

`NativeMpakLookupStorage` supplies two existing interfaces, `NativeMpakOpenLibrary` and `NativeMpakDirectorySearchLibrary`. It borrows actual storage and a returning `00BF6713` callback. Its directory search reuses the already reconstructed `find_native_string_vector_005efba0` in `src/native_string_vector_lookup.cpp` (commit `8cbe0c4b`); this packet does not implement or rename that helper. It neither constructs a provider/vector nor changes any archive record.

| Root/helper | Original ABI and covered behavior | Boundary |
| --- | --- | --- |
| `00BB4140` | ECX actual file vector, stack index, EAX 24h record pointer, RET4. Read begin at vector+4, compute signed DWORD byte difference `(end-begin)/24h`, then compare index unsigned. Null/out-of-range calls `00BF6713`. After a returning callback, reload vector+4 and compute `begin+index*24h` without a second check. | The caller supplies a returning invalid-parameter callback. If it returns without repair, native also continues with invalid storage; no safe fallback is added. |
| `00BB4F40` | ECX captured first directory row, EDX captured end, stack temporary key, EAX found row/end, RET4. Advance by 14h and invoke `005EFBA0` on each row+8 member vector. First nonnegative member index wins. | The directory row's own name is never compared. Captured end is not reloaded. |
| `005EFBA0` (reused dependency) | ECX actual member vector `{begin,count}`, stack key name header, signed index/-1, RET4. Each 8h member is `{length,pointer}`. Compare lengths, then accept empty/empty or `_stricmp(member,key)==0`; return first index. | The shared implementation captures count before data and computes a matching index against current data. Other native callers of this generic helper remain outside this MPAK integration. |

The native listings were read from the verified `battlestationspacific.exe` program. `00BB4140` body ends at `00BB417B`; `00BB4F40` at `00BB4F73`; `005EFBA0` at `005EFC15`. The direct CALL evidence in the report includes all known direct xrefs to these three roots. Ghidra was read only. The new class uses C++ virtual interfaces, so it is not a binary ABI replacement or an original exception handler.

The native MPAK runtime can borrow this same class for its open and directory-search references. `NativeMpakContainerLibrary`, provider construction, raw VFS host wiring, numeric table availability, real archive execution and game behavior remain separate work. A Win32 build checks source integration only.

## Focused copied-body comparison

The ignored fixture in `local/mpak_lookup_az_evidence/` contains a capture script, x86 runner, build script, three exact original body binaries, generated header, manifest, run log, Win32 probe executable and evidence archive. Capture checks each live Ghidra byte against disk, decodes every byte into contiguous x86 instructions, compares every decoded instruction start with the saved listing, and asks Ghidra for the containing function of **each** instruction. All 24, 26 and 53 instructions respectively belong to the claimed saved functions, including their final RET instructions; the verified envelopes are `[00BB4140,00BB417C)`, `[00BB4F40,00BB4F74)`, `[005EFBA0,005EFC16)`.

The runner copies those three full bodies into private executable memory, patches only their relative CALL operands to the returning invalid-parameter callback, copied member helper and CRT `_stricmp`, and invokes them through explicit original-register/stack adapters. It compares a valid populated file record, a returning validator that repairs vector+4, a false lure in the directory's own name, row+8 member search and first-match order, empty names, case-insensitive match and a counted-length mismatch. All eight checks passed. No malformed native access, FH3/SEH equivalence, archive I/O or game execution is claimed.

The source packet's `./scripts/build.ps1` Win32 Release and existing CTest 1/1 passed at commit `de42a18a`. After replacing the private helper with the shared implementation, the incremental Win32 build and CTest 1/1 passed again; the focused probe passed all eight checks. The report distinguishes two CALLs inside newly supplied roots, one CALL inside the reused helper, and seven external direct caller rows. It records SHA-256 hashes for source executable, each original body, runner, generated header, result log and archive.
