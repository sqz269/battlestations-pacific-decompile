# Text pool, lineage and mutable-state host integration

Source **`07c72d19b50a1e576f3c6e4e2f6edf2941660063`** wires the [Text process owner](CC12_NATIVE_GUI_TEXT_PROCESS_37.md) (`de08e5308`) and [mutable state owner](CC12_NATIVE_GUI_TEXT_STATE_38.md) (`86b767ab4`) into the normal application. It retains the [native font host](CC12_NATIVE_FONT_HOST_ADOPTION_36.md). The [machine receipt](../reports/cc12_native_gui_text_host_prerequisites_41.json) separates build/source proof from the currently unavailable full startup run.

`game_main.cpp` initializes the actual Text pool before the existing particle-pool subset. This preserves the Original relative table order: `CE3470→CD71F0` precedes `CE34EC→CD7830`. The real `std::atexit` registration owns the `CE0A80` pool destruction callback, with process/allocator-list metadata alive through it. No Text payload is allocated by this integration.

Before font/GUI consumers, `GameStartupHost` initializes Text/Element lineage using **the same** `vfs.native_owners().types()` and `vfs.native_types().light_types()` used by the VFS type domain. The parent guard/name stores and counter-before-ID publication are preserved by the recovered initializer. The new process keeps its lineage cells alive; CRT pool teardown does not dereference the saved VFS identity pointers. This is explicitly a **late Source bootstrap**, not proof of Original absolute CRT timing or numeric type-ID order.

The sprite Text bridge now samples the same verified mutable `E12FD4` backing on each layout/quad operation instead of a separate constant. The scalar owner has one retained instance; its initial words come from verified Original PE data/loader zero-fill. It does not initialize the lazy white quartet early. Native Text buffers, sections and font-material drawing are still inactive.

Entered pool/type failures are sticky and cannot replay. Pool failures check the metadata predicate before wrapped diagnostics and take `_Exit(2)` for both standard and unknown exceptions; other unknown pool exceptions retain WinMain's existing no-throw termination boundary. Entered type failures take `_Exit(1)` before manager/VFS/renderer cleanup. No guessed rollback was added. The [independent source review](CC12_NATIVE_GUI_TEXT_PREREQUISITE_REVIEW_41.md), `0d69fee7b`, found no remaining blocking lifetime, ordering or duplicate-owner issue.
