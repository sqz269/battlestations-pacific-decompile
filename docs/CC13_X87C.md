# cc13-x87c: three skipped functions

Packet cc13-x87c (2026-10-14). The code is in `src/cc13_x87c.cpp` and
`include/bsp/cc13_x87c.hpp`. Every name is a hypothesis, not a recovered symbol. Each
function is reconstructed as a new C++ interface over the native records. The bodies follow
the image call for call through named host hooks. They are not drop-in replacements of the
original ABI, nothing is wired into the game, and the code has been build-tested only.

## 00421CE0, the grid contour tracer

The only caller is 00423640 (not reconstructed). Neither `game_avoid_zone_runtime` nor
`game_hosts_avoid_zones` hosts a contour tracer, so this is a new reconstruction rather than a
ledger-only record.

- Extents: `(source->vslot10() - 1) / step + 1` and the same with vslot14. Both use signed
  IDIV. The source is `[owner+3D0h]`.
- It allocates a 1Ch-byte path and constructs it with 00421C10: owner, a NativeString
  "unnamed", and a vector of 0Ch-byte points at +0Ch (first/last/end at +10h/+14h/+18h). If
  the constructor throws, the unwind funclet 00C5E570 frees the block. The owner word is
  stored without a null test.
- Seed: the first non-zero byte of `grid[x][y]`, scanning y outer and x inner.
- Trace. The starting direction is 1. Each step does the following:
  - It marks the cell `(direction + 8) * 8` in byte arithmetic.
  - It probes up to eight neighbours, starting at `direction + 5 (mod 8)` and advancing before
    each probe. In-bounds cells are read signed, and the probe stops at the first cell above 0.
  - When the probe direction differs from the current one, it appends a world point and the
    probe becomes the direction.
  - It adds the direction to the cell and steps. The step table is shared by the jump tables
    00422274 and 00422294: 0 = -y, 1 = +x-y, 2 = +x, 3 = +x+y, 4 = +y, 5 = -x+y, 6 = -x,
    7 = -x-y.
  - It stops when the probed neighbour was above 1 and the new cell is the seed, or after more
    than 25000 points.
- World point:
  - The point is 0087FC30 at `(float(x*step), float(y*step))`, transformed by the owner's
    cached inverse world at +110h.
  - When +10Ch is clear, the inverse is refreshed inline. If +C8h is clear, the code runs
    00414DB0 on the parent, 00413920 `local(+74h) x parent world(+CCh)` (or the local matrix
    when there is no parent), copies the 16 floats to +CCh, sets +C8h = 1 and +10Ch = 0. It
    then sets +10Ch = 1 and calls 00B63D50(ECX = +110h, EDX = +CCh).
  - The x87 block 00421FDE..0042205D is read from the bytes. 00422009 is `DC C9`,
    FMUL ST(1),ST(0). The listing prints it as `FMUL ST1`. The sums are
    `x' = ((m[4]*0 + m[0]*gx) + m[8]*gz) + m[12]` and
    `z' = ((0*m[6] + gx*m[2]) + gz*m[10]) + m[14]`, and y' = 0 (XORPS).
  - The point is pushed with 004215D0 on `&path+0Ch`.
- Fill:
  - The fill walks the traced bounding box row by row. A marked cell (40h and above) has entry
    `e = ((cell >> 3) - 4) & 7` and exit `o = cell & 7`.
  - "Enter" is `e < 6 && (o == 7 || o < e)`. "Leave" is `!(o < 3 && o != 0)` for `e < 2`, and
    `e >= 4 && o >= 3 && o < e` otherwise.
  - Inside a span, every positive cell is cleared. The span ends after a leave cell.
  - A row that clears nothing ends the fill.
- Result: if the path has no storage or fewer than three points, the code frees the points,
  zeroes first/last/end, and returns the name storage through 00419CC0 and
  00BD1510(size = length + 1, 1). It then frees the path and returns null.
- Uncertain:
  - The float sums are exact at the main thread's 24-bit precision control. At 53 or 64 bits,
    the image keeps the intermediates wider.
  - The FLD/FSTP world copy would quiet a signalling NaN. Here it is a plain copy.

## 006C19D0, the air-ops property list

Callers: 006D37E0 (BSP_AirField_Serialize) and 00758DC0 (BSP_MotherShip_Serialize). Every
entry is an archive `+0Ch` write of the current value. The name "Declare" is kept from the
existing ledger. The image does the following, in order:

1. `readySlots`, when the list count +18h is non-zero. For each node of the std::list at
   +10h (head +14h), write `{1, index} = {1, node+8h}`.
2. `landingSquadrons`, under the lock at +4h, when +9Ch is non-zero. For each 14h record of
   +98h, open `{1, i}`, write `squadronID` `{4, +0h}` and `waitingPos` `{1, +8h}`, then
   close.
3. `landingPlanes`, under the lock at +8h, when the vector +A8h/+ACh is non-empty. For each
   14h record, open `{1, i}`, write `planeID` `{4, +0h}`, `distance` `{2, +4h}`,
   `speedmul` `{2, +8h}`, `leftside` `{3, +Dh}`, `abort` `{3, +Ch}` and `state` `{1, +10h}`,
   then close. A checked operator[] precedes each field.
4. `launchingSquadronID` `{4, +38h}` and `maxInAirPlanes` `{1, +58h}`.
5. `runwayFailure` `{3, +1Ch}` and `hangarFailure` `{3, +1Dh}`, each written only when
   00BD5680 says the value differs from `{3, 0}`.
6. `suppplanetypes` `{1, +20h}`.
7. `slots`, under the lock at +0Ch, when +50h is non-zero. For each 58h record of +4Ch, open
   `{1, i}`, write `classID` `{1, 0095B9C0(+4h)}`, `count` `{1, +8h}`, `equipment`
   `{1, +10h}`, `squadronID` `{4, +28h}`, `targetID` `{4, +4Ch}` and `state` `{1, +2Ch}`, then
   close.
8. `stock`, when +48h is non-zero. For each node of the std::list at +40h, open `{1, i}`,
   write `classID` `{1, 0095B9C0(node+8h)}`, `count` `{1, node+Ch}` and `squadLimit`
   `{1, node+10h}`, then close. The checked-iterator report runs after the open, after each
   of the first two writes and after the close.
9. `traffic`: open the section, call `[+3Ch]` vtable +10h(archive), then close.

Locks:
- Each lock is a CRITICAL_SECTION with a depth word at +18h. The guard object (vtable
  00CE37FC) enters it inline and leaves it inline.
- On unwind, the guard's destructor 00411F00 runs the same leave. The C++ uses one RAII guard
  for both paths.

Simplifications:
- Kind-3 values carry a zero-extended byte. The image writes only the low byte of the value
  word, so the upper three bytes are stale stack.
- The always-true container compare of the checked iterators is not reproduced.

## 00819CC0, the ship override of SetDamagedGfxLevel

It has no call xref. A byte scan of the image finds the address in nine `.rdata` vtables, all
at slot +1B4h, the slot that holds 00877B00 in 00CF8C08:

- 00CF90B0 battleship
- 00CFA778 cargo
- 00CFB738 cruiser
- 00CFC3D0 destroyer
- 00CFFA30 landing ship
- 00D01630 mothership
- 00D09678 ship base
- 00D0BF80
- 00D0C648 torpedo boat

The function is live and is not hosted. `gameplay_seg41_cc13.hpp` declares only the virtual
`set_damaged_gfx_level`.

When the new level differs from +358h, the function calls the base 00877B00. When the level
is positive, it then does the following:

1. For each id in class+7A8h, it visits every part of the unit list +48h (next +44h). A part
   matches when vslot5C(1Eh) returns true and part+38Ch equals the id. For a match, it calls
   vslot70(1). If vslot20() returns a node, it calls 00B6DA70 on `[[node+160h]+0Ch]` with
   (0.0f, 0), then 00710B80 on a fresh vslot20().
2. For each index in class+7B8h that is below +A18h, it takes the effect slot `[+A14h][i]`.
   It stops the effect's children (00867B10), sets effect+9h = 1, releases the slot's
   reference (InterlockedDecrement, slot 0 on zero) and clears the slot.
3. For each index in class+7C8h, it uses a checked index into the 44h-record vector
   +664h/+668h. When the record's node is set, it calls 00B6DFA0 and clears the node.
4. When class+694h is not positive, it picks one handle of class+7F8h with `NextU32(0) % size`
   (no zero test). When that handle is set, it creates a point effect with 008687C0 on the
   parent node +4A4h, with an identity matrix (1.0f from 00D7A24C) and 1, 0, 0. It then sets
   +9h = 1 and releases the effect.
5. Otherwise it loops `i = 0` while `i == 0 || i < class+688h`. Each pass does the following:
   - It picks a random handle the same way (no null test) and creates the effect.
   - When i is below the anchored count, it anchors the effect at class+684h + 0Ch*i
     (00745130). It then sets +9h = 1.
   - When `[00E188A8]+21D0h` is set, it creates a point announcement (0049C940). The position
     is either the anchor transformed by the unit world (004142E0, after the inline world
     refresh) or the unit translation +FCh. The velocity comes from unit vslot34 (00812090).
     The descriptor is `class+690h[k]`.
   - k cycles modulo class+694h, and the effect reference is released.

The 0049C940 argument order comes from the stack: unit vslot34 is RET 4, so the EDI push
before it is 0049C940's third argument.

Simplifications:
- The `(-(p != 0)) & 00E186ECh` and `& 00E17BF8h` tests are written as null tests.
- The effect reference is released through a catch block in place of the EH state 0 funclet.
