Installation performs no registry getter, native registry allocation, registration, factory construction or platform activation.

`bind_resource_registry_domain(strings, validation)` allocates the host metadata before publishing its pointer in the existing singleton deletion table. If metadata allocation throws, the registry publication and deletion pointer remain unchanged; existing VFS failure retention still applies. Repeated binding requires the same referenced string/validation objects and owned deletion pointer. An initial foreign binding or already published registry is rejected. No native publication is reset and no rollback is introduced.

Future procedural factory/table/sampler contexts must borrow that reference together with the existing manager cell. The application does not yet construct those contexts; this change prepares their common binding and does not claim future consumers are wired.
