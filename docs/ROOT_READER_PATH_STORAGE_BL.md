## Ownership and normal initialization

`00BEA150 BSP_StructuredReader_Construct` is the direct initializer of the path headers consumed by root constructor BEA380 and child constructor BEA250. Its original call convention is ECX = writable, caller-owned `70h`-byte reader storage; it returns that pointer in EAX with plain `RET`. The saved Ghidra signature is generic, so this ABI is from the complete `BEA150..BEA1B4` assembly. There is no reader allocation in this function. Its three direct callers `ADDA60`, `B80720`, and `BC4530` pass stack addresses at `ADDB02`, `B80844`, and `BC4569`; each then attaches a stream via `BF0430` at `ADDB17`, `B80856`, or `BC457E`. Only the narrow call windows of the two giant callers were qualified. The 198-byte `BC4530..BC45F5` body also calls `BEA700` at `BC45A2` with the same stack reader, then `BE9F10` at `BC45DB` before stack exit.

At `BEA16F`, BEA150 calls `BF09A0 BSP_StreamReader_Construct`: the complete `BF09A0..BF09AF` body writes zero to four DWORDs at reader offsets `+00,+04,+08,+0C` and returns the base in EAX. BEA150 then pushes destructor `0041DD20`, constructor `00415270`, count `0Ah`, stride `8`, and destination `reader+10h`, calling `BF7CD1` at `BEA18C`. The complete `415270..41527F` body writes zero length and null data to each eight-byte native string header. Thus the ten path headers occupy `reader+10h+8*i` for `i=0..9`. After the vector constructor returns normally, BEA150 writes `reader+60h=0` at `BEA195`, `reader+64h=FFFFFFFFh` at `BEA198`, and zero to `reader+68h/+6Ch` at `BEA19F/BEA1A2`, then returns the reader.

This initializes *header storage*. It does not allocate string character buffers, establish a capacity beyond the ten observed headers, attach a stream, or perform a read. The native BEA380 root path reads the current index from `reader+60h` at `BEA458`, forms `reader+10h+8*index` at `BEA45E`, and publishes `index+1` at `BEA466` before copying the tag into that header. The implemented BEA250 child path has the same storage dependency. `BEA700` allocates a `24h`-byte **root node** via `BF681B`, then calls BEA380; it does not allocate the reader. Candidate B936E0/B932E0/B93310 are typed node-value reading consumers, not creators of these raw path headers.

The paired native destructor `BE9F10..BE9F87` first releases the separate `+68h/+6Ch` name if populated, invokes `BF7C6E eh_vector_destructor_iterator` with ten headers at `reader+10h` and destructor `41DD20`, then calls `BF09B0` on the base. The caller's `70h` stack storage is not freed by it. Stream attachment and destruction are separate from the smallest path-header initialization packet.

## Exceptional boundary requiring Astra review

BEA150 installs SEH handler immediate `CC7138` before BF09A0. `BF7CD1 eh_vector_constructor_iterator` is a CRT iterator with stack arguments `(destination, stride, count, constructor, destructor)` and `RET 14h`. Its normal loop at `BF7CE8..BF7D01` invokes the constructor indirectly through `[EBP+14h]` at `BF7CF5`, advances the destination and constructed count, then sets success `[EBP-20h]=1` at `BF7D03` and calls `BF7D1E` at `BF7D11`. On that normal path BF7D1E skips unwind. BF7D1E is a frame-dependent helper: if caller `[EBP-20h]` is zero, it forwards destructor `[EBP+18h]`, constructed count `[EBP-1Ch]`, stride `[EBP+0Ch]`, and current element pointer `[EBP+08h]` to `BF7C10 __ArrayUnwind` at `BF7D30`.

`BF7C10..BF7C6D` is 94 PE/live-matching bytes, but the saved Ghidra listing has an undisassembled **44-byte gap `BF7C33..BF7C5E`**. Disk-byte disassembly shows the gap reads an EBP-relative exception record, tests `0xE06D7363`, may return early, and calls `C07A75` at `BF7C57` before restoring ESP; that call is not in the saved Ghidra instruction graph. The visible loop at `BF7C20..BF7C31` decrements count and invokes the destructor through `[EBP+14h]` while stepping backward. Its decompiler has a false register/stack input. This is the exact listing and EBP-frame boundary for an Astra follow-up, together with BEA150 handler `CC7138` and CRT EH metadata pointers `E02D50` (iterator) and `E02D10` (unwind). No Ghidra repair was attempted. Normal header initialization is established; full native exception and unwind parity is **not** established and no source implementation is delivered here.
