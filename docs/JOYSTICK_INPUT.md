# DirectInput joystick construction and polling

`JoystickInputDevice` reconstructs the bounded native `00A99940` construction,
object enumeration, queries, polling, reset and destruction path over the same
`InputDeviceTable` / `InputStateDevice` types used by input enumeration and focus.
Names are hypotheses. This is a typed Win32 C++ interface, not a binary-compatible
replacement for the native B48h object or its D5B7F0 vtable.

The evidence comes from read-only `bsp.py ghidra` queries against
`C:/Users/sqz269/bsp.gpr`, `/battlestationspacific.exe`, with raw disk decoding for
missing definitions and false no-return fallthroughs. Exact boundaries, original
ABIs and proposed tag corrections are in `reports/joystick_input.json`.

## Construction and SDK contracts

The enumeration factory can call `create_joystick_input_device_00a99940` with the
actual `IDirectInput8A`, original `DIDEVICEINSTANCEA`, and services that outlive the
device. It returns a standard-new object for canonical table attachment and
deletion. `JoystickFocusDeviceHost` supplies the joystick branch of
`KeyboardMouseFocusDeviceHost`'s required delegate. Class is 2; identity is the
canonical zero-return helper A93EB0; activity scans all 90 binding queries.

The native constructor takes ECX=this and two stack arguments (DI8, instance),
returns this in EAX, and ends with RET8 at A99E8B. It copies the product name,
recognizes the three literal spellings Xbox/XBOX/XBox plus 360, then calls
CreateDevice with the instance GUID and null outer unknown. It performs two
EnumObjects passes with flags 0: A98B90 counts objects with `(dwType & 1Fh) != 0`,
then A992F0 fills metadata, descriptors and mappings. The callback adapters are
actual stdcall SDK callbacks, with the same typed device as their context.

The format is generated by game code; it is not `c_dfDIJoystick`. Its six DWORDs
are `{18h, 10h, 1, object_count*4, object_count, descriptors}`. Each descriptor is
`{null GUID, index*4, original dwType, original dwFlags}`. SDK static assertions
verify the native 24-byte DIDATAFORMAT and 16-byte object layout and relevant
DIDEVICEOBJECTINSTANCEA offsets. The focused fixture compares every descriptor
and the complete dynamic header passed to the SDK interface. There is no fixed
native joystick format table to compare with an SDK constant.

Buttons use the first free of 60 slots, reserving slots 4..7 for the first POV.
Axis bindings begin at 60 and follow offsets 1,0,3,2,4,5,...; the instance-number
guards are unsigned 16-bit values below 60 for buttons and 30 for axes. POVs map
left/right/up/down to binding kinds 5..8, first at 4..7 and subsequently into free
slots beginning at 20. The first two objects with flag 1 provide feedback axes.

SetDataFormat precedes a DIPROP_RANGE query for **every accepted object**, with
DIPH_BYOFFSET and offset `index*4`. Only HRESULT exactly zero supplies a range.
The span is the wrapping signed subtraction maximum-minus-minimum. The current
platform HWND is fetched after those queries, then SetCooperativeLevel uses 5.
With feedback axes, the constructor sets DIPROP_AUTOCENTER to zero, then creates
two effects. The 56-byte SDK DIEFFECT matches the native structure, including its
final start-delay DWORD: flags 12h, infinite duration, gain 10000, no trigger,
the collected axes, zero directions, null envelope and zero constant/ramp
parameters. Native GUIDs D78F5C/D78F6C equal SDK GUID_ConstantForce/GUID_RampForce.
The constructor initializes effect kind 0; the evidenced kind-1 branch is also
implemented. No Start call occurs. Construction finishes with two polls at 0.0f.

CreateDevice, EnumObjects, SetDataFormat, SetCooperativeLevel, SetProperty and
CreateEffect HRESULTs are ignored as in assembly. A failed HRESULT with a valid
output is therefore accepted. Missing required outputs or inconsistent callback
counts are explicit host errors. These guards, standard containers and C++ RAII
are not claims of original allocation-failure or SEH-unwind compatibility.

## Samples, queries and time

A98E30 ignores its stack float. It clears valid, calls Poll, and on Poll failure
calls Acquire once and returns false. Otherwise it copies current to previous
before GetDeviceState. Failure there preserves any partial SDK output and returns
false without Acquire. Success marks valid, applies the native deadzone to every
object for which a range was obtained, and updates optional input detection.

Deadzone calculations retain the native x87 arithmetic and exact constants:
CE3D10 is double 0.20000000298023224; D5B7E8 is double 1.2500000046566129. The
signed span/2 is rounded to float before threshold arithmetic. Compiler conversion
performs truncation at the BF7420 CRT boundary; that matches the inspected native
SSE path's intermediate double. Native non-SSE fallback behavior and extreme
out-of-range conversion are not validated. The asymmetric ordinary case is
intentional: span 1000, raw 800 gives 750, while raw 200 gives 251.

Binding kind 1 treats any nonzero DWORD as pressed. Kind 2 compares against the
signed span midpoint, or against previous state when relative. Kinds 3 and 4 are
the lower/upper portions with quarter-span down thresholds. Axis values use the
native range subtraction and x87 division; POV values use the exact native
4500-degree-hundredth directions. query_1c reads the relative marker for any
nonzero binding independently of validity. The down/value wrappers normally
require valid and not inhibited. On an Xbox product, trigger codes 21/22 and the
code-64 zero result run before these guards.

After object processing, the poll scans 90 float values for absolute value above
0.25. On the first hit it reloads the actual global clock through the supplied
required callback, converts its timestamp with canonical `timestamp_seconds_x87`,
and stores rounded seconds plus 60. Xbox products then call genuine XINPUT1_3
ordinal 2 (`C2F166 -> IAT CE239C`) for user 0 and divide each trigger byte by 255.
The native ignored failed XInput output would be undefined; the typed API reports
failure rather than reading an uninitialized SDK structure. Native initial
sample DWORDs and trigger floats are also uninitialized, so callers explicitly
supply their initial storage values through `JoystickInputServices`.

## Ownership and bounded base composition

Native destruction frees previous/current arrays, destroys object names in
reverse order, frees metadata and format storage, then calls **Unload**, vslot
2Ch, on effect 0 and effect 1. It then frees the product string and destroys its
base. Neither the DirectInput device nor either effect receives AddRef/Release
in the recovered lifetime. The typed projection likewise borrows them. A runtime
owner must track the actual SDK references independently and keep COM plus the
string/clock/window services alive through typed destruction.

A98400 sends force-feedback commands 2, 20h, then 1, ignoring HRESULTs. A99900 is
the scalar deleting wrapper: it destroys first and frees allocation only for
flags bit 0. Flag 0 is supported for explicitly managed object storage.

The shared base constructor A95D70 writes base vtables/reference 1, zeros the two
256-byte input histories, constructs an empty force-request tree at +20C
(sentinel +210, count +214), and sets channel floats +218/+21C to zero through
A954C0(0). `InputStateDevice` provides the canonical histories. Only the empty
registry construction/destruction composition is represented here. General
force-request insertion/processing and the nonempty A95A80 registry destruction
remain a separate family; no fake request objects or SDK implementations are
provided. D5B7F0 vslots +38/+3C at A98CC0/A99710 and binding configuration at +30
A94440 are outside this packet. Name/accessor and other unused vslots are not
claimed as a complete vtable implementation.

## Validation

`scripts/build.ps1` passes MSVC Win32 Release with both existing CTests.
`tools/ghidra_export.py verify-seeds` reports eight matches. One ignored local
fixture (`local/joystick_input_fixture.cpp`) uses explicit recording COM doubles:
two enumeration passes; object ordering and dynamic layout; all range offsets;
cooperative and force-effect parameters; constructor polls; deadzone rounding;
relative/down/POV queries; clock timing; GetDeviceState partial failure versus
Poll failure; reset command ordering; reverse names/storage destruction; two
Unload calls and no COM releases. The fixture does not load DirectInput/XInput,
create windows, access hardware, change focus or validate gameplay. Commands and
result are recorded in the JSON report.
