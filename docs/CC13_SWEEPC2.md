# cc13-sweepC2: the functions cc13-sweepC deferred

Packet cc13-sweepC2 (2026-10-16) takes the "Skipped or deferred" rows of docs/CC13_SWEEPC.md. Code:
`src/cc13_sweepC2.cpp`, `include/bsp/cc13_sweepC2.hpp` (namespace `bsp::cc13_sweepC2`, host

## Model

As in cc13_sweepC: each routine works on the original object as raw bytes (Win32 offsets from the
image) and makes every call the image makes, at the same point, through a `SweepC2Host` method
named after the image routine or virtual slot, with the register inputs spelled out. Calls between
routines reconstructed here use the C++ directly (00A788A0 and 00A78CE0 call the reconstructed
RequestMusic 00A786F0). Debug-STL checked-iterator reports (00BF6713) are kept where the image makes
them. Constants carry their image address and width. These are new C++ interfaces, build-tested
only; nothing is bound into bsp_game and nothing here is ABI-compatible or game-validated. Names are
hypotheses, not recovered symbols.

## Shared RNG 00BD2F10

One draw site: 006CD810 (BSP_AirOps_AiLaunchTick) calls 00BD2F40 with ECX = 1 at 006CDAA5, once
per pass of its weighted kind pick. A pass is repeated, with a fresh draw, whenever the walk runs off
the end of the weight map (weights summing below the roll) and whenever the picked kind is still
owed by the launched-count map (that count is decremented first). The draw count per tick is
therefore data-dependent. The host still does not run this function (air_operations.hpp 815-821),
so wiring it would add draws to the shared stream and move every later consumer.
