# CC15 G24A: seven game-code rows from the stl_probable audit

Packet cc15-g24a. The cc15-stlA audit (docs/CC15_STL_PROBABLE_AUDIT.md) moved these rows from
`stl_probable` to `game_code`. The bodies are in `src/cc15_g24a.cpp`, with the interfaces in
`include/bsp/cc15_g24a.hpp`. They are new C++ interfaces with one host struct per function.
Object fields are read through their native Win32 byte offsets, and every call and global goes
through the host. Status: reconstructed and build-tested only. They are not ABI-compatible,
not wired into any host and not game-validated. Names are hypotheses.

Every `00BF6713` (`_invalid_parameter_noinfo`) call returns in the image. Each is modelled
as a host call at the same place, and the walk continues after it.

## Evidence notes

- **0045B420.** The point list is at owner+0F4h. Each node holds a 38h-byte record whose +0
  is the time. 00465A40 builds the record (RET 38h, checked at 00465B53, so the ledger's
  "RET 3Ch" note on 00465A40 is wrong). Where the record goes:
  - When the list is empty, or the begin time is greater than `time`, the record is inserted
    before begin inline: 00459EA0, then 00459900(1), then the link stores. The test is
    FCOMIP with JBE, and an unordered result takes the search branch.
  - Otherwise it goes after the iterator returned by 00455BC0, through 0045B0A0 (RET 10h).

  The empty branch copies the argument string with 0041DD40 and memcpy. The other two
  branches use 00426060. Two strings go back to the sized pool, each released as
  (length + 1, 1): the record's string at +4/+8 and the by-value argument. The 00BF6713
  call at 0045B45C is dead, because the `CMP ESI,ESI` before it always sets ZF.
- **0045DDA0.** Each pass of the index walk re-reads the vector words at +68h/+6Ch. Each
  non-null track goes through 0045B220, then `_free`. The slots are not nulled. The vector
  is then emptied by an inlined erase(begin, end). Finally +0 and +4 are reloaded from
  00D7A24C and 00CE3800, which hold 1.0f and 0.5f on disk.
- **00480A90.** The threshold is ((seed*7B913h + 67933h) mod 5A1C9h) / double[00CE6428],
  and the double on disk is 369097.0. The function sums the floats and returns the first
  index where the sum is greater than the threshold, or 0 if there is none. The model
  assumes main-thread precision (PC 24-bit). Both operands are exact floats, so one float
  division gives the same result as the image.
- **004872D0.** This is an inlined VC9 `list::remove(child)` over parent+0Ch. The iterator's
  container is the list itself, so the null-container and foreign-container checks never
  fire.
- **00489DD0.** It writes vtable 00CE6600, then detaches from the parent at +8 by calling
  004872D0 with the parent in ECX. It then deletes the front child until the list at +0Ch is
  empty; each child's destructor unlinks itself. Last, it calls 00485290. The 00BF6713 call
  at 00489E1F is dead, for the same `CMP ESI,ESI` reason.
- **004A5AA0.** The map is at manager+1Ch, and the key is the unit word (the key pointer is
  the address of the argument slot). While map[unit] (004A5750) is non-empty, the function
  deletes its front object through vtable slot 0 with flags 1, then calls
  map.erase(map.find(unit)). The library helpers carry wrong names in the ledger:
  - 0048CF20 is `map::find` (lower bound, then a key compare, RET 8), not EqualRange.
  - 00491F40 is `erase(iterator)` (RET 0Ch), not an xlen throw.

  The cc15-stlA note's "erases the key's equal_range" means the same thing for a unique map.
  I did not rename these helpers because they are outside this packet.
- **004AD380.** It writes vtable 00CE6F68. Each non-null element of the pointer vector at
  +18h is deleted through vtable slot 0 and its slot is nulled. Then the vector is erased,
  its storage freed, and +18h, +1Ch and +20h zeroed.

## Limits

- EH unwind paths are not modelled.
- 00419CC0 is modelled as taking no arguments: the three pushes before it belong to
  00BD1510.
- 00480A90:
  - A 53-bit pool-worker caller would round the quotient twice.
  - The host's double divisor is converted to float, which is exact only for representable
    values, as the on-disk 369097.0 is.
- A null front child in 00489DD0, or a null front object in 004A5AA0, loops forever, as it
  does in the image.
