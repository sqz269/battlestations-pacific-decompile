## Normal schedule and failure boundaries

| Phase | Source behavior and armed cleanup |
| --- | --- |
| Receiver entry | Store D68BC4 to actual A+0, then arm unchanged BaseCleanup as state0. A hardware fault before/at the store is outside this policy. |
| First manager | Genuine415350 returns M1; read captured S from unguarded M1+10. Create CE37FC/S guard; if S, Enter then increment its current DWORD+18. Before this completes, only base cleanup is armed. |
| State1 | Arm GuardCleanup even when S is null. Genuine second415350 returns M2; only afterward load current P from actual E1AE90. A/P and M1/M2 may differ. |
| Removal/publication | Call genuine BCFCA0(M2,P) unconditionally, including nullP. Only after it returns, store literal null to G even if removal changed G. No cache, identity check, compensation or old-value restoration. |
| Normal release | If captured S, decrement its current DWORD+18 and Leave S. Guard cleanup stays armed through normal Leave. A Source C++ escape there can decrement/Leave the same captured S again; balance and safe cleanup are not promised. |
| Normal return | After Leave returns, disarm guard, call genuine412430 to store CE3818 at A+0, then disarm base. Return void; no semantic EAX, free, payload cleanup or owner handoff. |
| Source C++ escape | Reverse RAII order invokes genuine411EE0, then genuine412430 only if guard cleanup returns. Existing MSVC C++ cleanup-escape termination remains. Hardware/foreign exceptions and Original FH3 behavior are excluded. |

These operations retain the native hazards: no manager null guard, no replacement lock, no depth clamp and no rollback. The private cleanup target reads the captured section, resets its guard profile, then conditionally decrements current depth and invokes Leave. The Source policy neither activates the reconstructed native state map nor promises completion after a failed cleanup.
