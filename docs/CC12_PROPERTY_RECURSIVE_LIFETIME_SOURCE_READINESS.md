## Closed Source binding and real ownership domain

Actual native phase data establishes `CE89D4[0] = 004E6730` and
`D16504[0] = 008F59E0`. On provenance-qualified live records and bags, bind
these two native calls directly to the two **complete new named Source
scalars**. Those scalars in turn call the complete named Source phase/release
or bag destructor. This closes the six-body recursive call cycle without
an opaque callback or a partial scalar. `D162C4[0] = 008F4170` is retained as
native data evidence; the six-body family never invokes that inner slot.

The phase literals remain the actual words emitted by the accepted raw
constructors. They are not callable Source addresses. No synthetic record,
bag, owner, substitute vtable, profile-memory array, generic destructor
callback, user-selected allocator or Original numeric call is proposed.
A matching numeric phase word alone does not establish allocation provenance
or membership in this Source domain.

Use an explicitly borrowed `NativeScenePropertyLifetimeContext`, constructed
from the actual `game::GameNativeStringProcess&` and
`game::GameNativePhysicalPoolProcess&`. Both process classes have private
constructors and existing canonical accessors. Context construction obtains
the former's real `raw_context()` and the latter's guarded
`property_node_pool_storage_00e175b0()`. Store those references/pointers
privately; accept no arbitrary raw pool or `NativeStringStorage` callback.
Resolve the pool before entering the six-body operation, so recursive clear
does not add repeated process-getter/mutex side effects between native stores.
The context owns no record, bag, pool, string header, allocation or callback.

Call `destroy_native_string_header_0041dd20(actual_node, context.keys())`
using the existing concrete `NativeStringRawPoolContext` overload. Its whole
51-byte Source body directly reaches the actual getter and return providers.
The node already contains the genuine length/pointer header; do not copy it
into a made-up temporary. The canonical process's `strings()` returns the
same actual-cell `ActualNativeStringPoolStorage`, whose existing 28-byte
header adapter and complete 420-byte release body are also retained. The
chosen concrete raw-context overload avoids introducing abstract provider
dispatch and preserves its existing getter-exception boundary. Ordinary
successful operation is the proposed admission; neither overload proves
Original exception behavior.

The caller must meet these concrete ownership conditions:

1. Complete the existing explicit
   `initialize_property_node_pool_once_00cc8a30()` first. Borrow the actual
   same initialized `38h` E175B0 cell and the process's same E188B4 allocator
   list. E17540, E175E8 and 0109DBF0 are distinct pools and cannot substitute.
   A nonzero cached atexit registration status still means construction
   returned and the pool exists, but provides no cleanup callback. A thrown
   startup is not a usable pool and is never retried by this context.
2. Every node is a uniquely allocated, aligned `14h` slot returned by the
   accepted allocator for that pool, normally through the accepted real
   `008F2930` new-node publication fragment. Its allocator-owned page ID at
   `+10` selects a live table entry; the slot is within that page's 64 slots,
   is not already in its free stack, and the page has space for its return.
   Do not independently reset page IDs, lists or critical sections.
3. Each nonnull mapped record is a genuine live `38h` current-CRT allocation
   with the accepted producer provenance and CE89D4 phase. Each nonnull
   type-6 child is the distinct mutable `114h` output of the real raw61/empty
   bag producer and accepted type-6 attachment. Every child backlink is the
   non-owning parent link established by the real 58-byte constructor.
   Real populated maps can be formed by the accepted lookup/new-node path;
   a populated clone implementation is not needed to destroy such maps.
4. Owning record, child and node edges form finite, unshared, acyclic graphs.
   The non-owning child backlink does not create an owning cycle. No root,
   key buffer, array block or reference block may be freed twice or alias
   another live object/frame/interior. Keep sufficient stack for the actual
   recursion. No cycle detector or substitute collection policy is proposed.
5. Keys are genuine copies allocated through the same canonical raw string
   cells as publication. A nonnull key releases captured pointer and current
   DWORD length plus one; a null pointer skips the length read and provider.
   Every nonnull return still calls the real getter **before** the return
   provider decides its size/gate path. Size `>= 150` frees through current
   CRT regardless of the small-return gate. Size `< 150` reads the real
   `01090AA4` gate: nonzero skips ring/critical-section return, with no extra
   free or header reset. For enabled small returns, retain the same live pool
   generation that supplied the key and valid ring capacity/indices. Do not
   treat the disabled gate as permission to destroy other graph storage.
6. Value buffers and roots released through current CRT must belong to that
   same actual allocation/free domain. In particular, array pointers are
   owning heap bases, and record `+28` plus child `+110` remain non-owning.
   No borrowed, stack, Original-process heap, pool-slot or map-interior free
   is admitted. Tag 7's payload is not promoted to ownership by this design.
7. Keep the canonical processes, publication cells, actual key storage,
   initialized pool/list, slots, roots and borrowed context alive for their
   required operations. Complete all record/key/node lifetimes before
   CD9260 releases property-pool pages. The string process is intentionally
   process-retained; the physical process registers its C++ destruction
   before the later pool callbacks. Preserve those existing orders and the
   supported getter's real manager/pool publication behavior.
8. Serialize graph mutation and pool trimming with the existing allocator
   domain. There is no concurrent mutation, trim, callback reentry, aliasing
   publication, arithmetic overflow, failed allocation, invalid memory or
   exceptional unwind in this ordinary successful admission. Do not add
   rollback, count-zero shortcuts, synthetic success or an extra free policy.

uses real Original FS/SEH registration and restores it on the normal path.

calling convention and argument transport, not an Original vtable ABI.
They claim successful native operations and root-bit results, **not**
Original RET4/register/flags/FS/SEH, exceptional cleanup, historical CRT or
drop-in binary compatibility. No naked scalar or hidden-context transport is
proposed; adding either would require a new complete ABI proof.
