# Raw wide-string assignment

The new raw-context004C5E20 overload covers all24 normal instructions. Original ECX=destination8, stacked source8, EAX=SAME destination and RET4 are normalized to an ordinary MSVC Win32 signature. It uses the caller's SAME actual AA8/AA4/AA0 graph through genuine raw4C53E0; existing wide/string/pool interfaces and algorithms remain byte-identical.

Destination/source identity returns immediately, before any header or provider read/effect. Otherwise capture source LENGTH for real preserve1 resize. After normal return reread CURRENT source LENGTH: zero skips BOTH DATA reads and copying. Nonzero captures CURRENT source DATA FIRST, then CURRENT destination DATA. Forward fenced WORD reads/stores include the actual NUL; after every store advance source2 then destination2 using wrapping DWORD arithmetic. No measured-length bound, input guard, header clear, post-resize self test, copy-constructor or semantic storage adapter is introduced.

Header/WORD accesses are byte copies into genuine scalar locals, with compiler barriers; no live typed DWORD/WORD/header object is assumed. Caller supplies genuine reached raw8/WORD extents and legal source/output/backing aliases, with lifetimes surviving resize and the whole streaming loop. Writes may affect later source reads, but the captured DATA cursors are not retargeted. Invalidating concurrent writers, private-stack protocols, hardware/fault/MMIO equivalence and unspecified backing are outside the ordinary-storage contract.

This leaf owns no temporary or selected EH action. Resize and partial stream failures leave actual header/backing/pool/publication debt with the real caller. No catch, rollback, retry, destructor, Frame, manual free or allocation-success fallback is added. Normal return is only the actual destination-return boundary, not an owner, loaded manager or later consumer permission. Existing raw resize/current-provider/allocator/error/overlap-copy/zero-byte-call qualifications remain inherited.
