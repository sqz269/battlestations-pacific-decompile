# Canonical base widget and Group deletion

Addresses: AA9730, AA8320, AC73E0, AC7260, AB8EE0, AB6A30, A9E070.

The common AA9730 sequence now consumes the existing canonical widget owner and
GuiTextChildDeletion allocation transport. Text's AB8EE0 path invokes it after
the actual AB8250 derived phase. Group's D5CB80 current4 target AC73E0 installs
its Group profile and immediately calls AA9730; it has no extra derived resource
tail. Its native flags-bit0 test occurs after that call. The new Group entry
preserves this ordering over the same parent-owned or transferred C++ allocation.

AA9730 first installs the base D5C130 table. Child20 still selects each child's
actual implementation; the current object's query at AA8372 is base-only. The
AB6A30 getter only reads F8BE28, while A9E070 scans F8BC88/8C. The C++ base path
projects their false Text-kind result under the valid initialized class hierarchy;
corrupted, aliased or concurrently changing native descriptor tables are outside
this interface. It does not call the already destroyed Text secondary hook.

The child4 loop always reloads the current head after a successful deletion.
Group and Text are now both accepted, so a mixed tree no longer fails merely
because its next child is a Group. A child stays attached through its derived
destructor, then detaches during its own base tail. Parent/root/node operations
use the existing actual detach helper and same native node lifetime domain.
The main node is re-tested after detachment, then the existing canonical timed
owner drains entries and backing. The emptied logical child-list projections
release their C++ allocations at AA9951..AA998E, even for flags0. Base profile
retirement does not decrement the reference count.

Scalar phase and flags are lifetime metadata on the existing GuiWidgetOwner.
The Text companion's historical phase remains synchronized. Recursive retirement
of an active or unfinished owner rejects before destructive work; an active
AA8320 call also protects its owner during scene callbacks. The host child list
must keep its count and current entry during child20 traversal. These are bounded
C++ lifetime guards, not native SEH, arbitrary callback reentrancy or atomic tree
retirement. Unsupported child4 profiles fail at their actual phase and retain
unfinished state; the function must not be restarted as if it were resumable.

Flags1 requires an actual owning parent entry or previously transferred handle
before effects. Flags0 performs the same teardown but retains its detached
wrapper for explicit disposal through take_detached_storage. Native Group pool
AC7260 uses F0-byte slots and the slab id at +EC in pool F8BFA0; this implementation
does not claim that raw pool ABI, Text's native pool, intrusive-list allocation
layout, vtable storage or the original EAX-return interface. The page manager's
separate companion-retirement projection is not replaced by this scalar path.

Strict MSVC Win32 compilation and the combined Release build pass, including
both existing CTests. One focused real-owner Group fixture passes nested child
and timed-entry retirement, both logical/native child trees, flags1 cleanup and
flags0 allocation preservation. It does not execute a mixed Text tree or native
machine-code differential. No permanent tests were added. Exact call-site checks
and final integration evidence are recorded in reports/gui_widget_base_lifetime.json.
The executable does not yet reach this complete canonical runtime; no game or
rendering validation is claimed.
