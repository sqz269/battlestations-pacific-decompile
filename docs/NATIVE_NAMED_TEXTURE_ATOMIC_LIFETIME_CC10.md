Reused backing must have no old companion, outstanding credit or in-flight access. The actual process serial is a live, disjoint `uint32_t`. Complete owner/string/cache/source/COM lifetimes remain independently required. Explicit placement directly establishes the intended atomic(1) lifetime. The independently compiled traits receipt for installed MSVC 14.51 Win32 C++17 (`_HAS_CXX20=0`) shows that outer `atomic<int32_t>` is default-constructible but has no eligible trivial default/copy/move constructor and is not an aggregate; its destructor is trivial. Thus allocation/byte-array implicit creation does not establish this particular atomic absent a separate construction event. This is compiler/type-specific evidence, not a universal C++17 atomic assertion or an inference from count bits/deleted copying alone. Count value and registration alone are not lifetime proof.
