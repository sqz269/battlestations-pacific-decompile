# Sampler cache string-header representation accesses

The B1A4F0 continuation now reads string-data representations with a private memcpy helper and clears data with a memcpy null-pointer store. Previously these fields were accessed as volatile uint32 words. The exact reviewed one-file candidate changes nine read expressions and one clear expression, mapping to 21 native data reads and three pointer stores. It preserves existing node/record accesses, counts, callbacks, ownership and lifetimes, with no public API/header/CMake/test addition and zero new native-byte credit.

Exact source SHA: `64cbf82f9417a1e931196ad63de3e5ec7cb95f7ade0b885d266e963925921e1a`. Requested/resolved/hidden temporaries are existing uint32[2] storage; record and alias name prefixes contain actual char* members. The input is a caller-borrowed actual eight-byte header with no assumed host wrapper type. Representation access reuses the existing generic NativeString helper pattern without projecting any of these bytes as a NativeString object, adopting arbitrary pointer bits or adding an owning header. Length reads retain their existing uint32 accesses. Hidden resource-pointer reuse and profiles remain separate.

The helper is NONVOLATILE. This packet qualifies actual emitted ordering for this strict Win32 build; it does not claim a fixed-width volatile access in the C++ abstract machine or support for concurrent/asynchronous mutations. Existing valid current backing, pointer representations and buffer/lifetime obligations still apply. No optimizer attribute, barrier, assembly or noinline adjustment was added.
