## Current selector, phase and flags schedule

The private phases are `bound`, `zero_dispatch`, `retiring`, `retired`, `failed`. Phase guards reject reentry before Native raw access. The expected internal zero adapter is admitted only in `zero_dispatch`; a second recursive invocation sees a consumed phase. The public phase/identity queries inspect companion metadata only and require that this companion itself is still alive. An identity retained after failure/retirement is diagnostic, never permission to read dead fields or a recycled slot.

Observed-zero entry is the existing `RenderCommandReference::release_zero_references() noexcept` interface. It first saves identity, registry and disposal metadata, then enters `zero_dispatch`. It checks this same registry binding, the already-zero actual count and current profile/current slot0`BD30E0`. It does **not** decrement again. The real existing `invoke_native_ref_counted_delete_00bd30e0` performs its own fresh current-profile capture. Its private adapter checks expected identity/flags1 and reads the **current** numeric slot`+4` from the actual alias, requiring`AB8EE0`.

After that target capture and before callbacks, the adapter consumes phase`retiring`, writes literal **DWORD1** to its persistent `frame.zero_flags`, and immediately calls genuine `delete_native_gui_text_storage_00ab8ee0`. Initial prepared flag bits are ignored. This is the reached `BD30E9 PUSH1` projection, not a previously initialized word that happens to hold1. Only real118 later reads the **current low byte** at this same stable address, after its destructor returns. The literal write does not freeze that byte against permitted callback effects and does not imply that bit0 will still be set at the late test.

`delete_current_scalar_00ab8ee0(caller_flags)` is a separate direct current`+4` operation. It performs **no count read, zero gate, decrement or protective retain**. It saves completion metadata and consumes `retiring`; flags preflight checks only their live address/extent/alignment and separation from raw/companion/persistent frame/known provider/disposal backing. Direct caller flags must be separate from the companion's prepared zero frame. It verifies the same canonical metadata entry, reads the current raw profile, then current numeric`+4`, and calls real118 with the actual caller's flags address. It never snapshots or reads the flags value itself. This explicit valid-storage domain preserves real118's late byte behavior.

Whole real118 preserves its current shader/current-zero dispatch, clear-after-return slots, current188/glyph/vector reloads, five data→state→conditional-current-length string releases, vector state3/no normal2, final base and seven reverse cleanup states. None is replaced by this adapter. Source85's `provider_call` marker is not Native exception-origin proof. ## Success and independently retained failure

Both entries capture disposal/registry/identity metadata **before** real calls. Only after genuine scalar returns successfully do they mark the companion retired, call exact-match registry `unbind` using independent metadata, then invoke the saved nonthrowing disposal callback **last**. That callback may destroy the companion. There are no later raw/companion checks or accesses; the direct method returns only the saved result local. The destructor requires success-retired and performs no native cleanup. Ordinary registry-unbind/disposal contract violations terminate through their nonthrowing interfaces.

The actual pool return happens inside real118 before this metadata completion. External serialized lifetime control must exclude slot reuse/new registration through the subsequent unbind. Do not move/delay Native pool return to simplify metadata handling. If current flags bit0 is clear, genuine118 still ends widget lifetime but does not return the slot; its allocation disposition remains with the actual caller. This companion does not synthesize a later return or own the slot.

An escaping direct Source failure only stores private phase`failed` and rethrows. It does not unbind, dispose, return the pool slot, destroy a creator, roll back shader/Shadow effects, retry or rediscover Native fields. The caller must keep this failed companion/registry identity, all scalar diagnostics/frames, completed creators and entire independent context/provider/backing graph alive. These are borrowed addresses, not automatic native owners. Outer118 cleanup may already have ended base/widget lifetime; the retained registry entry is diagnostic and cannot authorize another Native count/current-virtual access. Failure disposition remains explicit and separate. The Scene companion's catch-retire/unbind-on-failure policy is deliberately not used.

Entered zero-terminal errors store phase`failed` then terminate, following the existing Source `noexcept` terminal interface. No failing graph is automatically cleaned or disposed. A preterminal registry/identity error in an external count release can instead escape **after** its decrement and leaves an independently retained already-zero observation/obligation; it must not be replayed. Nested canonical effect-zero destruction used by118 is also nonthrowing/terminating, so its failures cannot unwind into Text outer cleanup; preterminal profile/lookup Source errors can. These policies and ordinary `/EHsc` catches do not establish Original FH3/SEH, Native IAT/register ABI, or arbitrary native provider-failure equivalence.

Caller-held creator1 → real material retain2 → matching material release1 remains useful and unchanged. It is no scalar/ancestor/lifetime barrier. A direct scalar may retire a positive-count Text; external raw118 bypass while this binding is active is excluded. All potential child/timed/ancestor routes need coordinated genuine bindings or an explicit domain exclusion. Profile/payload replacements stay current reads in the real providers. Replacement creators/services and their frame/registry/lifetime backing must already be retained before publication; no alias is adopted as an owner or discovered from ended fields.
