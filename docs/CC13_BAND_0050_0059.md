## Method

1. **Template shapes (126 tags).** The cc13-stl1 pipeline (`tools/template_shapes/`, see
   `docs/CC13_TEMPLATE_COPY_SWEEP.md`) was rerun over 00500000-0059FFFF from copies in `local/s50_st/` whose target filter
   is the address range (raw `FUN_`, no ledger name, no tag) plus the reviewed decision exemplars. Rows outside the band
   (fourteen 0042/0043 exemplars still untagged on main) were dropped before writing. Result: 106 `stl_shape`,
   8 `stl_probable`, 6 `trivial_body`, 3 `cg_adjustor_thunk`, 2 `tmpl_shape`, 1 `cg_scalar_deleting_dtor`, applied with
   `ghidra_tag` under the write lock (`local/s50-st1-ghidra-tags-0-20261012T121958Z.json`; 118 renamed, 8 bookmarked).
2. **Names (513).** Every remaining raw function was exported (`tools/ghidra_export.py decompile`), viewed with its
   callers, strings, named callees and vtable neighbours (`local/s50_view.py`, `local/s50_vt.py`), and named from string
   anchors, vtable position, constructor/destructor vtable stores, caller context and shape. Screen vtable slots use the
   layout visible in the 00CF791C dump: GetScreenId, IsSelfManaged, -, scalar deleting dtor, Register, -, Enter, Exit,
   Update, CollectChildren. Listener entries are named by their byte offset from the listener vtable the destructor
   stores. Names were validated for uniqueness against the whole index, written with `ledger.upsert` and applied with
   `ghidra_annotate --apply` (prior values in `local/ghidra-annotations-20261012T123902Z.json`).
3. **Assembly.** Read for every reconstructed function (the debug list render and selection math, the x87 map
   conversions and remap, the message type filter) and for the list erase 00522B70.
4. **Gameplay was left alone** beyond container copies and screen vtable plumbing (see "Left for cc9").

Ghidra state: `_free` (00BF9DC8) was checked before and after with `bsp.py ghidra proto` and is unchanged
(`void __cdecl _free(void*)`). No function was created or deleted, and no analyzer was touched.
