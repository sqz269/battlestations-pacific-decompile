# Native GUI page vector (CC10)

This packet operates on the **actual** 0x88-byte GUI manager from `00AA5D70` and actual page pointers. It does not create pages, attach typed `GuiLayoutPage` storage, dispatch movie focus, or bind the application. The source API adds a `NativeGuiPageLifetimeHost` argument to route two separately inspected current-page virtual calls; it is not an original binary ABI.

| Native body | Original ABI and covered behavior | Limit |
| --- | --- | --- |
| `00AA30C0-00AA3138` | ECX manager, one page pointer, RET4. Remove the first identical pointer from manager+14, shift subsequent DWORDs with equal-size/count `memmove_s`, decrement end; do not destroy or decrement the page. | Source CRT invalid-parameter handler differs from the original CRT. |
| `00AA52A0-00AA5383` | ECX manager, one page pointer, RET4. Call `00AA30C0` first, scan signed page+FCh priorities, insert before the first strictly greater priority, append directly if capacity permits. Equal priorities remain in arrival order. | Middle/growth insertion uses the existing `00BD08D0/00BD0700` raw four-byte-slot adapter, whose vector layout and one-element insertion body match the native `004D3B70/004D1B20` used here. The original library function is not separately ported. |
| `00AA31F0-00AA327E` | ECX manager, one page pointer, RET4. Find first identical pointer, shift and decrement end, call its current virtual+20, then reload its current virtual+04 and call with flag 1. Absent pointer returns without dispatch. | Virtual body providers are external. `00D5BE38` selects `00AA8320` and `00AA38F0`, but this module does not hard-code that profile or swallow unsupported profiles. |

The raw vector header at manager+14 has untouched DWORD+0, begin+4 (= manager+18), end+8 (= +1C), capacity-end+C (= +20). Its producer, `construct_native_gui_manager_00aa5d70` in `src/native_platform_focus_owners.cpp:221-260`, zeroes these three pointers. The producer of page+FCh is `00AC6600`/the layer property reader, whose typed projection retains signed `applied_priority` (`include/bsp/gui_layer.hpp:104`). The register function is called by `00AA5840` at `00AA5957` on initial load and by `00AC59A0` at `00AC5EED` when camera-store acquisition changes priority. The same-pointer removal before insertion is therefore required for repositioning, not an ownership release.

The `00AA52A0` assembly calls `00AA30C0` at `00AA52AE`, calls `004D3B70` at `00AA5314` for middle insertion and `00AA5375` for append with no spare capacity, and uses the in-place append at `00AA5349-00AA534F`. Both `004D3B70` and the existing `00BD08D0` read +4/+8, calculate the captured iterator index, call their raw count-one insertion helper, then validate/write the result pair. Both count helpers operate on +4/+8/+C four-byte slots, capture the incoming value before allocation, grow by max(count+1, capacity+capacity/2), copy prefix/value/tail, free old storage, and publish begin/capacity/end in that order. The reused adapter uses the same malloc-paired source storage and preserves raw pointer identity. Native helper symbol identity, original CRT exception frames, and invalid-handler identity are outside this source interface.

`00AA31F0` itself **does not** release a reference. `00AA5840` increments page+4 only when asked for an existing page with add-reference set; a caller such as `00518250` reads page+4 and chooses `00AA31F0` only when it equals one, otherwise uses a separate `InterlockedDecrement`/virtual-zero path (`include/bsp/title_init.hpp:73-81`). Other callers may use different ownership contracts; this packet does not generalize their release policy. Native `00AA326A` calls current virtual+20 after the vector removal, then `00AA3276` reloads the page vtable and calls current virtual+04(1). `NativeGuiPageLifetimeHost` from `include/bsp/native_gui_media_focus_lifetime.hpp` is reused to keep these calls separate and permit a changed profile between them. The host must provide real current-profile dispatch; the page remains alive until the second call begins.

The current `GuiPageRegistry` (`src/gui_layout_loader.cpp:707-727`) owns `unique_ptr<GuiLayoutPage>` and performs a similar stable priority insertion in `std::vector`; its addresses and objects are **not** the raw manager vector. `GameFrontendHost::release_screen_page` presently leaves typed pages loaded and logs `00AA31F0` as unimplemented. The next composition must first build actual page/profile/list/scene identities and bind page virtual providers; passing typed page pointers to this module is invalid. Native manager shutdown also iterates raw pages and invokes virtual+20/+04, so a removed page must not remain in that vector for a second deletion.

Validation: MSVC Win32 `scripts/build.ps1` and its three CTests passed. One ignored local Win32 probe linked against `bsp_core.lib` and passed: signed priority ordering, stable equals, same-pointer repositioning without duplicates, preserved page+4 reference word, vector removal before virtual+20, and virtual+04 after a profile change. This was a source-only probe, not original-code differential or game validation. No application path reaches this module yet.
