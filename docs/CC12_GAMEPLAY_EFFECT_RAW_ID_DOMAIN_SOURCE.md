# Gameplay-effect raw ID domain Source

This packet adds ordinary Source overloads for `008700E0`, `00870CD0`, `00870D00` and `00871440`. Acquisition and destruction borrow the same actual manager publication cells. Existing typed overloads and bodies remain unchanged. There is no category fragment, terminal slot0 binding, companion/prebinding protocol, application activation or new compilation unit.

`NativeGameplayEffectManagerCells` borrows the actual `01090AA0` and `00F87664` pointer cells. The ID context uses the existing current-game Lua selector, string storage and component services; it needs no name-index setup or replacement cache. The definition context borrows those same manager cells and the genuine string/component lifetime services. These bindings and their referenced objects must remain valid, and acquisition and destruction must use the same raw manager domain.

The raw lower stores null for signed ID<=0 without reading/releasing old output or accessing manager storage. Positive IDs use the actual tree at manager+4 and genuine signed find/unique insertion. Hits atomically retain actual payload+4, then reread the captured node's current value. Misses select current game Lua+1A0C, obtain Effects and the ID definition, test only the flag's low byte, load/identify the actual24h definition and insert its weak pointer. Equivalent/reentrant insertion neither retains the returned value nor invents cleanup for a losing fresh allocation. Name string, Name/definition/Effects Lua references and the Lua host are cleaned before the final current node-value read into output. Manager, captured node and referenced storage must stay valid throughout callbacks.

The wrapper logically captures output and ID, calls the genuine raw getter unconditionally (including ID<=0), then reads the borrowed full volatile DWORD flag and calls the lower. It returns the captured output address. Actual output, unsigned flag and any Lua conversion-mode bool are distinct live objects. Private argument/frame aliases and unstable bindings are excluded: MSVC can load the private output/ID argument slots after the getter, so this establishes ordinary Source capture under those preconditions, not Native stack-alias or register capture equivalence.

Raw definition destruction writes D0DA58 identity, arms the member cleanup, gets the current raw manager, then reads current ID+18. It finds and erases by ID through the genuine checked raw iterator provider, without testing the mapped pointer or substituting a new exception. It then destroys name, components and base in the established order. Array cleanup is disarmed before invocation, so an ordinary C++ failure does not retry the array. The matching scalar overload frees the original owner only after successful destruction and only when flags bit0 is set.

The existing `NativeStringStorage` header destructor is **noexcept**. Accordingly, MSVC removes the normal private state1 store before name cleanup and the final state-1 store; a name-cleanup exception terminates in this existing Source domain. The emitted state0 store remains before component-array cleanup. The private guard lowers state before each cleanup and terminates on a secondary exception. This is not Native name-throw/FH3/SEH equivalence.

The concrete `00870400` call retains the previously accepted Source loader operation. `GuiLua51Host` uses registry references. Neither proves Native current virtual+8/+14 dispatch or native14h Lua-object ABI. D0DA58 is an identity value, not a callable Source vtable. Actual current slot0/scalar dispatch, positive prebinding coverage, all terminal consumers, genuine live component/renderer/texture/sound services, original Native ABI and game/runtime behavior remain separate requirements. No default service or current-virtual adapter is added.
