# Frontend raw widget Model ownership contract

Frozen Source is Main `5dc9e9a018c8cb59b606fe904fca95ed7f9c574a`. The sealed Type2 audit is `911d59186e23f760a908e70648db26ec364e63f7`; its full 38-line document was read and all 56 current Source receipts match this checkout in bytes, SHA256 and Git blob. This is an actionable owner-migration design, **not an existing provider, Source admission or runtime activation**. The current Page constructor still has no Model supplier, its childless suffix still rejects mapped widgets, and `kNativeGuiPageChainCc15Bound` remains false. A second concrete blocker remains in the Model's terminal route: its canonical companion still delegates scene destruction through the legacy runtime. Consequently a complete populated raw Model provider is not yet Source-ready.

Select **one renderer-retained Model-companion domain**, extracting the common ownership from `GameNativeMissionModel::Impl`. Page and Mission become clients of that owner. Do not instantiate a frontend Mission Model: its constructor also binds sampler/effect ownership and its present owner exists only under `mission_ship.inc:140`. Do not expose an otherwise unused raw accessor. The migration and actual Page consumer must land together.

## Why this is the smallest real domain

`game_native_mission_model.inc:257–287` already composes the required process Model pool, renderer camera nodes, canonical owner registry, geometry/vertices, real material pools, VFS strings, mapped constants and Model tables. Its `raw_models` is born with `actual_names == nullptr`; `instance_models` borrows the same identities with `actual_names == &raw.strings`. The prepare callback explicitly accepts both environments (298–306). The same implementation already supplies constructor-failure retirement, canonical binding, terminal disposal and stream binding (308–340, 422–441). These are concrete ownership operations, not missing Native leaves.

The currently exposed `instance_geometry()` returns the typed environment (704). AAACD4 preflight requires the raw environment and the exact persistent raw-name-context object, node runtime and geometry owner registry (`native_gui_widget_property_children.cpp:29–38`). Nulling `instance_models.actual_names` would retarget live instance users and is prohibited. Preserve both environments as distinct, immutable interfaces over the same native providers.

`GameNativeGuiNodeApplication` is also genuine, but is not the missing supplier. It has a raw Model environment (CPP 71–96); its independent companions are private `GuiWidgetOwnerRuntime::ModelRecord`s and its public allocation path performs whole widget/layout association (`gui_widget_owner.cpp:425–487`). Its retained frontend instantiation is the Text-only diagnostic factory (`game_native_gui_render_application.cpp:422–437`), gated by GUI Text and Mission flags (657–668, 776–783). Its `GuiNativeScene` parenting cannot accept Page's raw renderer root. Merely returning `models()`, manufacturing a layout, or passing its legacy scene runtime to Page would leave the callbacks and lifetime unresolved. Do not migrate this separate diagnostic's disjoint objects into the new Page packet merely to widen scope.

The renderer is the actual shared retention root. Its geometry, camera and VFS-backed node services precede its optional Mission owner in member lifetime (`game_native_renderer_application.cpp:490–529`). `game_hosts.cpp:2313–2321` deletes `GameFrontendHost` before native singleton drain; Page bindings survive until 2335. A Model service owned by that frontend host would therefore die too soon. Keeping an entire Mission graph alive just to lend callbacks would introduce unrelated sampler/effect/generator obligations.

## Shared owner and exact migration

Proposed names below are new C++ host interfaces, not recovered symbols. Add `include/bsp/game_native_model_domain.hpp` and `src/game_native_model_domain.inc`; include the latter in the already compiled `game_native_renderer_application.cpp` before `game_native_mission_model.inc`. This avoids an unrelated CMake addition. The owner is noncopyable and address-stable. A `unique_ptr<GameNativeModelDomain>` in renderer `Impl`, declared before its client-owning optional graphs and after the providers it borrows, retains it through native drain. The new, actually consumed `GameNativeRendererApplication::model_domain()` creates/returns this one ready-domain owner; both Mission construction and the actual Page construction caller use it.

The shared owner must contain the **moved**, rather than copied, common fields: the shared type-bootstrap wrappers over existing VFS storage/counter, `raw_models`, `instance_models`, `materials`, Model and stream records, and the lifecycle implementation. It borrows `raw.strings`, graphics geometry/vertices, mapped `D5E520`, the Model constants/tables and the exact existing renderer/VFS references. There is one Model record per actual slot and one stream record per actual stream; records are stable host bookkeeping, not another canonical registry or native reference count. Keep `app.actual_owners()` as the only canonical registry and preserve `NativeModelReference`'s alias of actual `+04`.

Use an address-stable, noncopyable **client context** for each Page application and Mission implementation. It identifies the common owner and the client that acquired each record; it adds no native retain, pool, type counter or scene tree. Client contexts hold the two existing `NativeInstanceGeometryAccess` shapes as applicable: Page consumes a born-raw view; Mission consumes the typed instance view and its existing raw-loading view. Both use the same callback implementation and common environments. Each access's `companion_context` identifies its retained client context, which in turn names the one shared owner. Never mutate or replace these contexts/environments while a Model, stream, acquired frame or callback borrows them.

## Custody, retirement and admission boundary

A completed Model is not automatically owned by the Page list. The child helper's acquired record must distinguish allocation/preparation, constructor return, companion bind, child `+4C` publication and list linking. A constructor/preparation exception uses its existing retire-failed callback and same-pool slot return (CPP 44–62). After `constructor_returned` is set, a bind failure retains the completed creator (64–72), including an unpublished orphan. A later failure retains the already-created widget and Model independently; name cleanup has its own scratch state and must not imply Model destruction. No added reference, list deletion, retry or constructor-unwind path may manufacture recovery.

After publication, the actual child `+4C` and native reference graph determine retirement. The shared owner only supplies the canonical companion/terminal disposal; it does not independently release every record on client destruction or on failure. A retained client cannot be removed while records or acquired callbacks name it. Raw Page root/main-Model release, current profile dispatch and real timed entries must be supplied by the complete Page/Group lifetime graph; current Page callbacks still reject these routes. An empty default Model's `+180` is a construction fact, not a policy permitting only empty geometry or childless input.

Healthy registered Models/streams survive until their native owners retire. Incomplete acquisition/bind/name/retirement or a failed client prohibits normal singleton drain. Extend renderer retention checks to cover this service and retain the Page/Mission client, common owner, renderer, VFS/string storage, mapped data, callback captures and entered frames through the existing process-exit disposition (`game_hosts.cpp:2284–2290`). On a healthy shutdown keep the service through `singletons.shutdown()` and the Page lifetime host; require client records empty after their actual retirement, acknowledge common emptiness after native drain, then drop Page at 2335, Mission/client metadata and the shared service before their borrowed providers. A failure cannot unwind this graph normally, drain dependencies or replay a native entry.

The immediate ownership blockers are precise: the common lifecycle is still private to a Mission-owned `Impl`, no renderer-retained common owner/client migration or actual Page raw-access input exists, and the same canonical child's current54/zero-terminal route has no genuine raw-scene composition. The eight-file extraction plan selects the retention root and closes the ownership design; it cannot be approved as a complete populated Source packet until that last supplier is resolved with the reader/lifetime work. Review client isolation and compose the connected caller with raw parenting and complete retirement. A raw getter alone closes nothing.
