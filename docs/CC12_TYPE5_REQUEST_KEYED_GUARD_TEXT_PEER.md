## Correction and preserved checks

V2 reused `guard_entry_recipe_py.json` across separate recipe invocations, and
the guarded tool route similarly reused its entry and closure filenames. V4
validates the active request name against its exclusive request basename before
using it, then writes:

```text
guard_<decimal request-name length>_<request name>__<label>.json
```

The name is bounded to 1–80 ASCII alphanumeric/underscore characters; the label
is bounded to 1–100 of the same characters. The length fixes the request-name
boundary even when a valid name contains underscores. For example, `(a__b, c)`
and `(a, b__c)` collide under the V3 delimiter-only spelling but produce distinct
V4 names. An independently written string calculation checked 27 pairs, including
the five recipe entries, all eight before/after Native query route entries and
closures, and boundary examples. Every distinct pair produced a distinct string
and decoded to the original pair. This calculation did not evaluate selected
code or selected AST nodes. Exact repeated request/label pairs retain exclusive
creation behavior. On Windows, case-only request variants cannot both create the
exclusive request file; the reviewed fixed callsite labels are lowercase ASCII.
