# CC13 band 00400000-0044FFFF: naming and reconstruction sweep

Packet `cc13-sweep40` (worker cc13-sweep40, 2026-10-12). This was a non-gameplay sweep of the raw `FUN_` functions in
00400000-0044FFFF. Every name below is a hypothesis, not a recovered symbol. The C++ in `src/band_0040_cc13.cpp` is
**reconstructed and build-tested** (Win32 MSVC). It is not fixture-tested, ABI-compatible or game-validated. No game
runs were made.

## Method

1. **Template shapes (310 tags).** I reran the cc13-stl1 pipeline (`tools/template_shapes/`, see
   `docs/CC13_TEMPLATE_COPY_SWEEP.md`) over 00410000-0044FFFF. That stl1 run had skipped this band because it is outside
   every partition segment. The copies are in `local/s40_st/`, and their target filter is an address range instead of a
   segment list. Reviewed decisions, coarse twins, the repo's mechanical rules and the family regexes produced 145
   `stl_shape`, 124 `trivial_body`, 21 `tmpl_shape`, 10 `cg_scalar_deleting_dtor`, 4 `cg_adjustor_thunk` and 6
   `stl_probable` bookmarks. They were applied with `ghidra_tag` under the write lock
   (`local/s40-st1-ghidra-tags-0-20261012T113109Z.json`).
2. **Trivial bodies (58 tags).** Getters, setters, `*p = 0` and iterator-category dummies in 00410000-00412FFF that the
   stl1 rules had missed. Category `trivial_body`, evidence `st1_trivial`.
3. **Names (276).** I exported a decompile of all 420 functions that had none (`tools/ghidra_export.py decompile`). A
   PE scan found every absolute reference, and a vtable walk found the neighbouring slots (`local/s40_vt.py`,
   `local/s40_vtp.py`). Names come from string anchors, vtable slots next to named functions, singleton cells already
   named in headers, caller context and plain shape. The 205 functions with no caller and no data reference
   (unreferenced COMDAT copies) were named only by shape, or tagged. I read the assembly for every reconstructed
   function and for the x87 bodies.
4. **Gameplay was left alone.** That covers AvoidZone navigation, the gun and device-class registry, the plane HUD and
   zoom fields, and GameDynamicsList buoyancy. In those areas only pure container copies were named (`STL_*`,
   `TMPL_*`). See "Left for cc9" below.

Ghidra state: `_free` (00BF9DC8) was checked before and after with `bsp.py ghidra proto` and is unchanged
(`void __cdecl _free(void*)`). No function was created or deleted, and no analyzer was touched.

## Notable findings

- **Dialog command vtables.** The five command classes have 4-slot vtables with no RTTI, packed together at
  00CE4940..00CE49F8: scalar deleting dtor, `GetType`, `Read`, `Write`. `0044BE50`
  `BSP_DialogCommand_CreateFromArchive` reads the type string and allocates the matching class. The `Read` slots were
  raw: `0044A440` (msg: `panel`, `message`), `0044A570` (pause: `time` at 00CE37A8) and `0044A5B0` (callback).
  `0044A3C0` reads a `picture` field, but nothing references it.
- **Download manager.** I first named the vtable 00D1D7D8 slots `ContentPackageList`. That vtable is installed by the
  download-manager constructor 009955F0, whose object is published at 00F8A304, so they are now
  `BSP_DownloadManager_*`. `docs/PROFILE_COMMIT.md` runs virtual +14h on settings+98h after `0043EA80`. Virtual +14h is
  `0043E940` `BSP_DownloadManager_DisableOnly`. It re-enables every package that is not blocked, then switches **off**
  each listed name. So the settings list that `profile_commit.cpp` calls `downloaded_content` holds the packages to
  disable. The host method name `apply_downloaded_content_virtual_14` hides this. I did not rename that field or
  method, because they belong to another owner.
- **`0043EA80` keeps prefixes, not exact names.** It keeps a settings name when that name is a case-sensitive *prefix* of
  some package name. Any other name is erased unordered: the last entry is copied over it and popped.
- **`00438E80` trims zeros only before end of text.** It never trims zeros that are followed by a space, because its
  scan starts on the space character. Example: `"1.50 2.30"` becomes `"1.50 2.3"`.
- **Singleton base destructors.** These all clear a known cell and drop to the singleton base vtable 00CE3818:
  `00418280` (GameSettings, 00F8753C), `0042AC00` (GlobalConfigOwner, 00F878E4), `00425A80` (ProfileHintsOwner,
  00E17664), `00435750` (ProfileManager, 00E17680), `00435770` (VehicleClassRegistry, 00F8A0B8). The AvoidZone pair
  `004152B0`/`004152D0` (00E17624/00E17620) was left for cc9.
- **RNG.** `00439950`/`00439A00` (`BSP_Vector3f/2f_SetRandomUnitDirection`) draw from `BSP_Random_UniformFloatRange`
  with first argument 1. They were named only, and no host code uses them.
