# Physical stream pool on the shared raw lifetime manager (BA)

`NativePhysicalStreamOpenContext` now carries the existing borrowed `SoundLifetimeAccess`. A semantic fixture domain can still construct that view; a production host can instead supply its actual `01090AA0` publication. No second manager or projected-to-raw owner cast is created. The context and `0109DC28` pool publication must live through raw manager drain.

`00BF42A0` first reads the current pool. On a miss it captures the first manager's section+10 through `CapturedSoundLifetimeSection`, enters and increments recursion, rechecks `0109DC28`, allocates raw 10h storage, zeros +4/+8/+C, writes identity `D68EC0`, and publishes. It resolves a **second** manager before registering the then-current publication, releases the originally captured section on normal or abnormal exit, and reloads the pool publication after unlock. The separate raw stack placement of the captured guard keeps the source `__finally` release schedule. Allocation/registration failure does not invent rollback for an already published owner.

`00BF4370` consumes the popped raw pool and flags, clears `0109DC28` unconditionally, writes base identity `CE3818`, destroys its slots through `00BF3930`, frees the owner only for low flag bit0, and returns the original address. The first DWORD of original data table `00D68EC0` is `00BF4370`. `NativeSingletonDeletionBindings::physical_stream_pool` routes registered `D68EC0` through that body with the popped owner and same retained context, regardless of a later publication change; a missing binding remains a source contract failure. The same dispatch structure also binds existing `D5E5DC` render-batch pool and `D5E5D4` lock-owner deletion through the retained `NativeRenderBatchLifetime`, for the separately owned batch raw-lifetime packet.

Saved original ABI: `00BF42A0` has no arguments, returns the current pool in EAX and uses RET0; `00BF4370` takes ECX pool and one flags DWORD, returns the original pointer in EAX and uses RET4. These C++ interfaces are not binary replacements. The getter's 178-byte disk/live envelope `[00BF42A0,00BF4352)` decodes to 53 contiguous instructions, all owned by the saved function. The destructor's 49-byte disk/live envelope `[00BF4370,00BF43A1)` decodes to 14 contiguous instructions, but Ghidra currently excludes `00BF4398` (`ADD ESP,4`) from function ownership despite surrounding owned instructions. The report marks that one instruction unowned; it is not counted as a recovered saved-body pass. Primary integration owns any saved-listing repair.

This packet adapts pool registration and deletion only. `00BF3770` acquisition and `00BF5190` dead-slot append still call `NativeRenderBatchLifetime::lock_owner_00b1cd90`; that class currently needs a semantic `SingletonLifetimeDomain`. `00BF4BA0` physical open and `00BF55A0` recycle reach these paths, so the full physical stream route cannot yet share the raw batch lock or claim production completion. No archive or game behavior is established by a Win32 build.
