## Method

1. Survey per 64 KB band from the index (`local/s60_survey.py`), then a compact dump of every raw
   body (`local/s60_dump.py`: declarations, SEH and string-pool boilerplate stripped; string
   literals kept). 217 raw functions had no export; they were exported first
   (`bsp.py ghidra export`).
2. Classes from constructor vtable stores and from `.rdata` references: `local/s60_vref.py`
   finds the dword holding a function address, and the slot is read against the base screen
   layout of 00CEAE54 (+10h Register, +14h layout, +18h Enter, +1Ch Exit, +20h Update, +24h
   CollectChildren) or the listener / adjustor tables next to it. Unreferenced bodies (no call,
   no data reference) are named only when the shape is generic, and say so.
3. Existing docs were checked for every named address (`local/s60_docs.py` over the index's doc
   table); names were aligned with docs/HUD_MARKERS_RUNTIME.md, docs/CC13_AIR_OPS_SLOT_GROWTH.md,
   docs/CC13_HUD_AND_WIDGETS.md, docs/SCENE_CONTENTS_HOSTS.md and docs/PILOT_COMMAND_PATH.md
   (10 names or evidence strings were corrected after that pass).
4. Listings were read where the pseudocode has register inputs or x87 (00645160, 00645180,
   006067E0, 0064A740, 00622E30, 00638B90, 00658580, 006501A0, 006057E0) and constants come from
   the PE on disk (`local/s60_const.py`).

## Notable findings

- The plane effects screen (vtable 00CF43AC, slot 0 `BSP_HudPlaneEffectsScreen_GetScreenId`) is
  the object the earlier `BSP_PlaneHudScreen_*` names were given to: its Enter (00608C30) and Exit
  (00605CC0) call `BSP_PlaneHudScreen_EnsureCockpitCamera` / `_EnsureChaseCamera` and
  `BSP_PlaneHudScreen_SelectCamera`. The method names keep the existing `PlaneHudScreen` prefix,
  the slots use the screen's own. The plane HUD screen proper is vtable 00CF4544 at
  [00E198C4]+68h; the effects screen is at +6Ch.
- `BSP_HudPlaneScreen_UpdateInstruments` (00609BD0, RET 0Ch) draws from the shared gameplay RNG
  00BD2F10 (stream 0) in presentation code (docs/CC13_RNG_STREAM_CENSUS.md lists it). Nothing
  here wires it; a host that does must follow the RNG rule.
- The 58h record with vtable 00CF6564 is the air-ops slot record of
  docs/CC13_AIR_OPS_SLOT_GROWTH.md: `BSP_AirOpsSlotRecord_CopyConstruct` (0065CAF0), `_Assign`
  (0065CA50) and `_IsOut` (00658530, observed pointer set and state 3 or 4). It embeds two
  observer refs at +14h and +38h (vtables 00CF6514/00CF652C, copy constructors 00658710/006587C0).
- `BSP_HudSupportManagerScreen_WorldToMap` (00658580) takes the map size from the support-manager
  screen's widget +1C0h through the global, not from ECX; ECX only supplies the bounds
  +460h..+474h.
- 00645160 and 00645180 pass the current player index (game +18ECh) in EDX to
  `BSP_Unit_IsSelectableForControl` (00645060); 00645180 ignores ECX and takes the unit on the
  stack (RET 4), which is why docs/HUD_CENTRAL_UPDATES.md sees it called with a screen in ECX.
- Already reconstructed elsewhere without a ledger name, now named: 00644A60 and 00645710
  (`src/hud_root_rows.cpp`), 0064ABD0 (`ship_screen_flashes_0064abd0`, `src/hud_ship_screen.cpp`).
  Host hooks that the new names now identify: `host.change_page_00622e30` and
  `host.icon_frame_00653200` (src/ingame_gui.cpp, src/menu_screens_2.cpp) have a C++ body in
  `src/band_0060_cc13.cpp`; they are not wired to it.
- The "Befogo" marker (`BefogoMarker_Icon`, 0063E950) is placed by 00640A20 at the
  `BSP_GunBot_InterceptSolution` point: read as the gun lead indicator (docs/AA_LEAD.md lists the
  call site).
