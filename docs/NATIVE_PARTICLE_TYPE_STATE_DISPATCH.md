Known targets require their corresponding bindings. Before dispatch, the host
checks that the selected initializer borrows the same random domain and current
scalar publications. Object, Sprite light and Tracer bindings must also use the
emission caller's actual manager/lock publications and canonical light/scene
domains. Tracer uses the exact canonical generated-model lifetime runtime;
sharing only its scene runtime is insufficient. These checks enforce composition preconditions; they are additional
host checks, not claimed native instructions. Unknown targets still invoke the
required application callback. Callers without the optional binding preserve
their prior current-target callback.

B0CA40's original post-call reloads remain in place. Light population resolves
the already-constructed canonical owner from the same physical light pointer.
The new `adopt_constructed_native_point_light` host operation registers a fresh
constructed slot in its existing scene and backlink domains without allocating
another native slot, calling its native constructor twice or adding a retain.
Its host binding failure cleanup consumes that fresh construction; this does
not establish equivalence with the original FH3 unwind frame.
Environment validation also runs inside this consuming cleanup. The focused
rejection regression verifies that a null predicate returns the retained name,
recycles the identical native slot and leaves no host binding behind.

The worker reports distinguish full source from differential coverage. Sprite
and Object have focused original-byte state/light comparisons. Tracer's full
normal caller still requires real mesh/material, resource and runtime services;
an early stop before an unreconstructed service cannot prove a successful
Tracer attachment. Current virtual overrides always remain real boundaries.
