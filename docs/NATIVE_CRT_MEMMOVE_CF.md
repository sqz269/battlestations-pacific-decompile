# Native CRT memmove CF

This packet reconstructs the complete executable behavior of `_memmove` at `00BF87E0` through `bsp::move_native_crt_bytes_00bf87e0`. The accepted CC dispatcher and aligned engine remain its actual compiled provider. The source uses a new four-argument cdecl interface that borrows the real canonical feature word. It supplies no feature initializer, heap, runtime frame, exception handler, or ownership domain.

The original physical body is `00BF87E0..00BF8B44` inclusive: 869 bytes, classified as 247 instructions occupying 711 bytes, six constant tables occupying 120 bytes, and 38 skipped padding bytes. Fresh bounded BSP byte and listing captures match the installed PE and frozen BY evidence. Every live CLI batch constructs the verified BSP client for project `bsp`, program `/battlestationspacific.exe`, image base `00400000`, language `x86:LE:32:default`; there was no Ghidra mutation. Correct library names `_memmove` and `__VEC_memcpy` are retained.

Frozen provenance is BY commit `ee7a0e08c90e0f20f876f1dc10d64d6fc3bb01f6` (93 local artifacts), accepted CC commit `23028888845db06eb24ff66e0ec30e4751f45337` (65 artifacts), independent CA CC acceptance, and BM's CD proposal/mapping audit. Fresh checkout CRLF versus frozen source LF was identified explicitly; current CC source text, compiled bytes, relocations, and archive membership are checked separately.

The original entry is cdecl `(D,S,uint32_count)` with those arguments at entry ESP+4/+8/+Ch. It saves EBP/EDI/ESI, leaves EBX untouched, returns D in EAX, and uses a plain RET with 12-byte caller cleanup. The new naked MSVC Win32 entry adds `const volatile uint32_t& actual_feature_word_0109eea4` as the fourth argument. Its physical pointer is at entry ESP+10h, hence EBP+14h after the original prolog. Its caller removes 16 bytes. No claim of drop-in native ABI, native code placement, exception/fault-PC identity, or arithmetic-flag identity is made.

At BF8808, only after the original forward direction and unsigned count>=100h decisions, the source loads that fourth pointer into EAX and compares the actual DWORD at that address with zero. This reads neither the fourth pointer nor the feature word on backward or short-forward paths. EAX's previous wrapped S+count value is dead after the direction choice; all subsequent paths overwrite it before a meaningful use or return. The flag must be the actual stable canonical 0109EEA4 word, not a copied Boolean or inferred CPU feature. Its current value is read once at the native gate, before the matching low-four-bit alignment probe. The original hardware/startup setter and its SEH4 predicate remain separately owned evidence.

An eligible nonzero flag plus equal pointer low-four-bit alignments follows the original POP ESI / POP EDI / POP EBP and actual E9 tail transfer to `bsp::copy_native_crt_vector_00c0c82b`. At that point ESP is exactly the new entry ESP. The accepted three-argument provider reads the original D/S/count slots, ignores the fourth word, and RET returns to the original four-argument caller. This is an instruction tail jump, not reliance on C++ tail-call optimization. The emitted relocation, zero addend, actual current provider definition, and unique archive members are verified. Its real recursive call and aligned SSE2 engine remain those of accepted CC.

The complete scalar body preserves the original 32-bit arithmetic, unsigned comparisons, loads, stores, pointer adjustments, unrolled sequences, REP instructions, saves/restores, and returns. It computes wrapped S+count and chooses backward only when unsigned D>S and D<S+count; valid nonwrapping extents support the ordinary overlap claim. No overflow or negative-count rejection is added. Count is an exact uint32_t, not widened host size_t. Zero count returns D without buffer data accesses; equal pointers still take the original copy path.

Forward copying aligns D by one to three byte transfers, performs the original DWORD unroll or REP MOVSD schedule, then zero to three byte transfers.
