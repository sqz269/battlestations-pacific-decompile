# CC16 changed Text failure-origin repair design

Design only; no Source implementation or admission. Baseline is independent review `bf33b8f604df48bc17ea6ac75a3b963a1623d154` of changed Text `96dd22fd0f8b0cbc6ce97b6ed7f69af399993d33`. The four affected cleanup scopes are the parameter helper's narrow header, inner copied wide header, outer localized wide header and outer widened wide header. All four remain unadmitted for unclassified C++ failures. The known ShaderFrame class-key normalization is separate.

**The 96 pair alone cannot establish Native exception origin.** Its current callees expose preparation, phase, entered-call, boundary and retention diagnostics, not transitive proof of the current escaping cause. A guard confined to that pair can retain host/unknown failures, but cannot truthfully supply a positive Native path. The implementation must remain gated wherever the concrete provider cannot meet the evidence contract below. A dormant origin adapter or a public `native=true` flag does not close that gap.

## Selected passive API and placement

Append private metadata to `NativeGuiTextContentStorageScratch` and `NativeGuiTextChangedSourceStorageScratch`. Leave existing `words`, buffer/builder homes, layout Mesh home, outer wide homes and inner-home offsets unchanged; leave ordinary backing and all x87 blocks unchanged. The metadata owns no Native payload/reference and issues no game lifetime credit. The existing actual caller retains the scratch, selected/nested records and full provider graph through entered failure/disposition. Context additionally borrows the qualified own-runtime active-cause reader only after its binding is established; this is a Source EH-domain contract, not another game owner. Contexts remain genuine borrowed contexts; there is no global/TLS last-error cell, registry, new owner or native-memory write.

The following is the selected Source interface shape, not implemented code:

The port has no public operation to assert Native origin. `host` and `unclassified` can only withhold permission. `propagate` accepts only a privately created sealed witness, matches its exact active child edge/cause and cannot manufacture a Native leaf. A mismatched, missing, completed, stale or wrong-stage witness gives no permission; it does not create a new exception, fallback or terminal action. Only audited actual leaf/provider code may issue a Native witness. No such issuer is identified as already implemented by this design. A generic abstract binding, entered scope, profile address, normal-return credit or exception type cannot be made that issuer by declaration.

Private state needs these concrete fields: immutable self/parent invocation identity; each static call site's distinct stable edge identity and expected actual supplier-record identity; active edge; exact active SDK-defined cause key; origin (default unclassified, or known host, or sealed Native); sealed issuer/leaf and nested-witness link; ordinary versus cleanup-secondary escape stage; outgoing receipt; and each header arm's current armed/disarmed/return-entered/returned/return-failed phase. Reached receiver/home identities come only from values the existing body already captured; metadata must not read their Native contents. Fields and witnesses are private and noncopyable; public Acquired booleans cannot mint or replace them.

An actual added check/bind failure is marked host at its real throwing operation; do not derive even that classification from the public last-boundary field. If its exact cause cannot be established, leave it unclassified. Each actual changed-body invocation gets fresh persistent metadata. Distinct static parameter call sites have distinct metadata slots even though Native reuses the SAME physical narrow-header words. Recursive invocations use their own existing caller-retained scratch/records. This models the finite static body, not a new depth, glyph, input or record-exhaustion policy. There is no reset/retry/reuse method. Completed header identities are historical and must never follow a later refill of the same raw words.

The seven `sections_invocation`, `glyph_children_invocation`, `glyph_buffers_frame`, `shader_invocation`, `layout_invocation`, `single_line_frame` and `current_table` methods remain pure metadata. Any escaping error from their additional work is host, never Native. They must not allocate, perform Native work, reenter, read Native operands or change FP state. The other seventeen required binding methods receive a per-call port: `localise_00a9fad0`, `geometry_00b74640`, `section_00b732c0`, `shader_00b19210`, `parameter2_00b18b00`, `parameter4_00b18aa0`, `parameter1_00b18b20`, `clip_00aa9f10`, `wrapped_00aba270`, `text_current50`, `vertex_00b73bb0`, `index_00b73b70`, `texture_00b189f0`, `diffuse_00b179f0`, `model_current2c`, `parent_00b6e680`, `root_00b6d890`. There are no derived implementations of `NativeGuiTextChangedStorageBindings` in the scoped current Source search, so this does not claim a real producer already supplies the port.

## Exact cause and witness rules

1. Before a call, private glue binds a fresh edge to the current invocation, static Native site, SAME selected callee record and existing captured identities. This is passive bookkeeping. Entering that edge grants no cleanup permission.
2. At an escape, obtain the active cause key inside the current supported catch through the qualified SDK reader; do not call `std::current_exception()` for identity or add another snapshot. Host-only work records host. An existing modeled supplier may forward only its own currently escaping sealed receipt. Anything without that evidence stays unclassified. Do not wrap/translate the exception or guess from `bad_alloc`, SDK status, diagnostic message or public `provider_call`.
3. Positive evidence must originate at an audited actual operation that can distinguish its genuine modeled escape from every added admission/bind/preparation failure. At a required external provider, this requires its concrete genuine implementation/leaf record, or a separately established prevalidated path with no added host escape. Merely marking the boundary before calling an arbitrary callback is not evidence. Local host checks, registry operations and model/Text companion birth never become Native by being nested in a modeled function.
4. A parent adopts a child witness only when exact exception identity, active caller edge, expected child invocation/record, site, issuer, stage and nested-chain identities all match. The trusted glue verifies the relationship; no mutable public field supplies a Native flag. Repeated references to the same exception object on a later sibling still fail the operation-identity match. Reentry/sibling replacement cannot replace the active child link.
5. Propagate the SAME cause through `parameter -> inner -> outer` with `throw;`. A native primary may legitimately authorize several different armed parent scopes along the observed EH chain. Therefore permission is consumed per header arm, not globally per exception. A normal return carries no escaping-cause permission, even if a nested historical failure record exists.
6. If a callback replaces the cause, the old witness cannot match the new active-cause key. If a callback swallows a child escape and returns, that historical receipt grants no later permission. Completed records cannot be reset/promoted to authorize a later throw of the same actual exception object.

`std::exception_ptr` is diagnostic only: on the installed MSVC it may contain a copied exception or copy/allocation failure rather than the active cause, and its capture is not passive. Existing diagnostic fields remain qualified; the channel adds no such capture/copy. The active key borrows identity only while the corresponding original object is live in the SDK catch/rethrow chain; it neither owns nor dereferences that payload. Historical keys become nonauthoritative when that active chain ends. Retain failed records until caller disposition and never reuse their invocation identities. No new Native owner, retain, implicit cleanup, mutex, allocation registry, type wrapper or process-retention destructor is introduced. Internal port comparisons may be `noexcept` only after they are proven passive; do not put an unproved SDK reader, Native/provider/pool or cleanup call behind a new `noexcept` wrapper.

## Active-cause identity: pinned MSVC 14.51 own-runtime candidate

`std::exception_ptr` equality is rejected as the identity mechanism. Installed `14.51.36231` `crt/src/stl/excptptr.cpp:312..351` allocates a new control block and copies the thrown object; allocation failure substitutes `bad_alloc`, and copy failure can substitute another exception. Lines 433..436 compare shared-record identities; lines 448..461 perform a fresh capture. The snapshot can therefore differ on repeated reads of the SAME active exception and can run an exception copy constructor. Reusing these snapshots as passive identity would be false.

The bounded SDK source check establishes a conditional own-runtime alternative without invented layout:

- Existing SDK `crt/src/vcruntime/trnsctrl.h:217` declares `__current_exception`; its own line 239 uses that accessor to obtain the current `EHExceptionRecord`. `ehhelpers.cpp:113..115` returns the runtime's current-record slot. Use that exact SDK declaration/definition contract, not a handwritten prototype, ordinal lookup, numeric code cast, vendor-body replacement or copied private offsets.
- Existing `include/ehdata.h:483..510` defines `EHExceptionRecord`, `PER_PEXCEPTOBJ` and `PER_PTHROW`; the former is the actual thrown-object pointer. `ehdata_forceinclude.h:24..38` selects the nonrelative x86 definitions. Read the actual SDK-defined fields; the EH-record ADDRESS is not the cause key.
- The nonrelative/x86 catch path in `frame.cpp:1696..1706` registers the object and installs the current exception; lines 553..563 resolve ordinary `throw;` through the saved current exception. `frame.cpp:1751..1759` skips object destruction on rethrow. `i386/trnsctrl.cpp:750..767` and `ehhelpers.cpp:277..287` retain/check that object across nested catches. Thus a same-runtime ordinary rethrow can be compared using runtime-domain identity plus the actual object pointer, with the SDK throw-info pointer as corroborating metadata. Type is never an origin classifier.
- Object identity is borrowed only during the supported active catch/rethrow chain. Capture it before any diagnostic work; use `throw;` and no new exception wrapper/copy. After final catch consumption/destruction the pointer is historical only. Active call-edge/issuer/stage matching is still required to reject sibling reuse, replacement and cleanup-secondary escapes.

This is a static SDK-source candidate, **not an implemented/linked/fixture-proved reader**. Restrict any eventual reader contract to the selected MSVC 14.51 own Source runtime/domain and established active native-C++ catch. The accessor calls `__vcrt_getptd`; `per_thread_data.cpp:117..119` returns existing PTD, but lines 161..166 abort if unavailable, and earlier code may allocate new PTD. The actual catch path already installed its own PTD; using a different/unknown CRT instance merely to look for a match is not safe. Root must establish the SDK header/link/runtime-instance contract before any such query. There is no general nonthrow promise or added terminal policy. Foreign/managed/SEH/transformed/cross-runtime causes without this contract remain unclassified, with no new Native-input rejection.

The required Source reader API is a borrowed `NativeGuiTextActiveCauseReader` returning a privately constructed `NativeGuiTextActiveCauseKey` for the current supported catch. Its exact implementation/admission is gated until the above SDK declaration, object lifetime and same-runtime linkage are honored. Only passive key comparisons—not an arbitrary SDK/provider call—are inside the port's `noexcept` methods. Runtime/header/link validation remains outstanding; this does not establish Original game CRT/FH3/SEH/ABI identity or create any Native-origin witness by itself.

A per-current-call-edge rethrow-only control-flow seal is an alternative only if every intervening exit, destructor, metadata operation and secondary escape is audited not to replace the cause. That proof is not present in today's six suppliers, so this design does not use lineage alone as a shortcut. If neither actual SDK reader nor that stronger lineage contract is established, the path stays unclassified and 96 stays unadmitted.

## Four cleanup scopes and ordinary-return schedule

| Scope | Original arming epoch | Existing raw action if the current primary is proven Native | Host/unclassified escape |
| --- | --- | --- | --- |
| Parameter narrow header; inner states 1..9 | After each successful `41E870`; same `words+4` backing, distinct site metadata | Consume that narrow arm, call raw `41DD20` once, then propagate the SAME cause if it returns | No narrow return; retain its header/records/whole graph |
| Inner copied wide header; state 0 | After successful `4C8DD0` | Consume inner arm, call raw `436430(words+2)` once, then propagate SAME cause | No wide return; retain copied header and graph |
| Outer localized header; state 0 | After the two Native zero writes and before `A9FAD0` | Consume localized arm, call raw `436430(wide_headers)` once | No wide return; retain actual localized header and graph |
| Outer widened header; state 1 | Only after successful `4C5E60` | Consume widened arm, call raw `436430(wide_headers+2)` once | No wide return; retain actual widened header and graph |

Normal return keeps Native's explicit disarm BEFORE the raw return/getter. A failure from that normal-return call is a new primary call escape for any still-armed parent scope, not permission to replay the just-disarmed header action. The widened constructor can fail before its own outer arm; `AB8530` can fail before the inner copy while an outer arm is already active. Passive outgoing publication must therefore cover the whole inner and outer entry, including these pre-arm and post-normal-return operations, rather than only the existing catch regions.

The generic parameter helper needs a compile-time caller-site identifier and the corresponding fresh port/arm slot at each of its nine existing Native sites. This does not copy a header or change the material/value/name arguments. Keep existing code outside this exception/call seam byte-identical: all raw operand reads/stores, current getters, flag/height/home reuse, 2 x87 blocks, wrapped branch and distinct current50 epochs. No callback or witness query may be inserted while new ST0 is live.

## Secondary cleanup exceptions

Before the raw unwind action, mark only that arm return-entered/consumed; retain the triggering receipt. If the action returns, record returned and rethrow the original active cause unchanged. If it throws, read the new active-cause key in a DISTINCT cleanup-call node, preserve the trigger as diagnostic history and publish the new cause. Never borrow the trigger's Native permission or its child witness for that replacement, even if the exception type or object pointer happens to match.

Origin and EH transport permission are separate. A newly proven Native-origin exception from a cleanup action still does not prove Original FH3 secondary-unwind behavior. That continuation is currently unproved and cannot inherit ordinary-primary permission for another parent cleanup. Record it as cleanup-secondary with unproved transport; preserve ordinary Source propagation and retain unresolved records without adding `terminate`, `noexcept`, retry or rollback. Only separately established Native secondary-transport evidence could admit a more specific continuation. This design does not claim to recover that Native policy.

## Bounded implementation and validation proposal

The smallest local Source proposal, after the reader contract is approved, is the existing changed header/CPP plus one new implementation evidence document/report: private appended scratch state, seven host-only metadata seams, seventeen per-call borrowed ports, four guarded catches, passive outgoing propagation and exact arm/secondary state. It is incomplete for Native admission until the exact upstream receipts above are genuinely supplied. Do not publish that local transport as full changed Text or child-producer readiness. A useful first coupled slice is the actual `AB8530` host-admission escape before inner copy propagating to the armed outer scope; its real Frame and changed caller must agree, with unknown nested Native paths still gated. No new Native body is needed for this slice.

Validation when Root authorizes Source is finite:

1. Compare exact Source outside the origin/catch/call seam and existing scratch prefixes; keep all raw homes, reloads, 81 original call-site meanings, 8 x87 forms/2 blocks and literal/EH evidence unchanged. Check that no new port/metadata operation reads Native operands or runs while ST0 is live.
2. Audit each actual private issuer/forwarder against its genuine body. Require an exact current cause and expected caller/callee edge; reject inference from `provider_call`, phase, exception class or prior normal credit. No fixture-generated Native flag counts as this proof.
3. Use at most one focused Source cause-routing check for the concrete risk: added host admission inside an armed outer scope returns no header; missing evidence stays retained; the SAME exception object from a stale sibling/reentry cannot authorize cleanup; and a cleanup replacement cause does not inherit the trigger's permit. Test-private metadata fixtures, if needed, prove routing only, never Native origin. A positive Native cleanup check requires an actually audited genuine issuer, otherwise that case remains blocked rather than faked.
4. Root performs the normal common Win32 build/checks after coupled Source review. No build/runtime/ABI claim follows from this design, existing Source28 or the negative metadata check. No broad test suite, standalone probe or game process is proposed.

Only the two new design artifacts are changed. All prior Source and evidence remain byte-identical. No CMake/application/owner/ledger/Ghidra write, build, test, probe, game or process-control action occurred. Native exception-origin closure, genuine actual providers, wrapped recursion, Original ABI/FH3/SEH/secondary proof and whole frontend readiness remain false.
