# cc13-fe11: last open tactical library, preview and HUD map bodies

Continuation of cc13-fe9 / cc13-fe9c (docs/CC13_FE_9.md, docs/CC13_FE_9C.md). Segment 12/17 code is in
`src/frontend_seg12_17_cc13.cpp` / `include/bsp/frontend_seg12_17_cc13.hpp` (namespace
`bsp::cc13_fe3`, section "packet cc13-fe11"). Every routine below is *reconstructed* and
*build-tested*; none is ABI-compatible, fixture-tested or game-validated. Evidence: disasm-raw listing
(stack offsets tracked by hand from the prologue; every reg-reg x87 operation in 00503510 and
00515050 was checked against its bytes, including the DC C9 `fmul st(1), st(0)` at 0050389C and the
DE F1 / DE FA / DE EA pops), live decompile for structure, strings and constants from the image.
Call rows: `reports/cc13_fe11_calls.json` (verified with `tools/verify_report_calls.py`).

## Segment 12/17

- 004FF6F0 ShowDifficultySelect: three rows "FE.easy" / "FE.normal" / "FE.hard" cloned from +0B0h,
  each given the pair (0.5, 0.5) through vtable +30h; the result of 00AA6750 on the list is
  overwritten by that pair before anything reads it. The second row sets +100h after its insert, the
  other two before. The profile difficulty `[[00E188A8]+6ACh]` is selected last.
- 00503510 FrontEndPreview_Draw: the eye is `(v, v/3 + d, 0, 1) * RotY(-t/3)` divided by w, with
  v = `[00E084F8]` (copied to +7Ch every frame), d = 50 when the non-ship byte +4CCh is set (005072C0
  sets it) and
  t = `[[00E188A8]+64Ch]`; it looks at (0, d, 0). The two anchor widgets +574h / +578h are projected with
  the GUI camera `[[[+4DCh]+0F0h]+18h]`, and the model is shifted so the target sits under their screen
  midpoint: the midpoint at the target's depth is unprojected with the inverse projection and the view
  becomes `LookAt * Translation(Qx/w, Qy/w, 0)`. Rotor nodes (+428h vector) spin as
  `RotZ(-2t) * Translation(local position)`. A viewport/display size mismatch rebuilds the environment
  (00502480), the HDR block (the same nine values as 00504130's) and four "ColourRemap.tga" remap
  slots.
- 00506660 BuildOrderOfBattleList: rows are grouped by record +28h in the order type 2, type 3,
  type 1; group headers +128h / +12Ch / +130h sit at their first row's "MenuItem_Text" position minus
  (0.03, 0.055, 0).
- 0050E3C0 OpenEntryAsUnlocks, `(screen, data, side, unused)`, RET 0Ch: the second argument the
  callers pass (+0A0h) is a side index, used as `data + side*154h` and compared with the class rows'
  Race flag (`Race == 1 || Race == 4`). The per-mode string vector is chosen by jump table 0050EF40;
  in game mode 4 the list collapses to the first class of the type picked by `[00E1956C]`. Matching
  class rows are consumed (id and flag -10, type "0_0_0") so each row lands in at most one record.
- 0050EF80 OpenEntryAsOrderOfBattle, `(screen, data, side)`, RET 8 (two arguments, not three): builds
  +45Ch from the side block's unlock list (E+160h pairs, counts E+170h, texts E+180h; locked entries get
  count -1 and go last) and the change list (E+130h / E+140h, "fixed" or "change"). Here the related
  rows are not consumed, and a row never lists its own id.
- 00515050 (ledger name UpdateTutorialMovie): the body is the carousel animation step. The position
  moves by `2*rate*(target - position)`; the fractional part f places and scales the three cards; kinds
  0 and 3 drive the arrow widgets, kind 4 the three tutorial movie slots.

## Preview model loaded (005072C0)

`__thiscall(screen, resource, job)`, RET 8. The job is a 60h preview model (004FCFC0): +4h refcount,
+8h mesh name, +10h resource, +14h part instance, +18h mode, +1Ch class, +20h..+5Ch a placement
matrix. Findings beyond the cc13-fe9 structure notes:

- +4CCh is a *non-ship* flag: set when VehicleClass[class].Type is none of MotherShip, BattleShip,
  Cruiser, Cargo, Destroyer, TorpedoBoat, LandingShip, Submarine (log "Ship" / "NotShip!"). A
  non-ship is lifted by 50 (job +54h is the matrix translation y), centred on its bounds in x and z,
  and framed at three times its bounds radius (ships 1.5 times) unless the class sets
  UnitlibViewDistance; the result also goes to `[00E084F8]`, the distance 00503510 reads.
- Turrets are not built inline as in the in-game unit library (00680DB0): each Platforms entry queues a
  second job with mode 1 and placement `RotY(-yaw) * basis`; when that model arrives the same callback
  parents it under the vehicle root and hides the vehicle's "underwater" nodes. Only the yaw is used;
  the vertical window pair is read and dropped, and no "barrel" node is touched.
- The selected text of the HUD list `[[00E198AC]+70h]+0B8h` is passed to atol and the result is
  discarded; an empty-name descendant collection is walked with bounds checks only.
- Every mode ends by applying job +20h to the root, storing the job in +5C4h, dropping the callback's
  reference, setting the vehicle's "gun" effect colour to (0.5, 0.5, 0.5, 1.0) through 00B85200
  (provisional name), hiding "belsocockpit" and showing "kulsocockpit".

## HUD map register (005AB190), range by range

`src/frontend_screens_cc13.cpp` / `include/bsp/frontend_screens_cc13.hpp` (namespace
`bsp::cc13_fe1`). Each range is its own function and its own fragment record (address 005AB190, the
range in the record).

- 005AB190..005AB519 `hud_map_register_setup_005ab190`: the zoom levels come from the world bounds:
  the larger of the x span / 0.75 and the z span, times 1.1, picks the coarsest level (2 up to 8000,
  1 up to 25000, else 0) and rewrites the extent table 00E0CF40 for the levels at and below it (the
  defaults 48000 / 18000 / 8000 / 3000 stay in the others). The scale table 00F89AE4 is the crossfade
  table 00E0CF50 times extent / extent[3]. The 0.75 constant stays on the x87 stack from the first
  division to the `+34h` product (DC F9 / DC CA forms checked against the bytes).
- 005AB519..005AB7C5 `hud_map_register_objects_005ab519`: the terrain objects of
  `[[00E188A8]+19CCh]+34Ch` (log "Terrain child %s") are instantiated from their +424h model name,
  placed with their cached world matrix (+0CCh, rebuilt from +74h and the parent pose when +0C8h is
  clear), and kept in +510h (roots), +500h (the vtable +10h(6, 0) sub-node) and the list +498h
  (instances).
- 005AB7C5..005AC390 `hud_map_register_quads_005ab7c5`: fourteen map quads (table `kHudMapQuads`;
  arguments recovered with `local/fe11_quads.py`, which runs the x87 tracer from the range start and
  reads the pushes from the dump). The bordergrid and border quads bind "cLength" / "cOffset" to the
  world span +55Ch and the negated centre +564h. Two 61h-dword arrays (+130h, +2B4h) are cleared.
