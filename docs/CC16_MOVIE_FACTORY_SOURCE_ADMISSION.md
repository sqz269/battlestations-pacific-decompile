# Movie factory source and publication admission

This batch registers the real Bink module owner in `bsp_core` and the staged
movie factory adapter in `bsp_game`. It also admits one permanent typed factory
publication cell from the same process that owns the existing singleton manager
cell. No factory is constructed and no Bink import is called by this admission.
Subtitle playback remains OFF; the accuracy guard retains its prior setting.

The primary inspected the complete module/factory implementations, their
required interfaces, publication changes and independent reviews. The exact
source/review commits, file hashes, combined build and link receipts are in
[the admission report](../reports/cc16_movie_factory_source_admission.json).
These are new C++ ownership interfaces, with zero new native-body/vendor credit.

## Source contracts

The module resolves all thirteen real named exports before publishing stable
borrowed tables. Its completed module member releases an unescaped load after
lookup failure. The sound callback returns a function pointer; its older
header evidence is qualified separately from installed export metadata.
Actual loaded identity, runtime ABI and callback/handle quiescence remain gates.

The factory adapter owns separate metadata and requires the actual four-byte
receiver allocation, matched free, retained module/tables, supported original
data and the same manager/publication cells. It preserves captured-section and
second-getter-before-current-publication ordering. The ordinary Bink setup
status is ignored, as in the original caller.

Constructor C++ exceptions free only the captured raw allocation. Reached
publication/registry effects can dangle. Normal deletion unregisters the current
publication but frees/returns the captured incoming allocation, conditional on
flags bit zero. Retirement exceptions gain no extra clear/free. The metadata
destructor invokes no native cleanup. Root must enforce serialized nonreentrant
use and whole-aggregate terminal custody; the entry guards do not prove arbitrary
reentrancy, synchronization or an irreversible latch outside that contract.

The publication accessor forwards directly to one appended zero-initialized
cell in permanently retained `GameNativeStringProcess`. Existing fields retain
their order; `GameSingletonHost` gains no data member. The original PE proves
the native cell's loader-zero initialization. This is typed source authority,
not a literal fixed-address `F8AEFC` mapping or original binary ABI.
