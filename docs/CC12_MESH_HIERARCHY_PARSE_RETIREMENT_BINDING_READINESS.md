**Channel publication is conditional on a recognized `AnimationKey` child.** `B8AAD0` allocates the channel, reads its name/two DWORDs and determines the eleven-name index. Each recognized key is read/appended, then `B771C0` stores the channel into the captured group's indexed slot and updates the group scalar. A keyless channel is not automatically published; an unknown name retains index `FFFFFFFF`, and a channel before a group retains its null group. No application fallback, prevalidated group/index, end-of-reader publication, implicit AddRef or channel-allocation rollback may replace that schedule.

`NativeAnimationDeleteCalls` is a real finite group/channel deletion provider. AnimationChannels destroys captured groups with direct slot4 flags1, and groups likewise destroy captured channels with flags1. Each captured pointer cell is cleared only after deletion returns, then the current count is reloaded. These nested calls do not decrement group/channel references first. A throwing scalar destructor skips its outer free; native partial destruction and unwind actions are retained without replay.

## Hierarchy, cache and resource ownership

`B7F100` traverses `Item` children through `B7EB90`. Each item allocates an actual 88h pool slot, initializes only the recovered 84h payload fields, and appends the raw record to the **current manager+24 resource only after its fields finish**. The matrix and pool marker retain their existing semantics. Ordinary failure cleanup covers active child/name temporaries; unpublished record/field allocations are not reclaimed. An application wrapper cannot own those partial allocations retroactively or use a generic destructor to roll them back.

The genuine production caller is `B7F430`, whose current renderer slot50 runs before control/tag traversal and slot54 only after normal completion. Its `Resource` branch uses current parser slot8 and current resource slotC; `Hierarchy` reaches `B7F100`; `BoundingBox` writes the current resource. No application Source presently supplies that complete dispatch. Default hooks and base append bodies exist, but using them as generic fallbacks would replace game classification and unknown concrete parsers.

`B80720` has distinct publication branches that must remain intact:

1. It stores manager+20 factory before lookup. A cache hit publishes manager+24, atomically retains that resource and returns current+24 while leaving the factory word intact.
2. A miss reads the actual allocation-statistics target, calls current factory slot4 and immediately publishes the returned resource at manager+24, **before** name resolution/open/read/parse. A later exception does not undo that publication.
3. After root dispatch, it reloads manager+24, constructs a cache pair with the original name and attempts unique insertion. It ignores the insertion result; there is no invented success gate. It returns temporary names, clears factory+20 and writes wrapping starting-minus-ending metric to current resource+40 before root/reader/name cleanup and return.

Cache nodes and pairs borrow the resource pointer; insertion, cache erase and `B806F0/B80F10` manager teardown do not release it. `B801C0` erases by name without a resource-pointer identity check. A new cache, an RAII resource hidden behind the borrowed entry, or an unconditional replacement on insertion failure would change this ownership.

`NativeResourceContainerReferences` already supplies genuine base/game/fallback terminals and binds its lifetime context's item dispatch back through itself. `B88430` first decrements each current primary item and dispatches current slot0 at zero, then invokes `004C1400` and erases the resource's name, destroys each nonnull hierarchy payload and returns its captured slot to the same `0109022C` pool, frees the arrays and returns the name. It adds no pointer resets, retry or rollback. Its exception states free the remaining array/name/base members, not all unreached pointees. `718810` frees its three borrowed classification arrays before base destruction; those arrays do not release their items.

This still needs the complete actually reached item-reference chain. Camera/GroupParams and extra-item adapters exist. Mesh-item deletion must use the renderer's actual owner/geometry domain, and mesh loading requires that same geometry, material destruction/effect cache, texture-field loading, lighting, generators, metadata reads, mapped profiles and retained acquisition frames. The accepted type/fallback services do not close these loading/lifetime edges and must not be replaced with a new counter or copied descriptors.

## Physical shutdown and failure admission

The current normal shutdown keeps VFS, raw strings, resource publication/context metadata and renderer services alive through `GameSingletonHost::shutdown()`. It calls raw singleton drain first, retires the VFS runtime afterward, then frees/nulls the lifetime manager. `GameStartupHost` later deletes the singleton host and renderer before deleting its VFS host; the resource application's destructor therefore must remain metadata-only and avoid the already-destroyed singleton host. The canonical read-only owner remains mapped through process teardown. Process hierarchy cleanup `CE0ED0` later destroys the canonical pool storage through its registered CRT callback; a nonzero registration result is not evidence that construction failed.

Every actual resource/item/hierarchy payload borrower must complete native retirement before the shared drain and before the pool's CRT cleanup. The manager's borrowed cache does not supply that obligation. Calling a resource destructor after drain could reach its real `004C1400` getter and recreate a manager against a retired domain. Merely retaining C++ metadata until `delete vfs_` does not make this safe.

`GameVfsHost::invoke_native` latches `native_operation_failed_`; the startup host checks this and uses `_Exit`, preserving the graph without running native CRT cleanup. `requires_process_retention()` currently observes that latch and an open title-fileblock frame, not arbitrary external parser/acquisition frames. Direct use of a returned hierarchy/reader reference does not automatically latch it. A future invocation API must install its actual retained frame before calling native-semantic work, propagate interruption through this policy and prohibit replay. A failed `NativeResourceLoadCacheAcquired` also retains its nested name-resolution frame as required; ordinary local cleanup does not undo resource/cache publication or all parser allocations.
