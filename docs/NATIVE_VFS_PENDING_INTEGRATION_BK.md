# Native VFS pending integration

The rebuilt frame host now executes BDB0B0 against the current VFS publication,
matching the load at737B79 and call at737B7F. It walks the actual live mount tree
and dispatches each current provider+28 slot. Repeated providers and callback
changes to the tree are observable. Loading-manager getter4FDE20 followed by
update509190 remains an explicit unresolved production boundary.

NativeVfsLookupRouteContext now binds D68478 alongside the existing exists,
name-probe and device visitors. The existing BDD0A0 traversal routes current
BDC1E0 visit and BDC1D0 stop entries through the actual pending visitor. BDDA10
passes the original second name to traversal and preserves both owned visitor
names, callback DWORD, flags and raw acceptance byte.

NativeVfsRuntimeBindings consumes captured provider entries. Physical BF43B0 and
BF46B0 use real overlapped/unbuffered Win32 reads and actual provider+14h records.
FileStore BE7CB0/BE7CC0, MPKG BB9D30/BB9D40 and MPAK BB79E0/BB79F0 use their
verified rejecting/no-op native defaults. The six newly verified MPKG leaf bytes
are XOR AL,AL/RET10h and RET. Unknown current entries remain source errors.

The physical completion bridge admits BE7B20 and routes it through the current
FileStore factory/cache and complete BE78B0/AddFile source. The optional final
FileStore callback dispatcher remains borrowed. Production does not supply the
unreconstructed loading-manager callback; no callback address is treated as
host-callable code. The separately callable request composition requires both
a bound final dispatcher and an existing current FileStore provider.

RequestFile publishes a stable acquired frame before entry. Its nested BDF4C0
resolver publishes a second acquired frame borrowing the request's mutable
header. A normal result releases both; an interrupted call retains them together,
including the original name and contexts. The production GameVfsHost latches
native pump exceptions and reaches its existing process-retention exit before
the shared singleton drain. No retry or speculative cleanup is added.

The old projected pending callback/report interfaces now explicitly report
ERROR_NOT_SUPPORTED when given a native context. Their empty projected mount
list can no longer silently report a successful pump. Production uses the actual
runtime method directly, without constructing projected providers.

Independent review corrected missing archive leaf dispatch and the per-frame
publication reload. Four integration translation units and the new completion
and pending-route units passed strict MSVC Win32 compilation before the combined
build. Exact final build, fixture and bounded mission observations belong to
`reports/native_vfs_pending_integration_bk.json`.

The initial mission baseline at f41379f3 loaded USN01 and ran120 mission frames,
240 fixed steps and one scripted movement order. That run still logged the VFS
pump as unimplemented. The final report distinguishes it from the new pump run.
The rebuild uses the already selected private GFWL DLLs; the installed game,
options and saves are preserved and compared by the bounded runner.

The restarted Ghidra bridge initially rejected run_script_inline. Existing normal
metadata endpoints subsequently repaired the physical submission/completion body
membership gaps, preserving previous names, comments and default labels, and
recording the ABI evidence and preimages. All238 submission instructions and106
reachable pump instructions were verified; the unreachable3-byte alignment LEA
at BF46CD remains outside the function. All36 physical direct-call rows then
passed. `reports/native_physical_pending_flow_bk.json` preserves that repair;
the earlier script rejection remains recorded separately.

These changes do not establish full native ABI/FH3 parity, arbitrary archive
payload loading, asynchronous gameplay loading or game fidelity. The original
physical ReadFile failure's aligned-pointer free and leaked OVERLAPPED remain
documented native behavior, not newly invented ownership cleanup.
