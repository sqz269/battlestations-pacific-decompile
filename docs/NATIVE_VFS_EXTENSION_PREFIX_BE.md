# Native VFS extension-prefix registration (BE)

`register_native_vfs_extension_prefix_00be1480` writes the actual A0h manager's `+54` 20h-node red-black tree constructed by `00BE1DC0`. The caller supplies actual eight-byte extension and directory pooled string headers, the same `ActualNativeStringPoolStorage` used by the manager, and the established returning invalid-parameter callbacks. The separate `+60` search-group list is untouched.

`00BE1480` captures the tree head, then calls `00BDC3F0` to check for a duplicate pair. That helper copies **directory first, extension second**, lowercases extension then directory, changes directory backslashes to slashes and appends a trailing slash. It computes extension upper bound before lower bound, walks `[lower,upper)` and compares each node's directory with equal counted length plus case-insensitive string equality. Thus two rows with the same extension and different directories remain distinct; an equal normalized pair skips all insertion and additional temporary construction. The source uses the established physical-index lower-bound and iterator-advance functions for the same 20h tree shape and an explicit upper-bound traversal.

On a missing pair, `00BDCBB0` constructs the new 10h pair in **extension then directory** order. The wrapper lowercases both, slash-normalizes/trails directory, then `00BDCEA0` copies that pair into another 10h temporary. `00BE0B90` descends by extension only: smaller goes left and equal-or-greater goes right. Its `00BE0370` path allocates a 20h node, copies two actual pooled headers at `+C` and `+14`, writes color `+1C` and nil `+1D`, increments tree count, links against the current head, and repairs RB color/rotations. The source reuses `detail/native_tree_insert_storage.hpp` and the existing physical-index rotations. Its count check is the original `00BE0370` unsigned `count > 0FFFFFFDh` predicate. The copied pair is destroyed directory then extension, followed by the original normalized pair; the duplicate-check temporary instead releases extension then directory because it was constructed in the opposite order.

Native ABI: ECX manager, stack(extension,directory), RET8, no specified result. The C++ source interface has explicit string-storage and validation dependencies; it is not a binary ABI or FH3/SEH substitute. Program `/battlestationspacific.exe` was verified before live reads. Disk/live bytes and saved assembly match for `[00BE1480,00BE159E)` (286 bytes). Capstone decoding is contiguous and all 85 saved instructions belong to `BE1480`; no root ownership gap was found. The report verifies all 10 direct CALLs in the body and 13 direct `00738360` caller sites by their saved owners. Reached helper bodies `BDC3F0`, `BDCBB0`, `BDCEA0`, `BE0B90`, `BE0370` and `BDF700` were inspected as contracts, not claimed as independent fully reconstructed roots.

The native directory last-byte check is unsafe for an empty directory. This source covers valid nonempty startup directories and an initialized actual manager/tree; it does not fabricate empty behavior, original CRT exception identity, or success for malformed storage. The full `00738360` literal registration schedule, current provider selection, `GameVfsHost` migration and game execution remain separate. A source build establishes only compilation and existing CTest compatibility.
