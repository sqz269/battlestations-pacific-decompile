# Actual GUI effect production application

`GameNativeGuiEffectApplication` supplies a genuine numeric renderer material-
effect production graph over the application's existing renderer and VFS. It
composes the established actual compiler, native descriptor/VFS/state children,
program loading, effect loading and owning effect-cache acquisition. It creates
no semantic shader or material wrapper and no second registry or allocator.

## Concrete graph

The component borrows `GameNativeRendererApplication::material_compiler_owners`,
`material_compiler_sources`, `material_effect_owners`, `shader_descriptor_reader`,
`shader_cache_context` and `texture_cache`. A new ready-only
`effect_registry_domain()` getter exposes the renderer's existing
`NativeEffectRegistryDestructionContext`, including its exact record string and
array services and original numeric profile tables. Borrowing performs no load
or cache mutation.

The owned composition is:

1. `NativeMaterialProgramCompilerActualContext` and its established B3B3C0 tail,
   using the same process shader-mode/cache cells and actual pass/shader/state
   construction and registration domains.
2. `NativeMaterialEffectCompilerBinding` for B3C3A0, followed by
   `NativeMaterialEffectNativeChildren` using genuine B43B00, BDF4C0 and native
   state-cache operations.
3. `NativeMaterialEffectProgramsContext`, with numeric secondary-pass construction
   and the existing same-domain effect lifetime.
4. Mutually bound `NativeMaterialEffectLoadingContext` and
   `NativeMaterialEffectCacheContext`, using the actual VFS name/date routes and
   renderer record allocation/retirement domain.

No unknown scalar, sampled stack residue, imported native callable, or empty
success provider is synthesized. The `.mshd` to `.shfx` rewrite and cache alias
searches execute the existing B2EBB0/B31090 implementation.

## Caller prerequisites

Construct with the genuine ready renderer, VFS and
`GameNativeGuiEffectApplicationBindings`. The binding contains two distinct real
`NativeMaterialDescriptorSamplersContext` objects for the root and mode calls,
plus the actual mutable material-manager publication F8BBF0.

Both sampler contexts must borrow the same renderer pass lifetime, real pooled
strings, VFS dates and actual manager/loader publication cells. Their cache,
factory/registry, platform/message preimage, stack-knowledge and applicable
entry/release evidence must be genuine. The constructor does not create that
missing sampler parent service. Existing B3B280 helpers reject consumption of
unknown B-16 data; this composition neither supplies zeros nor recovers new
register/x87/control-flow evidence. Context/evidence updates are permitted only
under external quiescence and must be valid for every reached invocation.

F8BBF0 remains a required actual owner/global supplied by its real parent. The
native B45EE0 load samples its current byte +0E at the established call site;
this component does not allocate an invented manager or choose a policy default.

## Acquisitions and failure

`acquire_effect_00b318b0(stable_actual_name_header)` requires a live initialized
actual eight-byte string header. The caller keeps that header and its storage
valid through any retained failure. Before entering native work, the component
publishes a persistent operation, captures the current actual renderer and calls
the original fixed `0/1/1` B318B0 cache route. No extra retain is inserted.

A nonnull result must resolve through the same actual registry to an existing
`NativeMaterialEffectReference` whose storage and raw +04 atomic are identical.
Its original base/derived profile and live count are logged. A native null is
preserved; it is not a successful unavailable-child default. A normal return
transfers the actual caller-owned reference. The recorded result is thereafter
an opaque diagnostic identity, never another owning slot. If validation or
logging fails after acquisition, the still-unreturned actual reference and cache
frame remain inspectable in the failed operation.

An entered exception latches the application and retains the nested compiler,
loading and cache frames. Reentry, replay, reopening and retargeting are rejected.
The component never rolls back an entered native operation or destructs a failed
graph. Its caller must retain it with the application's process-retention exit
policy, together with the actual renderer/VFS and sampler services.

The acquired effect and cache record follow their existing actual reference
retirement paths. Completed effect owner records retain their genuine program
and descriptor bindings until original effect destruction. Therefore this graph
must remain alive through native renderer cache/effect retirement. After the
successful renderer drain, call `after_native_renderer_drain()`; it verifies the
same renderer's established owner/worker closure and permits metadata destruction.
It does not clear the cache, release caller references, or invent another teardown
order. A graph that never entered an acquisition can be discarded directly.

passes both existing CTest checks (12.26 seconds) and includes the renderer getter.
The new source is separately compiled until primary-owned CMake registration and
combined linkage. No new test framework or Ghidra mutation was introduced.

The primary's independent live font probe on checkout `40fd4eebe` passed with six
fonts, 1,060 glyphs and three actual D61948 images. Native owned-slot counts retired
exactly; one lazy fallback owner survived. Manifest SHA256:
`14b700643b37e12c0f17d18db544bc5ed29bb3f6302c6f08306607f040bef91e`.
This is resource/cleanup evidence for the font producer, not execution evidence
for this effect graph or native Text rendering.

The exact remaining consumer attachment is the font-shader/material factory
transport: route `GuiTextShaderServices` and native material creation to this
genuine numeric effect producer using persistent acquisition state. Current
AB8CE0 and callable-renderer material factory interfaces cannot call original
numeric table entries as host code. A canonical GUI page/widget/model owner must
also supply the same actual Text factory and material parameter-source lifetimes;
the current frontend's diagnostic IDs and scratch Text runs do not do so.

Real root/mode sampler parents and F8BBF0 publication, the consumer attachment,
and a subsequent actual effect/draw run remain required. The component is not
activated in the sprite frontend and does not export or replace production fonts.
Original register/string/tree/FH3 ABI, faithful native Text/world rendering and
gameplay remain unproved. Failure retention covers the established helpers'
exposed persistent frames; it does not recover unexposed callee-local bookkeeping
or add native SEH equivalence.
