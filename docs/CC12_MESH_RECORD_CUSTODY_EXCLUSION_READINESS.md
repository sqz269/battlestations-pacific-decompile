## Actual terminal interval and separate host quiescence

`delete_native_mesh_00b74280` destroys the Native payload then returns the physical C0h slot. The pool writes its free index/count and releases its critical section. Only afterward does `NativeMeshReference::release_zero_references` call the saved retirement callback; `NativeMeshPreparedRecord` unbinds the saved opaque key and marks itself retired. The record neither rereads returned bytes/+04/+BCh nor returns or releases the slot again. This interval must independently exclude reuse and slab trim/free across every participant, not only the new dormant allocator entry.

The pool critical section covers allocation and return separately. `trim_empty_slabs_00b73970` enters no critical section and can free an empty slab, move a table entry and rewrite every moved slot's slab index. The real `AllocatorListDomain` binding can dispatch this trim. `singleton_lifetime_allocate` invokes CRT `_callnewh` on allocation failure, but the finite corpus has no literal new-handler installation and only the declaration/body of `trim_all_004b46b0`; an actual host handler/scheduling bridge is not established. These absences do not exclude aliases, external installs or original Native callers.

`GameNativeResourcePoolProcess` positively owns the actual mesh pool/storage on the shared allocator list and supplies the same static binding. Its startup/getter mutex ends when the pool reference is returned. It does not enclose runtime allocations, terminal callbacks or borrowed uses. A lock solely inside a new wrapper would leave existing direct/static GUI, tracer, particle, post-effect, allocator trim and exit routes uncovered.

Registry `find` releases its short metadata lock before returning a borrowed companion; `resolve_actual` returns that same reference. Raw terminal dispatch decrements the actual +04 count before resolving and invoking the terminal method. `release_render_command_reference` is a separate direct companion terminal entry. The canonical registry owns no companion and retains no lifetime lock across terminal dispatch. Its size, capacity, prepared admission and old-key absence establish no borrower join.

Later disposal is a different obligation: all constructors/preparations, terminal calls, retirement callbacks, resolved borrowers and direct companion borrowers must be quiet. `retired()` is a record state, not a synchronization fence or active-call count. `dispose_retired_at_quiescence` requires externally proven quiescence, resets only the retired host optional and marks disposed. It must never destroy the record during the active terminal callback. No automatically collected pending records or extra Native references are justified.
