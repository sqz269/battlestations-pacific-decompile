# Dust post-effect initialization BS

`initialize_native_post_effect_dust_00b52860` reconstructs the complete
306-byte, 82-instruction initializer over an existing receiver. It constructs
the `oldfilm_dust.mshd` post-effect, publishes it at receiver+68h, binds the
current texture and resets the evidenced control fields. The four-byte
`get_native_post_effect_material_00b4cbf0` accessor is also reconstructed.
Descriptive names are hypotheses, not recovered symbols.

The original initializer takes ECX and no stack arguments, preserves EBX/ESI/EDI
and returns with RET. The receiver needs at least CCh accessible bytes. The new
C++ interface adds the storage extent and an immovable caller-owned preparation
block. It neither constructs the entire outer receiver nor releases its prior
+68h value. No drop-in initializer ABI or running-game result is claimed.

The first and final zero stores reproduce XORPS/MOVSS zero bit patterns. The
D7A24C value is copied as a DWORD without floating arithmetic or normalization.
Unlisted receiver fields and padding retain their preimages. The material leaf
is exactly `MOV EAX,[ECX+14h]; RET`: all four generated bytes match installed PE
and live Ghidra, with no relocation. Its fastcall declaration uses the original
single ECX input; it performs no profile check, retain or release.

The material setter operates on the current material, not an earlier acquired
companion. It retains the incoming actual texture and releases the captured old
texture through the same canonical owners used by the child constructor. Its
existing bounded slot/count domain remains applicable. Null native dereferences
are diagnosed at source admission boundaries rather than replaced by a dummy
child or material.

## Caller cleanup and host storage

DF8B64 names a three-state map at DF8B4C. State0 transitions to-1 and calls the
CBFFF0 raw24h free funclet. State1 transitions to0 and invokes CBFFFB, which
clears ownership bit1 before destroying the name. State2 transitions to-1 using
the same masked-name funclet, but is never visited by the normal body. The
CC0014..CC001D handler is exactly `MOV EAX,DF8B64; JMP BF6B43`; its saved definition
and forced export add no native-body credit.

The source consumes each cleanup edge before its call. If name cleanup itself
throws, the remaining raw-free edge still runs and the newer exception replaces
the original. This explicit ordinary C++ policy is outside native FH3,
double-exception, hardware-fault and private-EH-frame timing equivalence.

`NativePostEffectDustBlock` owns an existing `NativePostEffectConstructionBlock`
and the raw name header. Preparation reserves the child's existing host records
before any initializer effect. If the child is never entered, settling cancels
its unused reservations. If it is entered, its settled owner/reference records
remain available through `child()` for explicit external disposition.

The child B4E840 provider can finish its native body and then fail during host
registration. Its `native_completed` marker suppresses the caller raw24h free;
the caller name-cleanup edge is still consumed. The source does not invent the
parent+68h publication when the C++ child call did not return. Acquired child
handles preserve that completed allocation for external disposition. Earlier
native construction failures keep the original caller free schedule.

After successful publication, a failure during normal name return or texture
binding has state-1 and does not reclaim the completed child. Acquired fields are
diagnostics, not permission to retry a consumed return. All contexts, publication
cells, canonical registries and companions must outlive every surviving child.
Reset releases nothing: the caller first resolves any residual native/name
allocations, establishes external quiescence and resets the child block to idle.
Only then may it reset the outer diagnostic/name storage.

## Evidence and validation

`reports/native_post_effect_dust_bs.json` records six complete live Ghidra/PE
spans, the two bodies, literal and constant cells, three-state map, ten direct or
tail call rows and the generated material leaf. The independent Astra worker
reviewed the complete source/header, all82 initializer instructions, the live
leaf and complete raw EH closure, with no blocking findings. Accepted header
and source hashes accompany that review.

The preliminary working-tree MSVC Win32 Release build and both existing math
CTests passed. The initializer was not executed, and the preliminary build is
not represented as an exact committed integration test. The final combined
integration report records that later validation separately. No new test or
original-byte fixture was added.

Existing B4E840 renderer-callable+48 binding, material-factory internal completed
identity, provider materialization/terminal-noexcept and external-quiescence
limits remain. Parent B529A0 composition, injected cleanup failures, initializer
execution, native FH3/SEH, GPU and gameplay validation remain open.
