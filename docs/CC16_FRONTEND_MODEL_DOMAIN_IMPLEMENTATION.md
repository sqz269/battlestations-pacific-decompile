## Provider identities and construction

Renderer `Impl` retains one noncopyable domain after its node/camera/geometry/VFS/mapped providers and startup scene domain, before optional Mission graphs. The ready/quiescent `model_domain()` accessor constructs it once and is consumed by Mission now. Domain/client composition borrows the completed original process pool and existing VFS type storage/counter; it runs no Native factory, pool startup, type initializer, retain or acquisition.

The domain contains the moved light/Model bootstrap wrappers, common raw and typed Model environments, material access and sole Model/stream record lists. Both environments use process `pool_01090054`, renderer camera nodes, `app.actual_owners()`, actual graphics geometry/vertices and F8D3E4/F8D3AC material pools. Constants/tables remain mapped CE4ADC/CE4970/D7A208/D7A260, D62DE8/D62C88 and D5E520. The raw environment remains `actual_names == nullptr`; the typed instance environment remains `actual_names == &raw.strings`. No live environment is retargeted and there is no second registry/count.

Each client owns stable raw/typed access shapes with `companion_context` naming that retained client. Mission's client uses the existing three-argument `NativeModelOwner` constructor for both its typed instances and raw-name loading. Raw names do not select raw scene destruction. Page's required `make_page_client(NativeModelStorageContext&)` binds its concrete immutable raw storage before any preparation/publication. Page cannot consume the typed instance access. Its client validates the exact Model pool, renderer node-constant object/D7A208 cell, raw string context, renderer registry, point-light runtime and startup-scene increment/decrement cells. Canonical preparation performs the remaining owner/binding preflight without unconstructed actual-field reads.

## Record custody and retirement

Common preparation preserves native bytes and creates one stable record/owner over the supplied slot. Metadata failure erases only that abandoned preparation. Failed-constructor retirement accepts only this client's prepared/dead owner without a reference, before the caller returns its slot. Canonical bind creates the same sole `NativeModelReference` over actual `+04`, records registration only after registry bind returns, and preserves the completed owner/reference on a bind throw.

Each Page Model record owns its persistent raw terminal frame/acquired/host/binding; the binding borrows the client's stable real raw storage context and uses the canonical bridge's required four-argument owner. Normal raw18/raw54 dispatch remains the Page provider's explicit throwing transport. Domain disposal occurs after the canonical native terminal and lifetime unbinding; it notifies an optional client observer, unbinds once, then erases the sole record after actual pool return. If the native raw scalar consumes current flags0, it unbinds but retains the dead record and physical-slot receipt for existing process retention. It adds no pool return/retry/recovery route.

Mission's observer retains its original nonowning drawable index, verifies companion/actual identity and marks the existing drawable consumed/retired before canonical unbind. Raw Mission materialization selects acquisition metadata by exact owner **and client**, replacing `models.back()`. Model and Model-node resolution, destructor, incomplete-acquisition checks and post-drain checks use only Mission's client. Matrix environments borrow the common raw environment/type wrapper; unit/asset/bone/sampler/effect/generator ownership remains Mission-specific. Mission destruction never releases Page records.

The genuine completed-stream callback still uses the canonical vertex environment/reference/registry and terminal unbind/erase. Common checks cover prepared/unregistered records, live caller names and failed/incomplete raw destructor/scalar diagnostics. Healthy registered records await their real native owners. Clients/common state cannot be dropped while records name them; their existing failed-graph disposition retains them. Renderer retention includes incomplete common acquisitions. After actual singleton drain, Mission checks its own client and the renderer checks global common emptiness before provider teardown.

## Coupled Page caller contract

The actual Page constructor must require this renderer's `GameNativeModelDomain&`; its host passes `renderer.model_domain()` independently of Mission flags. Page constructs/retains its real raw node/scene/tree/string storage, then calls `make_page_client(storage)` before publishing the raw access/providers. Its Model raw tree context must borrow `renderer.camera_environment().nodes.point_lights`: `StartupSceneDomain` has a distinct `point_lights` value (`game_native_renderer_gui_scene.inc:210,251`), so copying that startup raw-tree binding would fail the required Model lifetime identity preflight. Page supplies `client.raw_access()` to the real same-invocation AAACD4 continuation, keeps acquired records and recursive lifetime frames with their invocation, includes `client.requires_process_retention()` in failure disposition, and retains its Impl/storage while client records or entered callbacks survive. Its completed drain calls `client.after_native_renderer_drain()`; common emptiness belongs to renderer drain. This component changes no Page guard, factory selection, helpers, Native owner source, CMake, ledger or Ghidra annotation.
