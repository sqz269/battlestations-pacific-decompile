# Actual native CRT pointer decoder

This packet reconstructs the complete 110-byte pointer decoder at `C04FDE..C0504C` (exclusive end) with a naked Win32 source entry that retains its caller's actual pointer argument word. It composes the complete [module-gate prerequisite](NATIVE_CRT_POINTER_DECODE_SUPPORT.md) and current actual OS/CRT storage. It does not create TLS/PTD storage, populate callbacks, implement the encoder, or close libm/SSE2 pow.

The source [native_crt_pointer_decode.cpp](../src/native_crt_pointer_decode.cpp) and [header](../include/bsp/native_crt_pointer_decode.hpp) are the only code owned here. The four-file packet also owns this document and its audit. Shared headers, CMake registration, Ghidra and ledgers remain primary-owned.

## Caller slot and actual storage

The new naked cdecl entry takes the original pointer value as its first stack argument and an added context reference as its second. At entry E, the actual pointer word is `[E+4]` and the stable context address is `[E+8]`. Only ESI is pushed. Thus `[ESP+8]` after that save is still the caller's original pointer argument word. A selected nonnull decoder is called stdcall with the current value of that word, then EAX is stored back to it. Every normal path finally reloads the word into EAX; identity paths make no write. Plain RET leaves both arguments for the source caller to clean up. This is an actual outgoing stack-slot contract, not a promise that a normal C++ by-value call mutates the original C++ variable.

`NativeCrtPointerDecodeContext` contains four stable borrowed reference bindings in Win32 order: current getter TLS index `E15B00`, current PTD/FLS index `E15AFC`, the actual current `TlsGetValue` IAT function word corresponding to `CE20BC`, and the existing `NativeCrtPointerDecodeSupportContext`. The import reference is not a copied function value, thunk address or generic replaceable resolver. It has the actual stdcall `void*(uint32_t)` getter type. The context argument word and reference bindings remain valid/stable across the call while native index, TLS getter, PTD and decoder values remain current. No private allocator or provider population is supplied.

## Complete current-selector schedule

The entry pushes the current `E15B00` index before capturing the actual `TlsGetValue` IAT word into ESI. It calls that captured import even if the index is -1. A null result selects module fallback. Otherwise it reads current `E15AFC`; -1 selects fallback. It pushes that captured PTD index, rereads current `E15B00`, and calls the same captured import again. The freshly returned raw getter is immediately invoked with the captured PTD index, with no extra null check. A null returned PTD selects fallback. A nonnull PTD supplies its current DWORD decoder field at `+1FC`; a null field goes directly to identity, without module fallback. The native record must provide a readable 200h-byte prefix at this point.

Fallback calls actual `GetModuleHandleA("KERNEL32.DLL")` and captures its result in ESI. A null handle goes to identity. Otherwise the full existing `C04EFB` source gate receives the stable borrowed support context. A zero result goes to identity. A nonzero result calls actual `GetProcAddress(captured module,"DecodePointer")`. The selected pointer from either route is tested once. A nonnull pointer is called with the current original argument; only this route writes the returned pointer back to the caller word. A null pointer simply reaches the shared final reread. There is no cache update, extra null validation, forced direct host `DecodePointer`, LastError restoration, exception translation or cleanup.

The selected getter and decoder must be the actual established OS/CRT providers with their stdcall ABI. This is a caller-owned current-storage contract, not an arbitrary callback domain. The prior sealed discovery grounds one actual construction route: `C053DC` publishes a raw FLS/TLS getter through `E15B00`, creates `E15AFC` and a 214h-byte PTD, and `C050F8` conditionally installs `DecodePointer` at PTD+1FC. Their complete startup, locale, allocation and cleanup dependencies remain source-incomplete. This packet neither assumes those current values are always populated nor synthesizes them.

The added second argument and context-address loads change its source ABI and volatile-register/instruction/fault footprint. The actual argument-slot read/write schedule and plain RET are retained.
