B93E60's decompiler conflates the declaration and format-name string. Assembly keeps the declaration in EDI through the stride read at B93EDC, while the string comparison reloads the independent stack pointer at B93EFA. Treating the string or payload allocation as a logical-object alias would therefore be incorrect.

For the concrete flags=1 construction path, B4BC00 installs D61D6C and creates a physical wrapper with D61E34. Logical virtual +10/+14 resolve to B49980/B49A80; their current physical +8/+C targets resolve to B4BA00/B4B9D0. The lock obtains a mapping through current COM +2C, or the explicit F8D4B8 null-COM sentinel. It stores the result at logical +8; the output base-offset pointer is a stack argument in this nondynamic path. Raw adapters BE9A20/BF02F0 forward the destination and count to the underlying input stream's current virtual +24 and debit its returned actual count. These adapters do not receive the logical object address. The dynamic lock's explicit logical-field output is +5C, also distinct from +4C.

Following the retained references one step further gives the same separation. Its full 32-byte body invokes B4B5D0 and returns the CPU-pool slot through B49570 only when flags bit 0 is set after normal destruction. B4B5D0 reaches B62010. The original B6206D..76 returning-free tail, missing from the live listing, is included in the fresh byte comparison. Knowing the stream's own profile does not supply the retained +4C object's profile.
