# CC13 gameplay band 00710000-0078FFFF (cc13-gp71)

Worker cc13-gp71 (the cc13-gp6b worker on its second packet), 2026-10-12, branch `agent/cc13-gp71` (base
origin/main `c03d29899`, which includes the landed cc13-gp6b). This is a metadata pass over cc9's gameplay band while
cc9's lanes are paused, with a small set of leaf reconstructions in new files. Nothing here was run in the
game, and nothing is wired into a host.

Status words follow AGENTS.md. **Named** means a ledger name (`config/names/0071..0078*.jsonl`) that
`tools/ghidra_annotate.py --apply` applied in Ghidra, with its evidence as the plate comment. Prior Ghidra
values are in this tree's `local/ghidra-annotations-20261012T2208..2216*.json`. **Reconstructed,
build-tested** applies only to `src/band_0071_cc13.cpp`. Names are hypotheses from cc9's docs, strings, Lua
field names, vtable slots, message ids and callers. They are not recovered symbols.

Leases: ranges `00710000`-`0078FFFF` in 64 KB pieces, without `0078D3D0`, which cc9-physics1 holds for the
plane water-surface law. A second, short lease covered the 52 cc13-gp6b message addresses renamed below. No
functions were created or deleted in Ghidra.

## Method

The same pipeline as docs/CC13_GP_006B_0070.md:

1. Export the missing decompiles (301).
2. Build a one-line dump per function and merge it with every doc line that cites the address.
3. Read vtable slot semantics from sibling tables.
4. Take message ids from the bytes (`local/g7_ids.py`, capstone) and their names from the 235-entry MT_
   table at `00E0AB68` (`local/g7_mt.py`).
5. For each bitstream constructor, use the vtable it installs and that vtable's IsType compare
   (`local/g7_msgctor.py`).

Listings were read for every reconstructed leaf. The FDIVP at `0074FA9E` is `DE F9`, so it computes
ST1/ST0 (water / capacity). Call claims are in `reports/cc13_gp71_calls.json`: `tools/verify_report_calls.py`
checked 10 rows and 0 failed.

## Notable findings

- **Message names now follow the MT_ table.** Every session message in the band carries
  `BSP_SessionMessage_<MT>_<Slot>`. That is the convention of docs/CC13_BAND_0074_0078.md, read from
  `00E0AB68`. The constructors that `BSP_SessionMessage_CreateFromBitStream` uses are `_ConstructForRead`.
  The 52 message names cc13-gp6b had given in 006B-006F (`BSP_AirOpsMessage89_*`,
  `BSP_AirFieldMessage72_*`, ...) were renamed to the same convention: MT_AIRBASE_DOLAUNCHSLOT,
  _SETSLOT, _STOCKITEM, _APPEARREADYPLANE, _SETORDERS, _SET/CLEAR_RUNWAYFAILURE,
  _SET/CLEAR_HANGARFAILURE, AIRFIELD_CREATE, BOMB_CREATE, GUN_FIRE, BOMBPLATFORM_FIRE/RELOAD,
  MULTIBOMBPLATFORM_GENERATE, VEHICLE_ADD_LAUNCHED, PLANE_TAKEOFF, CATAPULT_FIRE,
  COMMANDBUILDING_SETOWNER/SETLEVEL/UPDATECAPTURE/INFERIORLIST and DEPTHCHARGE_CREATE. The old names
  are kept in each record's evidence. docs/CC13_GP_006B_0070.md and the comments in
  `src/band_006b_cc13.cpp` still show the old names. Neither file was in this packet's lease, so the lead
  should follow up.
- **The airfield's 72h-75h messages are the runway and hangar failures**
  (MT_AIRBASE_SET/CLEAR_RUNWAYFAILURE, _HANGARFAILURE). The airfield's `+748h`/`+749h`, which
  `006D0D50` clears, are therefore the runway and hangar failure flags. The mothership's `00758750` and
  `00758890` route them by the names "RunwayFailure" and "HangarFailure".
- **The three Lua triggers.** These are `luaMW_AddProximityTrigger` (`008C9730` -> `007505C0`, vtable
  `00D00580`), `luaMW_AddLineOfSightTrigger` (`008C9460` -> `00750550`, `00D005AC`) and
  `luaMW_AddSquadOrdnanceDroppedTrigger` (`008C9A10` -> `00750660`, `00D005C0`). They share the base
  `00D00554` (`BSP_LuaTrigger_*`), whose `0074FDD0` calls the Lua callback.
- **The mission narrative object** at game+21E8h (`00735030`, 58h) holds the title list, the countdown
  (`00733FF0` start, `007340A0` stop) and two Lua callback holders. MT_MISSIONINFO (35h) carries its
  entries between peers (`00734B10` / `00734BF0` send, `00734DB0` apply).
- **`00729A40`'s threshold is FLT_MAX.** The double at `00D7A278` is 3.4028234663852886e38, so the test
  is "some barrel timer is finite and below FLT_MAX", not a tuning threshold.
