# CC15 g24d: spawn manager request list and the quoted split (packet cc15-g24d)

Four segment 61 rows that the cc15-stlA audit (docs/CC15_STL_PROBABLE_AUDIT.md) moved from
`stl_probable` to `game_code`, reconstructed in `src/cc15_g24d.cpp` /
`include/bsp/cc15_g24d.hpp`. Status: reconstructed and build-tested only. These are new C++
interfaces over raw image objects with one host hook per native call; they are not
ABI-compatible, not fixture-tested, not game-validated, and nothing is wired into a host.
Names are hypotheses, not recovered symbols.

No body existed for any of the four before this packet. Existing seams declare three of them, and
the signatures here match those seams:
`cc13_large61` `spawn_manager_remove_request_00943e40` and `spawn_manager_player_usage_00946970`,
and `cc13_seg52b` `string_vector_split_0094edc0`. 00943EC0 had no seam. Its caller is
`BSP_Replication_ApplyPendingEntityCreates` (0077EC20).

## Layout read from the listings

- The manager is (or starts with) an MSVC9 `std::list<Request*>`: +4 head node, +8 size. The
  inlined iterator's container test is `TEST EDI,EDI; CMP EDI,EDI` (the list is ECX itself).
  Node: +0 next, +4 prev, +8 request.
- Request +7Ch: the id, compared with the spawn message's +58h (0094B678) and the entity's +28Ch.
- `std::string` (0x1C): +4 inline buffer or heap pointer, +14h size, +18h capacity (heap at >= 10h).

All four keep the image's checked-iterator / bound tests (00BF6713, which returns) in their
places, along with the image's re-reads of the list head, the string size and the string capacity.

## Limits

- 00946970 takes 00946870's ST0 as a float. The main thread runs at 24-bit precision control, but
  under 53-bit control an unrounded ST0 would enter the FADD.
- 0094EDC0's EH frame (state 0 around the push_back) is not modelled; the hooks are assumed not
  to throw.
- 009439B0 is a hook. Its existing body (`SpawnRequestQueue::erase_009439b0`,
  src/lua_spawn_new.cpp) models a different, vector-based queue and is not this list.
- No Ghidra renames: the audit names are consistent with the listings.
