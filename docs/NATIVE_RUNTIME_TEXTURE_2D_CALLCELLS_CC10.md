# Runtime 2D factory call cells (B2A070)

This corrects three demonstrated dataflow boundaries in the existing source factory: raw format/pool call words, the levels word overwritten with the allocated slot, and the actual typed COM output cell. It also preserves the native accounting writes to the retained format/flags words. This is source and compiled evidence only; no runtime, application activation, new test, native ABI, private FH3, foreign escape, hardware-fault, or asynchronous equivalence is claimed.

Only `native_runtime_texture_creation.hpp/.cpp` change. The original 753-byte/237-instruction B2A070 body, its 153-byte accounting region, and its 151-byte continuation remain pinned in the separate read-only archives. This packet adds no native byte credit or new native function. The original combined proposal remains frozen and BLOCKED; the separately reviewed accounting-inclusive proposal is implemented.

## Mutable arguments and actual output

The source interface now borrows the same five live mutable DWORD call cells. After allocation it writes the slot bits to `arguments.levels` before state1 is armed. Cleanup consumes state1 before loading the current levels word and calling the existing B3DCD0 raw-pool return. The captured `raw_slot` diagnostic is not cleanup authority. No count reset, retain, canonical binding, rollback, or new failure behavior is introduced.

`com_output` is one nonvolatile `IDirect3DTexture9*` object. Both real COM calls receive its actual typed address; factory observations use volatile views of that same object. Its initial null store and retry reuse remain unchanged. The private Create call type uses DWORD format/pool words, preserving every bit without an out-of-range SDK enum conversion. This is an explicitly admitted genuine MSVC x86 stdcall boundary with nine DWORD arguments, not ISO function-type compatibility with arbitrary typed C++ SDK stand-ins.

Phase, unwind state, and diagnostics are implementation-owned across callbacks. The native call cells, genuine contexts, renderer/COM tables, and current backing remain live and mutable as documented. All five call sites rebuild against the mutable reference signature. Their argument objects are retained member storage; current continuations do not reread the overwritten fields. Public observers can see the resulting slot and scratch representations. This is a source interface change, not a drop-in private-stack ABI.

## Accounting scratch and CW

The lookup uses the current format word. Zero storage bits write full format zero; otherwise the shifted storage size is written, unsigned-converted, and stored as float32 in that same word. Captured width times height wraps as DWORD and writes flags before unsigned conversion. Accounting reads the current counter twice. FNSTCW writes only format's low two bytes, preserving its upper float bytes; flags receives the full zero-extended saved CW OR 0C00h. The global low DWORD is stored before FLDCW restores the current saved format low16.

One contiguous MSVC asm region operates on the actual live DWORD addresses. No incompatible float/uint16 C++ lvalue, guessed CW/preimage, extra FP operation, or external call is introduced inside the FP region. The private qword result is fully written by FISTP before its low DWORD is read. These raw call-cell observations remain available to later reserve, COM, final-release, and guard callbacks.

## Exact scope of ordering

Existing adjacent-read differences remain explicit. Source captures the current COM target before format/pool call operands, while native reads pool then format before its target. The append expression emits fresh data before fresh count, while native captures count first. Source increments count before its later current COM output read, while native captures output first. There is no service callback within these adjacent clusters. Equal-value reasoning requires ordinary disjoint retained argument/output cells and genuine renderer/COM/vector backing with quiescent access. It does not establish overlapping backing, every intermediate volatile observer, asynchronous mutation, or identical fault position. The accounting scratch writes cannot be excused by this qualification and are now preserved explicitly.

Original failure residuals and existing source cleanup/filter behavior remain. Constructor B3F7B0's raw descriptor/preimages/string/header/pointer access and ignored HRESULT obligations are unmodified; this packet does not complete all of B2A070's source or lifetime domains. Actual private FH3, nonlocal Lua/foreign escapes, fatal behavior, and caller activation remain separate.
