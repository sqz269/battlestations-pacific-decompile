# Application pending entity owners

Addresses: 00CD3910, 00CD3940, 00CDF4A0, 00CDF4B0, 00BFBC47, 009273A0.

Application startup now initializes the single raw destroy/kill owner pair through the recovered owner wrappers and actual CRT registrations. The represented order is observer dispatch CCD6A0, settings CD2D80, destroy CD3910, then kill CD3940, from the verified ascending initializer table. This is a process binding, not a complete native startup reconstruction.

The existing pending queue frame pass reads counts from those same owner bytes. Zero-filled pre-startup storage is rejected by the count binding when its sentinel is absent. The global storage remains alive after GameStartup is destroyed; successful real CRT callbacks free kill then destroy rings, without deleting their borrowed unit payloads. Registration status is logged and preserved, with no manufactured cleanup for a failed registration. The application performs one startup per process.

Actual population and nonempty copy/clear/delivery remain unavailable. The old copy/clear no-ops no longer report success: reaching them fails explicitly. No replacement event queue, injected event, copied unit owner or shadow count is introduced. Existing flag hooks retain their canonical unit identity.

`GameObserverRuntime::has_live_dispatch_owner()` also exposes the actual owner publication cell for the continuing unit binding. The retained owner+4 alias cannot establish liveness after raw-manager shutdown.

The component's actual-library process-exit fixture verifies three CRT observations. Combined application build and process evidence is recorded in `reports/game_pending_entity_binding.json` and the S aggregate once complete. Neither proves original-game exception handling, concurrency, gameplay parity or nonempty queue delivery.
