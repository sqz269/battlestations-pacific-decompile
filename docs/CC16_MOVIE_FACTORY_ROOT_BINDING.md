## Explicit process custody, including normal retirement

Module unload is **not qualified** by prefix retirement. The complete services
aggregate is held by an intentionally non-destructed process-owned `unique_ptr`
keeper; the Host member is only an observer. Neither normal Host destruction
nor CRT static destruction deletes that heap keeper or invokes the aggregate's
library destructor. The module/Impl/tables, heap service, owner and deletion
record remain together until OS process exit, even after flags1 frees the raw
four-byte prefix. This is an explicit bounded one-graph source custody policy,
not vendor quiescence or original unload timing proof.

The aggregate stores only self-owned members and references to permanent
manager/factory process cells. `GameNativeReadOnlyData&` is used only during
metadata construction; no Host, log, renderer or NativeData reference survives
there. No decoder/callback consumer is created by this root lane. Future real
decoder integration must retain its additional dependencies and close actual
borrowers; the present keeper does not magically qualify those future contexts.

Preparation failure before any native factory effect escapes may use existing
unescaped-module RAII cleanup. After successful preparation, the keeper is never
reset/replaced. Attempted process-graph recreation is rejected with the existing
aggregate still observed, so the terminal guard can retain it. Calls require
one serialized application graph; this is not a native irreversible latch or
reload/retry/concurrency guarantee.

Factory constructor failure may already have freed captured raw storage while
leaving dangling publication/manager slots. Root catch marks failure and runs
the existing log/`std::_Exit` retention route immediately, reading metadata only,
before a raw prefix read, ordinary deletion or shared drain. Delete exceptions
are likewise terminal. Checks repeat at shutdown, destructor and raw-drain entry.
Destructor/drain require retirement: Ready, flags0-retained, interrupted or failed
owners grant no cleanup permission. No publication clear, unregister retry,
sound reset, raw free or returning fallback is invented by these guards.
