## Failure custody, return window and explicit disposal

| Boundary | Required custody and action |
| --- | --- |
| Actual allocator throws or returns null | Preserve its existing behavior; no record preparation or guessed rollback. |
| Raw slot obtained; preparation throws | Real provider cancels entered host metadata and abandons only prepared records before throwing. Caller returns the same genuine unconstructed slot exactly once. |
| Preparation succeeds; transition invoked | Keep the persistent record and services alive. Terminal contract failure is not recoverable raw cleanup. |
| Mesh published; later particle/resource construction fails | Preserve existing Native reference/unwind effects and retain every affected published record. No automatic creator release or record destruction is supplied. Concrete partial-failure custody remains a separate dependency. |
| Existing mesh companion reaches zero | B74280 destroys Native payload and the same pool physically returns the slot before the record callback. Callback validates its own companion/phase, unbinds the saved opaque key and marks retired. No returned-byte, +04 or +BC reread. |
| Callback/terminal returns; all borrowers are quiet | Caller proves quiescence, explicitly invokes `dispose_retired_at_quiescence`, then may destroy disposed host storage. `retired()` alone proves neither quiet borrowers nor permission to destroy during the terminal callback. |

The required exclusion interval starts **no later than physical pool return and ends after old canonical-entry removal**. Allocation may otherwise reuse the slot while the old companion is still in terminal dispatch. Pool return unlocks its critical section before the record callback unbinds; the registry holds no lock across terminal dispatch and protects metadata only. Therefore neither lock closes the interval. The application must establish independent exclusion over all participating allocator/terminal/slab-trim paths, and keep returned keys opaque. Do not invent a reservation, reuse-block token, pending return queue or pool layout check and treat it as existing evidence. Record retirement must not reset/destroy its active host object; disposal is a later action after callback, terminal and resolved-companion borrowers are independently quiet.
