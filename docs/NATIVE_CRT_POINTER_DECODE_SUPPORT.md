## Current storage and complete composition

`NativeCrtPointerDecodeSupportContext` borrows four stable references: actual current volatile DWORDs `109DD84` and `109DD90`, the existing `LegacyCrtMathRuntime`, and the established `SingletonLifetimeCallbacks` returning invalid-parameter service. Their storage and service bindings must remain valid during calls; their current state is read at the native decision points. The context does not create OS state, errno storage, a TLS index or a handler. The unrelated `LegacyCrtMathRuntime::matherr_bypass_00e16bd0` member is not read.

`get_native_crt_winmajor_00bfbb61` captures the caller output pointer before the null/platform tests. Null output short-circuits the OS-platform read. Platform zero or null output calls the actual owning errno accessor, stores 22, then invokes the current established invalid service. If it returns, the getter returns 22 without a source output store or retry, subject to the service's own effects. Success copies the current major DWORD to the captured output and returns zero. The original pushes five zero arguments before storing errno and calling `BF66EF`; this source composes that all-zero invalid operation through the existing service and does not claim identical outgoing native stack words.

The existing errno interface is an explicit owning-CRT boundary, not a complete reconstruction of original `BFFB8B -> C051B7` and PTD startup. Similarly, the returning service does not claim full original `BF66EF -> C04FDE -> handler/Watson` closure. Those original bodies were separately pinned as dependency evidence. No generic policy callback or private replacement errno has been added.

`native_crt_pointer_decode_module_gate_00c04efb` initializes local major to zero and result to one, calls the full getter and ignores its status. A signed major greater than five returns one. Otherwise it directly calls actual `GetModuleHandleA(nullptr)`. There is no caller-supplied module substitute. It reads current mapped module+3Ch as a DWORD, current NT+6 section count as a WORD, then current NT+14h optional-header size as a WORD. It computes the section address before checking the captured initial count, including the zero-section case.

Each traversed 28h-byte section header is compared against the exact eight bytes `.mixcrt\0`, held in explicitly eight-byte-aligned read-only storage. Equality returns zero. After mismatch, the native WORD section count is reread before incrementing the DWORD index and advancing the section address; the loop compares unsigned. Raw image read helpers use the original DWORD/WORD widths and retain the optional-header read even when the count is zero. They introduce no MZ/PE signatures, module-null checks, optional-magic tests, range checks or terminator validation. Actual mapped header storage must support all reached reads.

`native_crt_strcmp_00c05920` is a full naked Win32 cdecl instruction body. It captures both stack pointers, aligns the first using byte/WORD reads, then reads aligned DWORDs from the first and compares bytes from the second. Wider first reads occur before zero/mismatch decisions. Unsigned comparison carry produces exactly -1/+1; equality produces zero. The body preserves EBX/ESI/EDI/EBP and follows the original EAX/ECX/EDX/flags schedule, including the internal NOP and `MOV EDI,EDI`. This is the general original comparator, not a bounded section-name comparison or host `strcmp` replacement.

## ABI, fault and exception limits

Original `C04EFB` takes no arguments and returns EAX 0/1. Original `BFBB61` is cdecl with one caller DWORD pointer, plain RET and EAX 0/22. The new gate/getter have an explicit context argument and qualified C++ interfaces. Their private stack layout, incidental volatile-register/EFLAGS outputs, exact fault addresses and native SEH continuation are not reproduced. No catch, cleanup or synthetic exception was added. The current owning services retain their own behavior, including a returning invalid handler or propagated C++ failure.

The naked comparator retains the original two-pointer cdecl instruction contract, including loads that may extend beyond a terminator within its current aligned word. Inputs must support those original reads. It does not validate or translate faults. This does not by itself establish whole-module drop-in ABI compatibility, installed-game behavior, CRT startup completeness or the later pointer-decoder argument-slot contract.
