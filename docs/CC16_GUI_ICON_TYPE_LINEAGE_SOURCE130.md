borrows the SAME canonical counter/root/root-guard identities as existing
Text/Group/Layer. Icon may initialize before Text/Group and has no payload-pool
startup/completion prerequisite. The existing process's allocator/pool metadata
construction is unchanged. All actual counter/publication/root storage remains
caller-held, unchanged and live through initialization, callbacks, consumers
and shared teardown; metadata identity alone cannot retain it.

The appended private loader-zero Icon guard/descriptor/state represent
F8BD9C, F8BDD8..F8BDE4 and Source completion respectively. Previous field offsets
are preserved; the private Source object grows. These members do not assert

Source attempt entered before guard/name/native effects. Guard1 and name word
D5C448 precede **00CD71BF CALL 00AA8200** over the existing Element/root graph.
Read BOTH current Element IDs F8BC88/F8BC8C before storing either F8BDDC/F8BDE0.

**Source failure/domain policy.** Reuse `bind_or_check_type_domain`, the actual
`CounterHost` and `LightTypeBootstrap`; no second root/counter or copied ID
authority is supplied. A completed Icon role first takes the existing pure
same-domain path, even when another role later failed. A fresh Icon call rejects
an interrupted shared Text/Group/Layer role. Cold Text/Group/Layer entries now
reject an interrupted Icon role; their completed-return branches remain before
these added checks. No old Native-body schedule is rewritten. Icon's own entered
state is sticky on escape; unexplained nonzero guard without private completion
is rejected rather than treated as successful startup. No reset, rollback,
replay, counter retirement or reentry is admitted. External serialization
remains required; no lock is held across native callbacks.

still reads Source metadata only. All existing completed lineage getters remain

F8BDD8 is a DATA role, not a Native function; the call-checker's warning on
