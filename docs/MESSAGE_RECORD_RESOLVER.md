## Lookup and missing records

`00705E00` receives the message owner in ECX, a NativeString pointer followed
by one unused stack word, and returns a **borrowed canonical VoiceClipRecord**
in EAX (`RET8`). Owner+4 is the message map. The complete listing ends at
`0070604E RET8`, three bytes, inclusive end `00706050`.

`00702910` performs lower-bound `00702300` and the reverse comparison using
the existing `00443D00` comparator. Empty string lengths are handled before
the CRT `_stricmp` call. Embedded NUL and locale behavior remain CRT behavior;
there is no Unicode folding, substring matching, or invented missing result.
An existing match returns node+14h without changing the record or allocating
string storage. The native node has links+0/+4/+8, key NativeString+C,
record+14, color+54, and sentinel flag+55.

On a miss `00705C50` constructs a temporary record, copies a key/record pair,
copies that pair into an inserted node, then destroys the temporary pair
(record before key) and temporary record. The published record identity is
stable during those releases. The resolver assigns its current input name,
sets sound ID to -1, and resizes its timed-key vector to one entry. It builds
the key text by constructing `">"`, constructing `"<"`, concatenating prefix
and name, concatenating that intermediate and suffix, and assigning the
result. The final, intermediate, prefix and suffix strings are released in
that order before any final timing write.

After cleanup, native code tests key length's sign, writes flag18=1 and
start10=+0, loads `[00E198C4]+A4`, then calculates:

```
end14 = unsigned_length * manager.per_character_7c + manager.base_80
```

The implementation uses the observed x87 `FLD; FILD; [FADD 2^32]; FMULP;
FADD; FSTP` sequence, retaining the caller's x87 control word. The sign test
at705FD8 precedes manager loading, while705FF2 rereads length for FILD. The
required manager accessor is a pure alias lookup, so it creates no additional
callback between these reads. Both timing fields come from that one manager.
The release callback may have changed the global manager earlier, which is
why this load cannot be moved above temporary destruction.

## Canonical record and lifetime

The actual record is40h: NativeString+0, sound word+8, NativeString+C,
alternate byte+14, NativeString+18, four intrusive reference cells+20..2C,
and a vector owner+30 with begin/end/capacity+34/+38/+3C. The canonical
`VoiceClipRecord` now carries `auxiliary_0c` and `timed_keys_34`; no alternate
record subclass or borrowed-to-owned conversion is introduced.

`00703FF0` initializes the three empty string headers, four null references
and empty vector pointers. **It does not initialize sound08 or alternate14.**
The resolver's by-value timed key similarly initializes only its two string
headers; start10, end14 and flag18 are stack residues until final writes.
`MessageRecordScratch` makes those inputs explicit and defined in C++. On a
miss, the alternate byte is preserved through both record copies; it is not
silently defaulted. Initial key scalar words are copied through actual x87
loads/stores, as in `00703170`, before the resolver overwrites them.

`007042B0` copies text, sound word, auxiliary string, alternate byte, alternate
name, four references, then timed keys. Each scalar is read after its preceding
string copy. `005B7DC0` clears a reference destination, captures the source
once, publishes it, then increments its intrusive count. `00704060` destroys
timed keys forward, four references backwards, alternate name, auxiliary
string, and text. Each reference is cleared after its release callback;
string destructors retain the native behavior of leaving headers untouched.
Despite its earlier autogenerated `CG_vector_deleting_dtor` label,704060
does not free the record or accept deleting flags.

The `00704190` interface consumes a by-value timed key (native `RET20h`, not
a pointer argument). Growing copies its fill temporary before capacity and
length checks; shrinking destroys the suffix forwards; unchanged size still
destroys the argument. The supporting vector constructor/destructor and
copy/insert/erase paths establish explicit NativeString deep copies and
releases. General mid-vector insertion in703CE0 and erasure in703B10 are
analyzed dependencies, not advertised as additional complete C++ ports.

## Integration and limits

`MessageRecordStore` is a semantic `std::map<NativeString, VoiceClipRecord,
PanelSequenceNameLess>`. The host owns its lifetime, and can populate it with
real loaded records; `clear_message_record_store` explicitly releases its
records and keys. The resolver context contains the existing string allocator,
`VoiceLineHost` retain/release/current-manager primitives, and scratch values.
No host method supplies a whole lookup answer. The parent binds this through
the current message store at `[00E188A8]+21DC` in `PanelSequenceHost`.

These are new C++ interfaces and standard-container projections, not native
ABI replacements. Native map shape, checked-iterator diagnostics/proxies,
allocator metadata, exact vector capacity and backing allocation identity,
and general STL internals remain library boundaries. Fully constructed
records expose four resource cells; fewer cells are accepted only for partial
C++ cleanup, and extra vector cells are outside the native four-slot record.
Callbacks must not delete the active record, invalidate captured key storage,
or structurally mutate a container while one of its operations is in progress.
Lookup reentry after node publication and singleton changes during string
release are supported. Comparator locale must stay stable for a live map.

The verified domain is normal return with valid headers and allocation success.
C++ cleanup prevents duplicate ownership but is not a reconstruction of native
MSVC SEH allocator-failure paths. Signaling NaN/unmasked trap delivery and x87
exception status are not claimed, although scalar copies and duration use x87.
No game runtime, native node ABI or native differential proof is claimed.
