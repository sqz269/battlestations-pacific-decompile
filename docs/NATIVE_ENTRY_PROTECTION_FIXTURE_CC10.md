# Current-protection restoration fixture

Four finite benign-child cases validate entry-byte restoration against the page's
current protection. This fixes a protocol defect identified in the second
original capture: the old writer acquired a page reporting40 but restored the
initial20. Attribution of that intervening permission change remains unproved.
This fixture makes no original-game launch; the original attempt count stays2.

The new writer requires a pending owned debug event, expected committed image
ownership and the full32-byte entry preimage. After temporarily requesting40,
it restores the prior value actually returned by VirtualProtectEx. Receipts
retain query-before, returned-before, temporary value returned on restore,
query-after, write/flush/restore API outcomes, byte counts and context reads.
No throwing helper intervenes between acquisition and the restoration attempt.
An incomplete transaction forbids resume or a second cleanup write. Cleanup
requires a stopped owned event and the owned CC-plus31-byte preimage; it restores
the byte and then terminates. The continuation decision and successful
ContinueDebugEvent confirmation are separate recorded states.
