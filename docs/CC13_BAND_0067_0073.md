in 00670000-006CFFFF (partition segments 27 tail, 28, 29 and 30) and 00700000-0073FFFF (segments 34

## Method

1. Survey per 64 KB band from the index; 1022 raw functions (383 + 639) had no export and were exported
   first (`local/s67_exportmissing.py` over `tools/ghidra_export.py decompile`).
2. A compact dump of every raw body (`local/s67_dump.py`, the sweep60 dumper with a vtable column:
   for an unreferenced function it reports the referencing table, its code-referenced start and the
   slot), condensed to one line per function (`local/s67_brief.py`) for the large bands.
3. Classes from constructor vtable stores and slot positions (`local/s67_vt.py` dumps a table with
   names), read against the base screen layout of 00CEAE54 (+10h Register, +14h layout, +18h Enter,
   +1Ch Exit, +20h Update) and the front-end manager layout (+4 load, +8 Activate, +0Ch Deactivate).
4. Existing docs were checked for every named address (`local/s67_docs.py`); the resource item
   classes were renamed after docs/RESOURCE_NOTE_PARSER.md, docs/GAME_RESOURCE_PARSER_REGISTRATION.md
   and docs/CC12_MESH_RESOURCE_CLASSIFIER_CONSUMER_READINESS.md (Note, ZoneDesc and MAux items).
5. Listings were read for every reconstructed body (x87 operation order and RET sizes) and for the
   slot pools; call claims are in `reports/cc13_band_0067_calls.json` (`tools/verify_report_calls.py`:
   10 rows, 0 failed).

## Notable findings

- **RNG rule.** `BSP_FishSchoolModel_Init` (00709310) draws from the shared gameplay RNG
  `BSP_Random_UniformFloatRange` 00BD2F10 (stream 0) at 007093F4 and 00709440 when it places fish.
  docs/CC13_RNG_STREAM_CENSUS.md does not list it. A host that wires fish schools must use a
  presentation stream or keep it behind an OFF switch.
- The fish-school and flag models are allocated from fixed slot pools (Mit::allocator_list_elem
  subclasses linked into the list at 00E188B4): two 18Ch-byte slots per 800-byte block for fish
  schools, 32 slots of 1A0h bytes per 3444h-byte block for flags. Each slot stores its block index
  in its last dword (+188h, +19Ch); free stacks are uint16. Reconstructed as `SlotPool`.
- docs/APP_INIT_GAME_ENTRY.md records that the per-frame hook (vtable 00CFEA98) calls 008E2560,
  which runs 0070AA70 three times and then 0070A710 three times, with "the subsystem behind it
  unidentified". Both callees sit between the fish-school and flag pools in segment 35, and
  0070A710 locks the vertex buffer at +78h like the flag model's material builder; they are named
  `BSP_FlagCloth_*` provisionally. The identification rests on placement and field layout only.
- `BSP_DigitSpinner_StepDigit` (0067DF40) returns `(digit + delta + 10) / 10`, so 0 is a borrow,
  1 no carry and 2 a carry, not a plain carry flag.
- The resource item classes (vtables 00CFD860, 00CFD888, 00CFD8FC, 00CFDBD8) all follow one
  shape: slot +8 returns the type token global, +0Ch tests a token chain starting at it, +14h
  returns the type name address. 00CFD860 is the Note item, 00CFD888 the ZoneDesc item (the one
  `BSP_ZoneDescResourceParser_CreateItem` builds inline), 00CFD8FC the MAux item and 00CFDBD8 the
  GeomMesh item.
- `BSP_GeomMesh_RadixSortByAxis` (007230F0) sorts the global record array 00E19BDC with a stable
  4-pass byte radix sort on the raw dword at +0, +4 or +8. The keys are treated as unsigned, so if
  they are IEEE floats a negative coordinate sorts after every positive one unless the caller biases
  them first; the caller 007240E0 was not read.
- `BSP_VFS_MountContentPackages` (0073BC40) and `BSP_MsarProviderFactory_GetSingleton` (00736D00)
  are the MSAR mount pair that docs/NATIVE_VFS_FILE_DATE_DISCOVERY.md and
  docs/CC13_LUA_SCRIPT_LOADER.md describe; 0073BC40 still has no caller or reference.
- docs/MODEL_REACHES_UNIT.md calls 00710630 a copy constructor; its body is a ref-pointer release
  (InterlockedDecrement, delete at zero, clear). Named `BSP_RefPtr_Release_00710630`.
