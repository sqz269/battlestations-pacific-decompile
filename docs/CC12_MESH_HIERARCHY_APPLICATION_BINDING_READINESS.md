# Mesh hierarchy: explicit application binding readiness

Baseline: `c919a5bfd88ef9f6b252ef81a0918dfaf790d7cd`. This file-only audit uses current Source and accepted retained reports. It performs no Native analysis, installed-image read, table/callee/handler query, Ghidra mutation, C++/CMake/ledger edit, build, test, probe or runtime execution. The opening brief's health contact is separate from this Source audit. Source636 and the completed fallback owner API are unchanged context.

**A narrow retained hierarchy-services API is ready for a Source packet.** The existing resource application can retain the genuine `NativeResourceRootDispatch`, `NativeResourceStreamReadContext`, `NativeResourceHierarchyParserContext` and a borrow of the canonical hierarchy pool, then expose them only through an explicit application call. All required ordinary Source services and original data identities for that binding are already retained. There is no need to wait for allocation statistics or to construct a full cache, classifier, renderer or mesh-loading graph.

The concrete missing application edge is the structured-node deletion domain. Wiring a hierarchy reader directly to `NativeVfsRuntimeBindings` would fail when a child handle reaches zero references: that dispatcher admits its stream/provider families, while a hierarchy child is `D68BB4`. The existing `NativeResourceRootDispatch` supplies the genuine `BD30E0 -> current slot4 -> BE9FC0` node path and forwards stream operations to the real VFS dispatcher. Current `game*` Source constructs no instance of this adapter or a retained hierarchy parser context.

## Smallest next Source packet

Suggested packet: `cc12_mesh_hierarchy_application_binding_source`. Keep the implementation in `include/bsp/game_native_resource_application.hpp`, `src/game_native_resource_application.cpp`, and the explicit forwarding surface in `include/bsp/game_hosts_vfs.hpp` / `src/game_hosts_vfs.cpp`, plus its focused evidence document/report. Proposed API names are new Source names, not recovered symbols.

1. Append address-stable host metadata to the existing resource application's `Impl`: a noncopyable hierarchy binding that borrows the already-owned raw string context, canonical initialized hierarchy pool, mapped bounds/table data and this application's actual VFS bindings. Preserve the earlier publication/context members' identities.
2. Construct `NativeResourceRootDispatch` over those actual VFS bindings and raw strings. Construct `NativeResourceStreamReadContext` over the same strings, that node-capable dispatcher and the process `0109DB64` byte. Construct `NativeResourceHierarchyParserContext` over that read context and references returned for `CE4ADC` and `CE4970`. Validate the required mapped spans, including `D68BB4`'s two qualified words, before exposing the binding.
3. Provide an explicit borrow/bind call through `GameVfsHost`, using its own `native_` and `resources_`. Require its completed core-ready state and existing operability gate; pass only its own raw services/string context into the resource owner. The actual constructor already proves the `native_->raw_strings()` relationship. For any direct resource-application overload, preserve that same-runtime/string-domain precondition or make the overload private to the host; matching only one publication pointer is not proof of an arbitrary caller's whole runtime identity.
4. Return stable borrows of the retained read context, hierarchy context and canonical pool as needed by genuine callers. The API binds services only: it performs no resource/parser getter, type initialization, I/O, root creation, hierarchy parsing, resource creation, manager publication, shared-drain registration or native cleanup. Constructing host metadata does not justify adding a Native startup call.
5. Repeated borrowing must keep the original adapter/context addresses and require the same borrowed domain. Do not rebind a used context to another VFS, string pool or mapped-data owner. Preserve owner lifetime through every consumer and the complete shared drain. Destruction of this metadata must not dereference a singleton host that may already have been deleted or repeat native teardown.

This is a usable binding to complete Source, with a real node-deletion terminal and a real stream provider. It requires no abstract `remaining` service, success sink, fake stream, private pool, copied type IDs or application-local sentinel byte. The new API's intended consumers remain explicit; it does not announce that startup now invokes them.

Direct use of the returned parser context still requires a live actual manager, current resource, structured handles and reader/stream storage. `B7EB90` reloads manager+24 only when appending the completed raw record. Binding must not cache that pointer or replace its native selection. Pool retirement and resource ownership stay with the actual caller; merely borrowing services creates no records to own or drain.

The exact failure contracts matter to that later surface. `B8A910/B8A990` disarm allocation cleanup before current slot20 dispatch; a reader failure retains the allocated item. Neither a normal C++ owner destructor nor a retry may silently undo or reconstruct those states.

A later parsing API must also propagate interruption into the existing `GameVfsHost` retention policy or an equally concrete retained owner; returning a borrowed context alone does not install that new invocation policy.

## Mesh, container retirement and lifetime boundaries

Renderer `TextureLoadingGraph` already owns the canonical `NativeMeshEnvironment`, `NativeMeshSectionEnvironment` and `GuiNativeGeometryOwners`, sharing `0108FFF8/010901D4`, the actual owner registry, VFS string wrapper and mapped profiles. Renderer section-layout services borrow that same geometry. Reconstructing another geometry/mesh domain would break this established ownership.

Current public renderer providers expose runtime textures, surfaces, holders and direct terminals; `actual_owners()`, `texture_cache()` and section-layout APIs expose other existing services. They do not expose a complete `NativeMeshLoadingContext`. That context still needs the same read/metadata context, material destruction/effect cache, texture field loading, lighting, generators, mapped profiles and persistent acquired frames. A hierarchy-services binding does not supply those dependencies or admit `B947A0/B94850/B94900` mesh loading. The current mesh adapters already retain acquired frames before invocation; failed frames cannot be discarded or replayed.

`NativeResourceContainerReferences` supplies real base/game/fallback resource terminals and binds its item dispatch through itself before forwarding. Its lifetime context already accepts the actual manager and hierarchy pool. It must eventually compose the complete reached item-reference chain, including the same mesh geometry and extra-item/string domains. The particle runtime's `resource_references` member is a required borrowed input, not evidence that the application constructs that missing chain. Pool presence and complete individual destructors do not establish resource-retirement composition.

The existing hierarchy cleanup `B88320` destroys fields through the actual raw strings, returns the original slot to the supplied pool only for flags bit0, and returns the original record address. The parser initializes only its 84h payload fields; matrix bytes and the slot+84 pool marker remain untouched. Its ordinary failure cleanup releases only active child/name temporaries, leaving unpublished record/field allocations as the recovered body does. Root/node deletion debits declared payload and reader path state without seeking unread bytes. These semantics must remain in the existing genuine Source services.

`GameVfsHost` constructs `native_` before `resources_` and destroys them in the reverse order. `GameStartupHost` keeps VFS, raw strings and deletion contexts through the actual singleton drain, then deletes the singleton host before the VFS-owned metadata. The canonical mapped-data owner remains mapped through `host.reset()`. The new binding therefore has an existing lifetime home, provided it performs no destructor-time borrowed-host access and all actual native payloads are retired or retained under the established failure policy. This audit adds no retirement or startup edge.
