## Method

1. Survey: the cc9 list filtered to the band; 503 missing exports were exported first
   (`local/g6_exportmissing.py` over `tools/ghidra_export.py decompile`).
2. A compact dump of every raw body (`local/g6_dump.py`, the sweep67 dumper with a vtable column),
   condensed to one line per function and merged with every doc line that mentions the address
   (`local/g6_docmap.py`, `local/g6_merge.py`). cc9's docs (SQUADRON_LAND_TASK, AIROPS_LAUNCH_TICK,
   AIROPS_LAUNCH_START, AIROPS_LAUNCH_GATES, AIRFIELD_TAXI, BOMB_FAMILY_TICK, GUNNERY_OPEN_ITEMS,
   SHIP_AI_OPEN_ITEMS, CONTROLLED_UNIT, COMMAND_CLASSES, SCENE_COMMAND_TYPES, ENTITY_CLASS_IDS,
   RECON_PUBLICATION, PROJECTILE_KINDS and others) already described most of these routines by address
   without naming them; the names carry those descriptions with the doc cited in the evidence.
3. Vtable slot semantics from sibling tables (`local/g6_slots.py`: tables sharing at least 30 entries
   at the same offsets, and the names their entries carry at the slot), class ids from
   ENTITY_CLASS_IDS.md, and the tiny bodies classified from the PE bytes with capstone
   (`local/g6_stubs.py`). Strings from the index data refs (`local/g6_strs.py`).
4. Bodies were read in pseudocode for every name that does not rest on a doc row; listings were read
   for every reconstructed leaf (FMUL bytes at `006E0559`/`006E054F` checked against the D8/DC
   ambiguity), the predicates at `006BC410` and `006E3B80`, and the stubs.
5. Call claims: `reports/cc13_gp6b_calls.json`, `tools/verify_report_calls.py`: 11 rows, 0 failed.

## Notable findings

- **Class 35h is the dummy target vehicle.** ENTITY_CLASS_IDS.md lists 35h (vtable `00CFCD60`) as
  unnamed; the band doc for 0067-0073 called it a door/cargo/bomb-carrier unit. Its serializer
  `00700870` writes the saved table `"_dummyTargetVehicle"` (velocity, openState), and `00701250` reads
  the Lua boolean `HitOnTheFly`. The ledger already uses `BSP_DummyTargetClass_*` for its class record
  (`009600A0`, docs/LOCAL_PLAYER_UNIT_LISTS.md), so the MBullet-family dummy target record
  `00CFA5CC` was named `BSP_DummyTargetBulletClass_*` here to keep the two apart.
- **The command-building handler's D5h arm is `006F29D0`, D3h's is `006F4D10`.** The call sites are
  `006F5492` and `006F54A9` in `006F5460` (verified). This matches SHIP_AI_OPEN_ITEMS.md's correction.
- **`006F2A67` is a split.** Ghidra made a function at `006F2A67`, inside `006F2A50`
  (SHIP_AI_OPEN_ITEMS.md: "006F2A50's take (006F2A67..006F2BC6)"). It reads EDI and stack slots it does
  not own. It was left raw; it needs a listing repair (delete the function, let `006F2A50` own the body),
  which is a Ghidra mutation outside this packet.
- **`006D1D20` returns 10h, not 45h.** It is the airfield class record's recon category (16, the
  "airfield" row of RECON_PUBLICATION.md); 45h is the airfield's class id. The recon categories as a
  whole are already reconstructed in `src/recon_slot_lists.cpp`.
- **Two shot-interface "ignite" bodies.** BOMB_FAMILY_TICK.md says shot `vtable[3Ch]` is `00809F20` for the
  rocket and `006E1CD0` otherwise, while PROJECTILE_KINDS.md gives `006E6C20` for the same slot of
  `00CF93B0`. The shot-interface tables hold `006E6C20` at `+3Ch` (`00CF93B0`, `00CF9D90`,
  `00CFD570`). `006E1CD0` has no table reference, one direct caller (`00809F20`), and addresses its
  object at `this-248h`, so it is a method of a different, embedded interface. The two docs may describe
  different interfaces; both functions are named, and cc9 should check BOMB_FAMILY_TICK.md's sentence.
- **The debug unit inspector** (singleton `00E19AAC`, vtables `00CFB9B0`/`00CFB9A0`) prints a recursive
  panel for the unit picked in the HUD unit-pick screen ("flooded: %3.3f" for ships). Debug only.
- **Session-message ids in the band**: 72h-75h (airfield, base 62h), 7Ch and C6h (unit), 81h, 85h, 86h,
  88h, 89h (air ops), A3h (airfield create, base 47h), ADh (gun fire), B1h-B4h (bomb drop, platform
  reload, rack load, catapult launch), B6h/B7h (bomb and depth-charge create), D3h-D6h (command
  building). Each one's constructor and type predicate is named.
