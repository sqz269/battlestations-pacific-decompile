# Canonical current-IAT cache zero release (CC10 Packet A)

This adds an explicit source composition for `004DDB40` using the existing
canonical actual-resource domain. The current raw naked entry remains intact.
There are no new native bodies or native-byte credit, and no callable native
vtable, substitute terminal, count initialization, retry or compensating retain.
Packet B's particle-clock singleton-manager profile binding remains separate.

`dispatch_native_render_actual_owner_zero` shares the existing post-zero
resolve/identity/terminal operation. It resolves the canonical companion only
after the caller has already observed zero, compares its borrowed atomic with
the SAME actual resource+4, and invokes its nonthrowing genuine terminal. It
never changes the count. Existing `release_native_render_actual_owner` still
performs exactly one sequentially consistent `fetch_sub`, then uses this helper
only when the previous count was one.

The new canonical `release_native_particle_clock_sink_004ddb40` overload captures
the original resource, forms resource+4, invokes the CURRENT borrowed CE2220
Interlocked cell once, and branches on its returned count. Nonzero performs no
canonical lookup or resource-profile read. Zero reaches the shared post-zero
helper. The added canonical argument is a new C++ source interface; the original
raw naked overload's stack word/RET4 and current-cell callable-profile contract
remain unchanged. No original binary ABI or private FH3/SEH is established.

`NativeParticleClockShutdownContext` appends an optional borrowed
`actual_resource_owners` pointer. Null preserves the raw callable-profile route.
When supplied, the existing current secondary-profile/+10 validation still
requires 4DDB40, then selects the canonical overload. This adds no cache or
resource metadata domain and performs no implicit admission or registration.
The appended field changes the source context's Win32 size20 to24; existing
source callers must rebuild. Prior field offsets and the raw leaf remain intact.

The actual clear schedule is retained: capture current last resource from
current count/base, read current secondary profile+10, release that resource;
after callback return reread current count and, if nonzero, current base, destroy
CURRENT last record through 4D45A0, and perform one memory RMW decrement of
CURRENT count. Repeat, then actual 4DC410 resize0. Neither a saved vector snapshot
nor a saved record replaces those reloads. Resource/companion terminal disposal
may free both objects; no access to either follows it.

The native pin is the complete 31-byte 4DDB40: stacked capture at 4DDB41,
resource+4 at 4DDB45, current `[CE2220]` call at 4DDB49, returned-count test at
4DDB4F/branch4DDB51, zero-only CURRENT profile/slot0 at 4DDB53/55, no-argument
call4DDB59, RET4. Four owned normal bodies/299B and two reached procedural
profile rows were re-read through the existing verified Ghidra project/program
before building; each matches the immutable readiness and original PE.

The canonical owner and companion must remain live under caller lifetime
synchronization. Missing/mismatched canonical identity after zero propagates
as a source error with the count already zero. No retain/reset/retry repairs it.
A companion must borrow the same live B19980-created atomic, with one successful
canonical binding. Companion construction does not itself bind; if binding
fails, the caller still owns its explicit retirement obligation. A retirement
callback unbinds only the exact identity/companion it actually bound, then may
dispose the retired companion without reading dead resource/count storage.

Existing procedural companions use the current D64478/D644B4 views to execute
real BD30E0 -> current BBC6D0/BBC7F0 -> C304A0/base/CRT free and exact metadata
retirement. Unknown profiles, concurrent retirement, missing companions and
throwing terminal dependencies are outside the established normal contract.

Cache credit policy remains unchanged. Every nonnull hit retains regardless of
the retain-new flag. A new nonnull resource's original count belongs to the cache
after append; retain-new0 returns a borrowed pointer and retain-new1 adds one
caller credit. Record copies and temporary destruction do not retain/release
resource+28. Quiesce loaders/lookups/reference producers, release each actual
caller credit once, and keep canonical/profile/pool/context dependencies alive
through the last cache decrement and exact terminal retirement. Null-result
records and partial append/alias/resource failures retain their existing caller
obligations; this packet adds no null skip, cache rollback or removal policy.
