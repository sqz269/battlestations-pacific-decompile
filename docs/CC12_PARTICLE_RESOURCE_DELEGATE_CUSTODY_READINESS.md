## Resource admission and retirement

`native_particle_model_construction.cpp:75-114` creates the actual mesh, section and material before invoking their three `noexcept` bind hooks. The mesh/material catches return only raw constructor-failure allocations; section creation delegates its complete existing factory. These actual identities first become available inside those helpers. `NativeParticleModelConstructionCallees` exposes only the postconstruction resource hooks.

`NativeRenderActualOwnerRegistry::prepare_binding` requires the exact nonnull, aligned actual identity and allocates its null map entry. `publish_binding` fills the validated prepared entry without insertion, rehash, Native retain, or callback. Preparing an unrelated key or reserving generic capacity is insufficient. A mutex or validation failure that reaches an existing `noexcept` publication has its existing terminal policy; this is not a general promise that arbitrary host admission cannot fail. Current Source uses this prepared-entry API for the particle model record, not these three resource companions.

All three companions borrow the same Native count and require positive current counts and real retirement callbacks. Their destructors require prior retirement. On the zero path, they validate the live profile, perform Native physical deletion and pool return, mark the companion retired, then invoke its disposal callback without accessing it afterward. The callback must have stable storage and unbind the actual key as an opaque identity after physical retirement. It must not dereference an already returned Native slot.

`GuiNativeGeometryOwners` positively owns lists of mesh/section/material records and unique companion objects, validates shared canonical domains, unbinds then erases records on terminal callbacks, and requires empty lists at destruction. Its mesh and section factories perform Native creation before allocating companion metadata. Its material admission accepts an already completed acquired frame, allocates entry/companion metadata, and records partial acquired effects before regular binding. These are useful existing custody contracts, but their allocations and throwing admission cannot become nonthrowing particle postconstruction hooks. Calling a GUI factory would also create another Native object.

A complete delegate therefore needs a separately established preconstruction exact-identity preparation/cancellation/publication seam and persistent per-resource custody. It must preserve Native ordinary unwind, actual counts and the particle constructor's shared model/material/mesh/section domains. No default/no-op implementation, second registry, shadow owner/count, or invented raw-address map is admitted here.

## Saved renderer and random providers

`native_particle_model_construction.cpp:139-155` captures both the renderer and its `+5C` entry **before** AF10B0 descriptor construction, then delegates exactly `(renderer, entry, 0, 0x1000, descriptor)`. After creation it preserves the established mesh publication and creator-release order. A helper must authenticate that captured D5F0A8 receiver and B287C0 code token and must not replace either from current globals or a later `+5C` load.

The complete B287C0 body allocates and constructs the actual logical vertex, publishes its completed creator to the supplied acquired pointer before renderer-array append, and preserves its later current `+58` registration behavior. Constructor failure uses its existing Native raw-allocation unwind. A later exception can leave a completed creator and partial renderer registration. Existing GUI stream admission records the companion before canonical binding, so its partial effects likewise remain in the caller-owned acquired frame. The saved-renderer helper may throw; the three resource bind hooks may not. This difference permits the narrow helper without inventing a new ownership policy.

The existing BD2F10 path resolves the same stream state through BD2ED0 and uses the established range body. That body includes unsigned x87 conversion/correction, scaling, a binary32 spill before affine range arithmetic, and final binary32 rounding. Borrow the existing `NativeParticleUnitRandomAccess.random`, `unsigned_correction_00ce3978`, and `unit_scale_00d63b80` without replacing state, seeds, constants or arithmetic. Positive tracer and ship-AI callers are retained. Neither a unit-only BD2F40 replacement nor a new random sampler is justified.

## Persistent particle-model custody

1. Before AF74A0, prepare the sole actual-slot `NativeModelOwner`, scene association, Generated admission, exact-key registry entry, and `NativeParticleModelPreparedRecord`. Preparation and cancellation must finish before Native construction. The hook adapter merely borrows this record and the real resource delegate.
2. AF74A0 publishes the particle profile before its acquired construction try block. The record and all borrowed services must survive every subsequent constructor callback and exception.
3. On acquired failure, AF74A0 destroys entered emitter pointers and base-owner state, then invokes failed-profile retirement. The outer registered-effect caller returns the raw AF62F0 slot only after AF74A0 throws. Do not destroy the model twice or treat raw allocation return as record disposal.
4. A successfully constructed model can outlive the effect constructor. Later effect-construction failure only unwinds the effect base; it does not supply a successful-model destruction/custody policy. A stack-local record, adapter or service bundle is insufficient.
5. On final Native retirement the actual slot can return to its pool before Generated unbinding and the record callback. Then the canonical registry key is unbound and the record becomes retired. The raw key is opaque at this stage. All callback contexts must still be alive.
6. `dispose_retired_at_quiescence` is a later explicit host action. It requires no active constructor/hook, terminal callback, or resolved borrower that can still use the record or companion. `retired()`, a registry lookup, and a registry mutex are not evidence of that quiescence.

The closed corpus contains only the existing borrowed prepared-hook adapter as a construction-callee subclass. The model-construction wrapper has declaration/body but no application caller; `dispose_retired_at_quiescence` has declaration/body but no Source caller; the explicit owned-record and owned-adapter storage spellings have no matches. These limited negative results accompany the positive bodies, not a claim about all possible C++ type aliases or hidden external callers. The application renderer owns a canonical registry, but its getter/drain do not establish particle-record custody. Shared pools, name/manager providers, and separate post-effect records do not supply it either.
