# Game input settings runtime composition

`GameInputSettingsRuntime` is a stable-address owner for the reconstructed input-settings service chain. It owns `NativeInputKeyboardStorage`, `NativeInputSettingsScriptServices`, `NativeInputSettingsTableServices`, and `NativeInputSettingsLifetimeContext`. Its `get()` method calls the reconstructed `005547D0` singleton getter with that retained context. The class adds no native ABI or new native-function attribution.

The caller supplies the actual `00E198E8` settings-publication cell and `01090AA0` manager-publication cell by reference. It also retains the referenced string storage, Lua bootstrap and file services, conversion flag, and two float constants for the entire lifetime of this owner. `GameInputSettingsStackPolicy` requires three explicit input words: descriptor flag, vector opaque, and sensitivity default preimages. None has a default value. The source evidence does not justify choosing zero for an unspecified native stack preimage. The descriptor and preset-flag stack cells are distinct in native code even where the current table-service contract uses one supplied seed; this API does not assert that their historical stack contents were identical.

Construction only composes references and storage. It does not invoke the native getter, allocate the settings object, or register a singleton. A production host must construct the raw services and both publication cells, construct this owner, bind `context()` into the canonical singleton deletion service, and only then call `get()`. Keep the owner, both cells, and every borrowed service alive through raw-manager drain. The manager's registered deletion path owns destruction of a published settings object; destroying this C++ owner is not a substitute for draining that manager.

The existing `005547D0` slow path allocates and constructs the settings table, publishes it, and registers its deletion callback. The source composition here leaves that behavior in `native_input_settings_lifetime.cpp`. `NativeInputKeyboardStorage` supplies the concrete fourteen-operation tree provider, while the table service retains the exact script and numeric inputs supplied by its caller. This packet does not wire `GameStartupHost`: the current executable has no proven raw `0109CEEC` Lua/VFS service route for the settings script. Source reachability through `get()` is established; executable startup reachability and game behavior are not.

- `src/native_input_settings_lifetime.cpp` contains the `005547D0` getter, the `006AB6B0` settings constructor call, publication, and raw-manager registration. Its associated reconstruction report records direct calls at `00554846`, `00554867`, `005547F6`, and `00554859`.

- The preimage provenance is bounded in `docs/NATIVE_INPUT_PREIMAGE_PROVENANCE_AY.md`. Unobserved or overwritten words remain explicit caller policy because this composition cannot infer a native stack value.
- This source owner has no standalone native address. The report's call rows are evidence for the existing native getter boundary, not claims of new native function coverage.
