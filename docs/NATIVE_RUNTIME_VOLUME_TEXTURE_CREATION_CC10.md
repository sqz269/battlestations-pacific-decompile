The complete native factory is `[0x00B2A5A0,0x00B2A7AA)`, 522 bytes and 164 instructions. Native ECX supplies the actual renderer; six stack DWORDs supply width, height, depth, levels, format and flags. It returns the constructed owner or zero in EAX and uses `RET 0x18`. The profile reference is `0x00D5F138`, renderer profile `0x00D5F0A8 + 0x90`; no direct callers were observed in the bounded query. The four-entry pool table begins at `0x00B2A7AC`.

The immutable readiness document incorrectly called the two excluded boundary bytes `CC CC`. The observed five bytes at `0x00B2A7A7` are `c2 18 00 8b ff`: the return is followed by `mov edi,edi` at `0x00B2A7AA`. The body boundary, size, instruction count and table location do not change. The separate correction receipt preserves that error and its original evidence instead of rewriting the readiness archive.

The mutable six-word block preserves cached format/depth/levels and usage, current width/height on both COM calls, and current full flags before construction. Allocation bits overwrite the height word before the low-byte state-1 store. Failure cleanup reads that current word, not a captured owner diagnostic. The exact 20-byte caller-live local frame contains the pool DWORD, an actual `IDirect3DVolumeTexture9*` output object, saved renderer pointer and eight-byte optional guard. Its scalar/pointer lifetimes and defined preimages are caller obligations. The SDK receives the address of the actual typed output object; there is no DWORD/void-pointer alias or fabricated local default.

The guard entry writes its receiver and returned low byte only when the current mode enables entry; its other three first-word bytes retain their preimages. The normal exit reloads current mode and reads the full saved word through bounded MSVC machine-byte access, then the current guard receiver. It does not form a DWORD lvalue over live mixed members or claim an asynchronous C++ access guarantee. A mode transition from skipped entry to enabled exit or cleanup requires a valid preexisting guard; the implementation does not initialize one retroactively.

The first real `CreateVolumeTexture` captures the original renderer's current device, then format/depth/levels, clears the output once, and captures the current table. Current pool/height/width precede its current table `+0x60` target read. Retry requires current null output and a captured nonzero HRESULT other than `0x8876017C` or `0x8007000E`. It invokes genuine B29670 with the current saved renderer, reloads that renderer/device/table/target, and rereads pool/height/width into the same output cell without clearing it. Its second HRESULT does not control native flow. Pool nibbles above three require a defined retained pool preimage. There is no default-pool fallback, AddRef or Release.

Actual B3F2D0 allocation uses the same volume pool. After publishing raw-slot bits to the caller height word and arming state 1, nonzero allocation invokes genuine B3D720 with current full flags and COM input, the same serial and owner context. The returned owner is captured for publication and return; diagnostic fields are not substitutes for captured native operands. Current renderer `+0x1B00` capacity is captured before current-count comparison. State 1 disarms after comparison and before reserve. Wrapped doubled capacity is signed-clamped to at least one. The raw 735FF0 provider receives the original raw header address under its existing domain; its typed overload cannot adopt header or slot lifetimes. After reserve, current count precedes current data, the computed nonzero address controls the captured-owner store, and current count increments unconditionally. Null allocation publishes null and leaves acquired COM residuals.

The native state map is state 0 to -1 through CBD3A0/B21110, and state 1 to 0 through CBD3A8/B3DCF0. The C++ cleanup consumes each state before its action. A construction exception first completes the sibling constructor's base cleanup, then returns the current caller slot through B3DCF0 and the same B3D860 pool, then performs current guard cleanup. B3DCF0 is the complete 12-byte, four-instruction selector `[0x00B3DCF0,0x00B3DCFC)`. The started count and COM obligations survive raw pool return. An append/reserve exception occurs after state-1 disarm and leaves the constructed owner. The full -1 store precedes normal guard leave; failure there does not rearm cleanup. A second C++ exception during cleanup terminates; foreign/hardware exceptions continue their existing search. This source does not reproduce native FH3 or claim equivalent foreign-exception behavior.
