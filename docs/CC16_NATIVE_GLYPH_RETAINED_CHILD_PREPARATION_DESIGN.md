## Exact preparation API and its limits

Append this one proposed method to the existing GameNativeRawDefaultTextOwner, preserving all old APIs:

```cpp

    const GameNativeCanonicalDataOwner& actual_canonical_owner,
    NativeGuiTextGlyphQuadStorageContext& actual_caller_context,
    std::size_t model_node_call_capacity);
```

Each call creates ONE distinct nonmoving private `Impl::GlyphChild`, installs it in the existing Services-owned retained history before bind(), and returns only its actual GlyphAcquired. It exposes no private Attempt, RawReference, count or credit. Preparation occurs on a stable already-prepared owner/service graph before the caller's parent Native entry; actual admitted owner phase/reentry guards remain a Root implementation decision. New graphs do not reuse/reset the ONE AA1380 factory Attempt or repeat Services::prepare. The new private birth metadata pins those exact graph aliases and the expected caller Context. Raw93 Frame need not be exported by a getter: the already-constructed acquired record supplies its bound private triplet at the real constructor call. Public diagnostic fields cannot establish provenance.

The caller still owns its genuine input Text, parent Frame/acquisition, ten homes, position/stream/mapping backing and selectors. SingleLine scratch.quad_homes and Wrapped Frame.quad_homes are the actual existing homes, refilled only after normal return. The new preparation API does not own/copy them, read their values, bind an unknown parent input, or claim pre-entry parent/home proof. ## Retention, partial failure and real disposal

Allocate only C++ metadata before Native entry. A constructor/allocation failure before installation has fresh metadata and no Native effects; it does not justify Native cleanup. Install each constructed graph in owned history before bind()/remaining admission so a partial bind or caught rejection cannot free or replace the record. Use the existing owner's sticky failure/retention hierarchy. No new child destructor performs disposal, Native cleanup or termination. Do not reuse old wrappers whose destructors demand unrelated modes. The existing fixed destructors/NoThrow boundaries are inherited Source projections, not Native FH3/SEH proof.

Extend the existing retain()/custody_settled aggregation to all retained children. Distinguish unused metadata, healthy live/completed child, entered/interrupted/failed graph, and genuinely disposed/quiescent tombstone. Healthy live children remain owned even when a diagnostic retention query is false; false never authorizes deleting their backing. Failed/entered/poisoned graphs and any partial Model/constructor/shader/map debt remain retained. A healthy child becomes settled only through actual completion/disposal and nested custody proof, followed by existing parent drain acknowledgement. Do not infer settlement from public phase/completion fields, zero/null slots or a borrowed progress snapshot.

The current host already uses _Exit(1), retaining all borrowed Text/font/material/node/frame owners on incomplete or retirement/drain failure (runtime caller905-949). It does not provide a passive recoverable leak API. Preserve that existing policy and admission boundary; this design adds no global exit/recovery/cancellation policy. Current populated retirement is not closed, so successful birth does not imply this existing owner can safely reach reset/close with live Glyph children. Keep runtime admission false instead of inventing cleanup.

Each child requires a stable private disposal context distinct from the old factory callback. Only the actual binder-installed RawReference completion route may use it. RawReference::finish_success823 first sets retired and unbinds the owner, then invokes saved disposal LAST. C180's independent private tombstone must be recorded before destroying ONLY that companion, without reading the ended Text/Model payload or freeing unrelated graphs. Prove route/admission before actual scalar/zero work; the terminal metadata callback is not a new validator or policy boundary. Use retained identity/private receipt and the existing fixed `void (*retire)(..., RawReference&) noexcept` type only as its inherited Source projection. Do not add a new NoThrow claim, throwing failure guard, terminating callback branch, allocation/log/lock, count repair, retry or scalar/zero substitute. The actual populated scalar/zero transport and its complete disposition remain unavailable and require separate proof; preparation never invokes disposal.

Model node_call_capacity is exactly the existing explicit helper backing extent (old preparation1478), with its existing Source representability/freshness obligations. It is not a bound on Native Glyph count/recursion and cannot prove complete domain cardinality. The genuine caller must prepare a distinct record/backing for EVERY actually reached/recursive call before entry. No exhaustion result, truncation, fallback or reset is supplied. Calls for OTHER captured targets stay unconstrained; no known-color coupling or target whitelist is added by this preparation API.
