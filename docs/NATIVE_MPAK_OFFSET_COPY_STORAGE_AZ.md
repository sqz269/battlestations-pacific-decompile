# MPAK offset vector copy

Address: 00BB6180. The only saved caller is 00BB65A0 at 00BB6616. The new `NativeMpakOffsetCopyStorage` supplies the existing `NativeMpakOffsetVectorCopyLibrary` interface over actual Win32 10h headers. The original entry is ECX destination, one source pointer on the stack, EAX destination, RET4. This source method has a new C++ ABI.

The allocator/debug word at +0 is untouched. A null source begin means a zero count regardless of source end; destination begin/end/capacity at +4/+8/+C are then cleared and the function returns. With a nonnull begin, signed `(end - begin) >> 2` produces a DWORD element count. The first rejected unsigned count is `0x40000000`; BB6180 calls 00A40AD0 to construct the native `vector<T> too long` length error. A valid nonzero count allocates `count*4` bytes through the source singleton allocation boundary corresponding to 00A3E910/`operator new`, then publishes begin=end and capacity before validating the source range.

The first check compares current source begin with a captured end. If its 00BF6713 diagnostic returns, the second check captures current begin and reloads current end. If that also returns, the body reloads destination begin and calculates the copy size from the first captured end and the second captured begin. It invokes `_memmove_s` only for nonzero byte count, ignores its return code, then publishes end from that calculated size. No fallback for an invalid or repaired source is invented. Backing allocated before a later failure remains in the caller's vector header; BB65A0's exceptional cleanup destroys only the record name.

The source uses `NativeHardwareLayoutTreeLengthError` and the established native SBO message constructor for the length branch, plus `_invalid_parameter_noinfo` and CRT `memmove_s` for their existing library boundaries. Original operator-new, CRT throw/invalid-handler, FH3 and alias behavior is not binary compatible with this C++ interface. No MPAK parser, startup binding, installed archive or game path was executed by this packet.
