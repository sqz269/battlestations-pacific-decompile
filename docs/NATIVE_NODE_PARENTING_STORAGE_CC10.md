# Raw node parenting storage

The source implements the six complete normal bodies below over actual node bytes and live pointer-only array descriptors. It composes the published raw root, scene, tree-unregistration and world providers. Existing logical parenting and the separate requested-null-only destructor projection remain separate source interfaces; neither is used as a substitute here.

All 664 bytes match live Ghidra and the installed PE; the listings contain 241 instructions and 23 calls (17 direct, 6 indirect). Final RET4 instructions are B6E749, B6E093, B6D7F4, B8F536, B8F4B4 and 59E63C, each 3 bytes. No compiler handler is called directly by these bodies, and no new undefined-function boundary is claimed. The worker made no Ghidra changes.

SetParent reads old parent30 before capturing the incoming parent word. Equality returns immediately. An existing parent is unlinked through B6D940, then current A0 is unregistered and cleared; the old-parent-null branch instead propagates a null root. For a nonnull request, the requested parent's profile is captured before the genuine current group-token getter B8E600. Its captured table's current0C target is read afterward; only AL selects the group branch. The selected attachment is captured before child prepend and survives its callbacks. A nonnull selected attachment reaches the child's current1C; a null selection reaches B6D850. Requested null captures rootA4 before clearing30/A4/A0, propagates that captured root, then unregisters attachments recursively. The final dirty-bit path captures flags5C and reads child presence before the flags store; current40 is always dispatched on the changed-parent path.

Prepend captures the child argument, checks parent equality, publishes child30 before propagating the parent's current A4, and checks current child170 afterward. If still null, it captures the child's profile, reads current parent170, then reads current50 and invokes it with recursion1. The linked-list stores preserve current/reloaded head order, wrapping count38 increment, flags and descendant invalidation. Its current40 and SetParent's later current40 both execute; the source does not coalesce them.

Ordinary attachment reads current oldA0 and calls B8F4C0 before capturing its incoming argument. It publishes that captured request and calls B8F460. Because A0 was just published, the native registration equality guard normally returns without appending; no corrective insertion is invented. It then traverses current head/current1C, passing the original captured attachment and rereading each current successor after its callback. Group attachment has no child recursion. Only B8F4F0 executes entry PUSH ECX: its local key is seeded with actual self, then rewritten after oldA0 capture on the removal path. The CMP EAX,EAX/JNZ path is unreachable from normal entry. The first-equal removal uses the address of that actual local key; late incoming request publication and the same registration equality guard follow. B6D7B0 has no such local push/store.

B8F460 captures its child once, compares childA0, captures capacity180 before comparing current count17C, and reserves only on equality. Doubling wraps as a DWORD; the signed result selects doubled capacity only when greater than1. After reserve it rereads current count then begin, tests the computed destination before its store, increments the current count and publishes childA0. No reference count, canonical binding or companion metadata enters this borrowed-key array.

59E5E0 is a full 95-byte normalized instruction clone of B7B390: only the rel32 operand bytes at offsets21h and4Dh differ, and both call the same BF55BE allocator and BF6989 returning free. The source therefore reuses the genuine existing pointer-only reserve helper. B7BED0 and B7B620 are byte-identical 103-byte erase bodies, so group removal reuses the latter. These are distinct original entry identities with proven source-provider reuse, not renamed original callees. Fresh live B7B390 disassembly includes ADD ESP4 at B7B3E1, stores at B7B3E4/E6, pops and RET4 at B7B3EC. Its stale exported gap has already been repaired and published; no new repair is needed.

The array contract is a live `SystemAmbientBacklinks` object over exactly12 native bytes, with nonnegative count <= capacity, accessible disjoint backing, representable allocation size and real singleton allocator/free provenance. Establishing that trivial descriptor lifetime preserves its entire preimage and does not construct a logical group owner. `SceneResource*` is solely the existing helper's opaque pointer representation; neither its layout nor methods are accessed. Native overflow and computed-null copy destinations are outside the reusable helper's admitted valid domain. The raw append still retains its own computed-destination guard and wrapping count store. No custom CRT/container port or duplicate array engine is introduced.

`NativeNodeParentingContext` borrows the existing raw node context, a required exact type/attachment dispatcher and current group-token cell. Scene/tree owner registries and decrement-cell identity must match. All profile resolution is side-effect-free metadata lookup; every reached0C/1C/40/50 target requires a genuine binding, including callback-mutated tables. Known bootstrap predicates require initialized current lineage cells, not cached or invented tokens. Recursive bindings retain prepared frames and fresh acquisitions. Diagnostic-taking entries reject reused acquisitions before native writes. Argument/local frames are initialized, stable caller preimages; group-local self stores and nested argument stores occur only where native code performs them. The source exposes no saved-register/private-stack parity promise.

Failures retain already-published hierarchy, root, scene, attachment, array and flag effects and all persistent nested diagnostics. There is no native rollback or extra retain/release in this packet. Allocation failure propagates through the real existing reserve provider. Host diagnostic and C++ exception transport are distinct from native CRT/FH3/SEH; a failed invocation must not be retried with its consumed acquisition state.

Strict MSVC Win32 build and both configured existing CTests pass. One ignored executable runs an original/source sequence over genuine B6F5A0-created prefixes and separately established actual12-byte descriptor lifetimes. It exercises reserve growth, duplicate-key first removal, the equality guard, real current group/node predicates, both world notifications, an incoming parent-cell mutation during prepend, ordinary current-successor mutation, equal-parent and null-parent paths, and the false-group predicate with inherited currentA0. It compares all18Ch bytes per fixture storage plus initialized backing entries after normalizing physical addresses. Actual counts remain1 and the canonical registry remains empty: this packet performs no ownership admission. The fixture's extra derived tail preimages are caller-owned; it does not claim a full group constructor or terminal.

The original six bodies are copied with their direct-call rel32 operands relocated. All original virtual-load/call instructions remain intact; their fixture tables bind explicit genuine source providers at callable host addresses, and source dispatch validates those exact table/target identities. Numeric original D62C88/D634F8 tables are not overwritten or claimed as executed. Original internal calls use copied B6E010/B8F460/59E5E0, while original attachment virtuals use copied B6D7B0/B8F4F0. Shared callees include raw B6D940/B8F4C0/B6D890/B6D850/B6DA30, pointer-only B7B620, real allocator/free, and raw scene/world/type providers; their machine code is not independently compared here. Controlled callback mutations surround genuine providers and remain fixture evidence, not default production callbacks. Nonnull scene ownership/terminal behavior, native exception transport, private stack aliases, arbitrary derived targets, full binary ABI/application/gameplay are outside this focused proof.
