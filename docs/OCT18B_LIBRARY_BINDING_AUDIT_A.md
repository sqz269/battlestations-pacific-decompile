# OCT18B library binding audit A: CRT, math, Lua, zlib

Audit-only lane `oct18b-libA`, 2026-10-18. No host implementation, binding, dependency revision, game installation, or runtime setting was changed. No game runs were made. The companion STL/compiler/telemetry/xlive audit is [audit B](OCT18B_LIBRARY_BINDING_AUDIT_B.md).

The policy remains to bind library code. A difference in an original library's ABI or implementation is not, by itself, a requirement to reconstruct it: the rebuilt game runs newly compiled code and fresh stock-library objects. An exception needs a concrete retained layout or observable behavior that the binding cannot supply.

The audit establishes no requirement for a broad new CRT, Lua or zlib reconstruction. Preserve the existing selected math/layout pins and decide the small observable behavior gaps explicitly. Lua has verified differences beyond `LUA_COMPAT_LSTR=2`; no additional private zlib codec behavior was found in the reviewed game-used entry/stream contracts. That is not a universal proof of an unmodified library.

The **50 family rows** below comprise **15 bind-safe, 2 layout-bound, 30 behaviour-sensitive, and 3 unreached**. Sensitive rows include already supplied pins and explicitly pending domain/parity obligations; the count is not thirty proved stock divergences or thirty missing bodies. Rows have different aggregation sizes and must not be treated as function totals. The script-only sin/cos/log10 CRT entries are covered in the Lua/math discussion, not counted as native-direct math families or declared globally unreachable.

## Scope and evidence

The original input is `battlestationspacific.exe`, SHA-256 `b682a82c52f81f957b2c70222077305a933f72481686c88843077f714b956dd6`. Live batches verified `C:/Users/sqz269/bsp.gpr`, program `/battlestationspacific.exe`; the saved snapshot reports 76,774 total functions. [The coverage artifact](../reports/oct18b_library_binding_a_coverage.json) retains saved graph callers, every-byte E8/E9 rel32 candidates in executable sections, and absolute-dword candidates in every PE section. It includes the Lua tail at `00C2F3E0..00C2FF90`, in addition to `00A60870..00A776B0`, and the full zlib block `00BC94D0..00BCF90F`.

Raw hits are candidates, not proof of an instruction, function boundary, or reachable rebuilt path. In particular, the three apparent `luaO_fb2int` references and the `longest_match` reference described in the Lua/zlib appendix are overlapping instruction bytes. Nearest preceding snapshot entries are labeled `owner_candidate` throughout the artifact. Named callers in the tables below were checked against live function bodies or explicitly labeled unowned raw code. Negative caller counts never establish that a callback is unreachable.

Class meanings: **bind-safe** applies to the stated, reviewed game-use contract, including its preconditions; **layout-bound** means a retained representation requires a compatible interface, and the table says whether it already exists; **behaviour-sensitive** includes a proved semantic difference or an explicitly identified parity obligation whose bitwise equivalence is unproved; **unreached** is restricted to a stated rebuilt path or conditional branch. Class counts are family rows, not Ghidra functions, instructions, reconstructed credit, or a count of missing implementations.

## Sorting: equal keys are real, but the current binding matched

Verified call instructions are `0094F1CB`, `00B27E68`, `00B813E2`, `00BC356C` to `_qsort`, and `0093FFD9` to `_qsort_s`. The extra instruction `00BD208E` is in a short raw wrapper beginning `00BD2080`; the comparator `00BD2050` tail-calls string comparison. Ghidra currently has no function there. It must not be attributed to preceding `00BD1E80`.

The cloud comparator `00BC2FE0` truncates the difference of two float sort keys; keys less than one unit apart can compare equal, and this equivalence can even be nontransitive. Different puff order can change translucent rendering. The sound comparator `0093F4B0` compares virtual float values, so equal values are possible. String duplicates/case-insensitive matches and equal resource sizes are possible too. Resolution pairs are deduplicated before sorting, and equal full pairs carry identical data. Resource dump ultimately reaches the existing CSV save stub, so its row permutation currently produces no file.

For valid arrays, the inspected original bodies and local Windows SDK `10.0.26100.0/ucrt/stdlib/qsort.cpp` have the same control decisions, including their unstable shortsort. A manifest-embedded Win32 `qsort_probe.exe` copies unchanged original `00BFBE50..00BFC5F6` code, preserving relative calls to original helpers. It compares the actual installed UCRT `10.0.26100.9711`, plus the existing `src/native_qsort_kernel.cpp` projection. Two controlled pointer arrays of 7 and 12 elements exercise the cutoff with cloud-style truncated finite differences and sound-style finite sign comparisons: **4 cases, 0 mismatches** in output identity and comparator argument sequence; the projection also matches for the two `_qsort` cases. This is scoped native differential evidence, not an exhaustive comparator/NaN/fault proof or a game run. The input hashes and exact result are retained in the coverage artifact.

The historical `_qsort_s` helpers have register-heavy internal interfaces; copying the whole original span avoids inventing their prototypes. Invalid-input CRT errno, invalid-parameter handler, exception, and TLS behavior is outside this probe and outside the valid-array recommendation. Neither instability alone nor the mere existence of equal keys justifies new reconstruction when the selected implementation retains the observed schedule.

## Heap and integer binding details

Original `_malloc` selects a CRT-private `HeapCreate` heap and, on older OS modes, a small-block heap or 16-byte rounding. Modern `ucrt/heap/heap_handle.cpp` selects `GetProcessHeap`; `malloc_base.cpp` and `realloc_base.cpp` retain the ordinary storage and failure contracts. Allocation addresses and available memory are not promised equal. The inspected game consumers do not read the CRT's allocation headers. `tools/image_ref_scan.py 0109e1bc 0109ed7c 0109ed68 0109e314` found only original CRT-region references; `_msize` `00C07B5C` is referenced only inside CRT. This is bounded negative evidence, not a global proof of memory safety.

The large-allocation boundary is explicit: `00BD1131 CALL 00BF9F1A` in `00BD1120` uses sizes >=`0x96`; `00BD1201 CALL 00BF9F1A` in `00BD11F0` uses sizes >=`0x81`; `00BD1525 CALL 00BF9DC8` in `00BD1510` releases large string blocks. Their smaller requests use game-owned size rings/arenas rather than SBH. `src/native_string_pool_storage.cpp`, `src/storage_pool.cpp`, `src/singleton_lifetime.cpp`, and the native pool service adapters already preserve the appropriate boundary.

The raw realloc instruction site is `00A87BAD`, target `00BFDCEC`. It belongs to an INT3-delimited sequence beginning `00A87BA0`; there is no Ghidra function here. The preceding seven-byte getter is a different function. Disk disassembly, rather than the function-call verifier, establishes this extra edge. It forwards pointer/size to realloc and logs pointer values without dereferencing the old freed allocation. Telemetry stores malloc/free/realloc function addresses in slots at `00A5D009/00A5D013/00A5D01D`; these are genuine absolute operands, not direct game calls. Companion audit B decides whether the telemetry path runs. Mixing an original allocation with a modern free is not authorized by A02; current source must keep coherent ownership.

For the signed division role, verified instructions are `00B8266B`, `00B827EF`, `00B83817`, and `00B83A1D`. The caller immediately consumes EDX as well as EAX. Additional raw sites `00B81DB2` and `00B82235` have the same target; neither has a live enclosing function, so no named caller is asserted for them. Existing `src/native_scene_registry_query_erase_leaves.cpp` and `src/native_scene_registry_registration.cpp` already implement the exact positive-divisor arithmetic and DWORD wrap; local UCRT `stdlib/div.cpp` and `ldiv.cpp` return the same mathematical quotient/remainder pair. A complete VC8 runtime body or old CRT exception representation is unnecessary for this use.
