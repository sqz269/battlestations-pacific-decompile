## Identity and lifetime

`EffectOwnersGraph` is stored inside the stable application Impl, after `CompilerOwnersGraph` and before `RenderResourcesGraph`. Its construction access borrows the actual VFS string storage, the current renderer cell, and the SAME process `effect_serial_00f8d3a8()` reference. That accessor does not consume/reset the serial or perform native pool startup.

Its destruction access borrows those same strings and `compiler_owners.owners`, which is the application's actual canonical registry. Its `NativeMaterialEffectLoadOwners` uses `texture_loading.geometry`, that destruction access, and the existing read-only `0xD61A00` profile. The provider validates the geometry registration/retained-owner identity and genuine bind/unbind/find targets. The compiler state cache, pass lifetimes and geometry registration share this registry. There is no replacement registry or fabricated callable profile.

The graph's `owners` member is destroyed before its borrowed destruction/construction contexts. The outer graph is destroyed before compiler, shader, texture/geometry and registry dependencies. The application getter requires the actual ready phase and returns references to these three stored members. Callers must keep the application and all borrowed contexts alive through successful loading, retained failed frames and native retirement.

This is host metadata construction: the existing load-owner provider allocates its Impl/list metadata. It is not a native effect allocation or native registration. The existing completed-creator API can move Programs/create an Entry before later companion/binding operations fail. Completed effects and failed frames therefore require their original explicit lifetime obligations. Native terminal cleanup, exact canonical unbind, Entry erasure, caller postcallback completion, and all borrowed users must finish under quiescence before backing/context disposal. No automatic retain, rollback, retry, default payload or partial-construction admission is introduced.

`requires_process_retention()` and application drain admission remain unchanged in meaning. They inspect existing phase/shader/shadow state; they do not discover externally retained effect frames or outstanding effect Entries. The load-owner destructor still requires an empty Entry list. Merely exposing this view does not make early application destruction safe.
