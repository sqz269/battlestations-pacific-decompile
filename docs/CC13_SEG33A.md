## Conventions used in the code

- Archive fields go through the archive's slots +4h (open section), +8h (close), +0Ch (write field) and +10h (read field); keys and values are the 8-byte by-value `{kind, value}` pairs (`ArchiveArg`). A kind-3 (byte) write fills only the low byte in the image; the upper three bytes are stale stack there and zero here.
- Where the image reads an uninitialised stack slot after an archive read that may not write it, the code reproduces the slot's known prior value (006E6360, 006E6A60, 006E6B10, 006E7850 ownerType); where the prior value is unknowable (006E7850's bbv vec3 and tracers byte) it starts at zero. Both are noted per row.
- x87: operand direction was read from the bytes (006E1B21 `DE E9` FSUBP, 006E1EBB and 006E6E4E `DE F1` FDIVRP). Extended-precision intermediates are modelled with double and one final float rounding.
- Intrusive references: [00CE221C] InterlockedIncrement / [00CE2220] InterlockedDecrement on object+4, vtable[0] at zero (the helpers `ref_add` / `ref_release`).
- The inlined entity-handle lookup (ids split at [00F89A10] between the tables at [00F89A54] and [00F89AA8]) is reproduced through `HandleTables`; 006E1930 and 006E6B10 test id 0 first, 006E4B60 and 006E4C10 do not.
