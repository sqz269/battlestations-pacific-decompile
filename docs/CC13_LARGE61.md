# CC13 large61: the large segment 61 functions (cc13-large61)

Packet cc13-large61 took the six large segment 61 functions that cc13-left61 and cc13-avoid1
left (docs/CC13_LEFT61.md, docs/CC13_AVOID1.md). Code: `include/bsp/cc13_large61.hpp`,
`src/cc13_large61.cpp`. Every call the image makes is a `Large61Host` method named for its
target, invoked at the same point with the same arguments; field reads go through `Raw`
(shared with cc13_left61). Names are hypotheses, not recovered symbols.

Status for every function below: reconstructed, build-tested only. New C++ interfaces, not
ABI-compatible, not fixture-tested, not game-validated. None of them draws from the shared
RNG 00BD2F10. Not modelled anywhere: the EH unwind states (the destruction of temporaries
on a throw).

## Uncertainty and simplifications

- 00947BC0: the decompiler's view is confirmed against the listing (argument slots ESP+24h..+3Ch
  after the five pushes).
- 00945450: 00F87574 is BSS (zero in the image). Whether 004C6BA0 can return null on this
  path was not checked; the native calls vtable+88h on the result unconditionally, and so does
  the reconstruction. The ECX/EDX roles of 00B64640/00B646E0/00B64780 and 004134F0 follow
  `include/bsp/frontend_seg16_24_28_cc13.hpp` and `include/bsp/camera_projection.hpp`.
- 0094BFF0: 004C7AA0's body was not read. Its 28h-byte result is used only through out+10h and
  out+1Ch. The reference frame buffer is sized 58h, the room the frame leaves (+108h..+15Fh); its
  true size comes from 008F84D0, which was not read.
- 0094B600: the 00946D70 tag in the host branch is a stale stack dword (the by-value string slot
  address of the last iteration). 00946D70 does not interpret it, so the reconstruction passes 0.
  ST0 results of 00946970 and 00946F00 are kept as doubles. The x87 divisions (FDIVR D8 F9 at
  0094B8CD and 0094BF25, read from the bytes) are computed in double, then stored to float. The
  extended-precision double rounding can differ in the last float bit in rare cases.
- 0093D2D0: 00B74310 is called with the scene still in ECX; it was not read whether it uses
  ECX. The x87 FADD/FMUL at 0093D6E9/0093D727 (and their copies) are DC-form, read from the
  bytes (DC C1, DC C9), so the 6000 and 0.5 are applied, as the decompiler shows.
- 0093FF10: the pseudocode drops ECX and most call arguments; everything here is from the listing. The x87 forms at 009404FF (DC C9), 0094099E (DC F9) and 009409B5 (D8 C9) were read from the bytes. The distance sums and the volume quantisation are computed in double here, while the image keeps the intermediates in extended precision; the last float bit can differ in rare cases. 0093FA70's fourth argument is the sound pointer (cc13_left61 types it as a float `z`). The by-value options copy passed to 0093FE90 is owned and destroyed by the callee. The local array destructor's reallocation and zero-fill branches are reproduced, although they only run for a negative capacity or count.
