# CC13 gameplay band 00800000-0084FFFF (cc13-gp80)

Packet `cc13-gp80`, Claude worker in the cc13 lineage, 2026-10-12. Gameplay code owned by cc9, whose
lanes are paused. This is a metadata pass plus a few build-tested leaves in the cc13 band file. No
host file was edited, nothing was wired into a host and no game was run.

Names are hypotheses, not recovered symbols. Every ledger row (`config/names/0080..0084*.jsonl`,
evidence prefix `cc13-gp80`) carries the evidence: Lua binding callers, string immediates,
vtable slots read from the PE on disk, the MT_ name table at `00E0AB68`, and the caller spine.
Rows whose evidence starts with "Provisional" rest on body shape and caller context only.

## Method

- Input: `python tools/raw_ownership_cc13.py list cc9` filtered to 00800000-0084FFFF, 480
  functions (Ghidra `FUN_`, no tag, no ledger name). All 480 were exported live first; only
  about 40 had exports before.
- Triage by `local/gp80_triage.py` (callers/callees with resolved names, strings) and compact
  pseudocode (`local/gp80_peek.py`). Assembly was read wherever a claim depended on a compare, an
  x87 sequence, a register argument or a jump table (00805990, 0080B190, 008127E0, 00828EC0,
  008457E0, 0084CF80, 0084EB80, 00847030, 0080E290, 00835840, 0080E0F0, 0080E1B0, 00812B00).

  `BSP_SessionMessage_ConstructBase` and the MT_ table at `00E0AB68` (`local/gp80_pe.py msg`).
- Vtable slots were read from the PE on disk (`local/gp80_vt.py`, `bsp.py scan-bytes`).
- Generic engine containers use the existing `TMPL_` convention (`TMPL_DList_*`,
  `TMPL_PtrArray_*`); std:: algorithm and vector instantiations use `STL_*_<addr>`. All are
  ledger names, not tag rows.
- Ghidra: renames and plate comments through `tools/ghidra_annotate.py --apply` (prior state in
  `local/ghidra-annotations-20261012T211333Z.json` and `...T212544Z.json` in the worktree).

There was no `docs/CC13_BAND_008*` file for this sub-band beyond `docs/CC13_BAND_0080_008F.md`,

## Findings worth a second look

1. **The turn-path planner is dead code.** 0080CFB0 builds left/right turning circles from a
   start heading and four circle pairs with a goal heading (fsin/fcos of heading -+ pi/2), then
   scores candidates into planner+14h..+38h. It has no direct caller, no absolute dword and no
   Ghidra xref. Its helpers (0080B1F0, 0080C060, 0080C590, ...) are left raw.
2. **"Firepower" is barrel counts.** 00812310..008124C0 sum gun+448h (the barrel count,
   docs/CC13_FLAK_FLYTIME_BURST.md) over the artillery/aa/torpedo/depth-charge category lists at
   bind time; 008127E0 divides the live sums by them for `GetFirepower`. The aa live sum
   (00812600) counts 1.0 per aa device (double 00D7A210) and never tests the dead byte +3B8h,
   unlike the other three, so a ship's aa ratio is mounts / barrels and does not fall when a mount
   dies.
3. **`BSP_Ship_ResetRandomTorpedoBarrel` (0081DCB0) draws from RNG stream 1**, not the gameplay
   stream 0: `BSP_Random_UniformFloatRange((void*)1, 0, n)`.
4. **`0081BA80` writes `guncamos.lua`**: it sets `guncamos[index] = {r, g, b, a}` and saves the
   table through the file system. It is unreferenced (a tool path).
5. **Ghidra split** at `0084DDC1`, a function start inside `BSP_PlaneSquadronCommandBlock_BeginCommand`
   (0084DDA0). Left as is; the ledger row of 0084DDA0 records it.
6. **`BSP_VehicleClass_IsTorpedoProofSmallCraft` (00828EC0)** answers true for a torpedo boat
   (0Eh) or a landing ship (0Ch, byte +808h clear) whose float +500h is at least 8.938947
   (00D099AC). `src/attack_commands.cpp:140` takes its result as an input
   (`torpedo_target_blocked`); the leaf below gives the rule.
