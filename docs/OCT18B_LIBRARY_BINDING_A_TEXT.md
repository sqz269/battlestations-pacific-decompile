# OCT18B CRT text, parsing, state and I/O binding audit

Audit date: 2026-10-18. Scope is the original CRT/library window `00BF0000-00C30000`; game code near the beginning of that window is not automatically CRT. This is a binding audit, with no vendor-body reconstruction, source rewiring, host changes or game runs. Descriptive names already in the ledgers remain hypotheses unless they are recognized library names. Math/x87, heap/new/div and Lua API surface differences are owned by the companion audits.

The high-risk boundaries are numeric text, locale/ctype objects and CRT-owned streams. The random arithmetic matches the local UCRT implementation; the clock source does not. No selected family is proved unreachable. Public byte operations are qualified binding candidates on their defined input domains, not a proof that every original call has that domain.

## Family classifications

`bind-safe` below means a typed stock binding on the explicitly stated normal domain. `layout-bound` means original objects or owner state cannot cross directly to a different runtime. `behaviour-sensitive` requires a compatibility decision or evidence for the caller domain. These are family rows, not reconstructed function counts.

| Family | Class | Original surface and caller-domain result |
|---|---|---|
| Byte copy/move/fill | bind-safe, qualified | `00BF7680` memcpy, `00BF87E0` memmove, `00BF79F0` memset. Byte results/returned destination admit ordinary Win32 bindings for valid storage, correct count, and memcpy non-overlap. The 2,439 saved memcpy callers are not a proof of non-overlap, fault/read-ahead identity, or zero-count invalid-pointer behavior. Preserve explicit memmove where aliasing is possible. |
| Non-locale C/UTF-16 string operations | bind-safe, qualified | strncmp/strchr/strrchr/strncpy/strstr/strncat and the 16-bit substring body `00BFD341`. Match terminated/size-bounded inputs, padding and returned interior pointers; comparison consumers must use sign unless exact magnitude is proved. Original fault/access scheduling is outside this qualification. |
| Secure memory/string calls | behaviour-sensitive | memcpy_s/memmove_s/strcpy_s/strcat_s/strncpy_s expose destination clearing, errno and original invalid-parameter dispatch, not just a copy. Normal valid-buffer success can bind; no whole-caller proof excludes failure branches. |
| Narrow printf/sprintf/vsprintf families | behaviour-sensitive | Integer, text and float formats coexist. `00BF7A6A` builds an original local FILE with count INT_MAX and flag 0x42 before the original output engine. Numeric text reaches NativeString and Lua strings; current UCRT formatting options, rounding and locale must be selected explicitly. |
| Wide formatting families | behaviour-sensitive | `00BF96F6` is used by credits formatting; `00BFE105` by PIPEIPC. Count/termination/truncation and old wide-format specifier conventions need their own caller constraints; an identically named modern entry is insufficient. |
| scanf/sscanf | behaviour-sensitive | `00BF7533` and `00BF7573` use different scan engines despite the same ambiguous FID label. Scene token readers use `%f`/integer scans and inspect assignment count; successful prefix parsing is observable. No complete malformed-input or string-width domain has been established. |
| atof/strtod floating parsing | behaviour-sensitive | atof `00BFA66C` and Lua's `00C0373C` wrapper reach the original `_LDBL12` conversion path. Float rounding, underflow/overflow, accepted spelling, end pointer and errno affect parser acceptance or resulting values. There is no equality proof over supplied assets, script strings or caller-generated text. |
| strtol/strtoul integer parsing | behaviour-sensitive | Lua's hexadecimal fallback calls `00C034AC` with base 16 and converts an unsigned 32-bit result to double. Preserve Win32 unsigned-long width, endpoint, whitespace, overflow/errno and locale. A 64-bit host `unsigned long` would be a distinct contract. |
| rand/srand | behaviour-sensitive, algorithm matches | `00BF98CF`/`00BF98C2` use a per-thread provider word at +0x14. UCRT uses the same 32-bit LCG and 15-bit result. | _time64 ordinary UTC seconds | bind-safe, qualified | `00BF9886` and local UCRT `time.cpp` both use GetSystemTimeAsFileTime and convert to Unix seconds, with optional 64-bit output. | clock | behaviour-sensitive, concrete implementation difference | `00BFD2C7` subtracts original startup FILETIME and divides by 10000. Current UCRT uses QueryPerformanceCounter/frequency and returns -1 on failures, negative delta or LONG_MAX overflow. Original low-32-bit result, wall-clock adjustment and quantization differ. Script os.clock and telemetry consume the result. |
| Calendar/local time/strftime | behaviour-sensitive | Lua OS wrappers reach difftime64/gmtime64/localtime64/mktime64/strftime. These remain tied to the selected CRT time-zone, locale, buffer and invalid-time behavior. No complete date range, TZ/DST history or concurrent returned-buffer contract was audited. |
| Locale and C++ ctype vectors/facets | layout-bound | `00BF5879` returns an original 16-byte vector with table allocation/ownership; linked STL callers copy it into retained facet fields. `00C027AC` and `00C03806` also expose mutable locale state and lconv pointers to Lua. Rebuild the complete stock consumer/runtime together, or adapt the original layout and owner contract. |
| Public ctype/case mapping | behaviour-sensitive | toupper/tolower/isspace have original C-locale fast paths plus locale-dependent slow paths. Caller strings can contain bytes outside ASCII and some callers pass sign-extended char. Do not replace them with fixed ASCII transforms or assume every int is in the public ctype domain. |
| FILE and descriptor I/O | layout-bound | Original fopen/fread/fwrite/fseek/ftell/fclose/fflush and inline consumers share one CRT's buffers, locks, text translation, descriptors and errors. | mkdir/remove/rename paths | behaviour-sensitive | Original wrappers use CreateDirectoryA/DeleteFileA/MoveFileA with original DOS-error mapping. Local UCRT converts narrow names to UTF-16 using its compatibility code page; `_wrename` uses MoveFileExW(COPY_ALLOWED). Same-directory ASCII success may agree, but full error/encoding/move equivalence is not established by inspection. |

Family-row totals: **3 bind-safe (all qualified), 2 layout-bound, 11 behaviour-sensitive, 0 unreached; 16 total**. None of these counts conveys new reconstruction or gameplay credit.

## Original versus stock details

The original rand listing is CALL `__getptd`, read +0x14, IMUL by 0x343FD, ADD 0x269EC3, store +0x14, SHR 16, AND 0x7FFF. Seed is CALL the same provider then store its argument at +0x14. Original PTD initialization `00C050F8` writes seed 1; `00C051B7` allocates 0x214 bytes on the selected thread-storage path and records GetCurrentThreadId. UCRT `stdlib/rand.cpp` has identical constants and initializes through its own `__acrt_getptd` state. This proves matching arithmetic, not common TLS identity or interchangeable PTD layouts. The companion Lua audit confirms that the original registered math table omits random/randomseed; do not invent a Lua->original-rand edge from a generic Lua source tree.

The original clock assembly obtains FILETIME through the IAT, subtracts globals `0109DDD8/0109DDDC`, divides unsigned 64-bit by 0x2710, and returns the low result in EAX. There is no matching negative-delta/LONG_MAX branch in this body. UCRT `time/clock.cpp` stores QueryPerformanceFrequency/start_count, scales the QPC delta to CLOCKS_PER_SEC and bounds it. This is a concrete service change, although no failing game behavior was observed or claimed.

Original floating parsing `00C03621` uses locale update, ctype whitespace, `__fltin2` `00C13A3F`, end-pointer update and conversion flags/ERANGE. `__fltin2` reaches the original 12-byte long-double path and `__ld12tod`. Its prototypes contain propagated errors: an apparent locale argument derived from strlen is not reliable type proof. UCRT `convert/strtod.cpp` instead calls `__crt_strtox::parse_floating_point`; `inc/corecrt_internal_strtox.h` explicitly implements hexadecimal digits and infinity/qnan/snan forms. This audit does **not** assert a particular spelling is rejected by the original without inspecting its complete parser or probing it. It records a different conversion implementation and an unclosed caller domain.

UCRT `convert/cvt.cpp` lines 786-847 exposes three relevant options: legacy MSVCRT versus C99 exceptional strings, three versus two minimum exponent digits, and legacy versus standard rounding. `inc/corecrt_internal_stdio_output.h` passes formatting options into that converter. No explicit compatibility-option setting was found by the scoped source/include/cmake search. The original `__cftog_l` `00C06652` selects `__cftoe2_l` `00C05EA1` for exponential output. That helper copies literal `e+000` at `00D6A5D4` and only removes its first exponent zero when global `0109E9B0` mask 1 is set. The analyzed image bytes of that initial global were zero; this was not a running-game memory sample. A separate absolute-reference scan found a setter-shaped unregistered body at `00C270C7` (write `00C270F5`) and getter at `00C270FE`; neither entry had rel32 or absolute-dword references in the full-image scan. They were not silently treated as absent because Ghidra had no function there. Assembly confirms the exponent branch and three-byte memmove. The inspected UCRT printf-options storage defaults to zero, and its converter defaults to two exponent digits. **Static counterexample prediction:** without either compatibility setting, Lua `%.14g` of the exactly representable value 1e20 emits original `1e+020` versus current-default `1e+20`. This is an inference from the two implementations, not an executed differential result; indirect setter writes, options supplied by other startup objects and a complete formatter comparison remain outside the proof. General `%f`/`%.14g` byte equality is not established by matching format strings. Normal finite float32 `%f` may be easier to qualify than arbitrary Lua doubles, but this audit did not assume its entire input range.

Original secure copy `00BF672C` returns zero immediately for count zero; on invalid nonzero requests it can zero the destination, set EINVAL/ERANGE in original errno and call original invalid-parameter dispatch `00BF66EF`. `00BF93A4` similarly empties a bad destination before dispatch. Replacing only the byte operation drops visible error/state behavior.

Original `__Getctype` assembly, unlike its misleading propagated field names, writes four words at offsets +0,+4,+8,+C. It allocates 256*2 bytes, copies the ctype table, sets ownership=1, or uses the original table and ownership=0 on allocation failure. The linked facet copies and eventual frees make this an observed layout/lifetime boundary. For streams, original `00BF7A6A` directly builds old FILE fields; UCRT `inc/corecrt_internal_stdio.h` instead defines a pointer-sized public FILE over a larger private stream with `_ptr`, `_base`, `_cnt`, flags, descriptor and CRITICAL_SECTION. Whole-stock rebuilt Lua inline stdio consumers use their own headers coherently; they do not prove an original FILE object is layout compatible.

## Risk order and completion

1. Preserve or qualify numeric text/parse behavior first: direct data-loader calls and registered Lua conversions have open input ranges and affect values, token acceptance, interned strings and emitted text.
2. Preserve coherent locale/facet and FILE ownership. Direct original private vectors are established; coherent opaque stock stream usage can be adapted without asserting old layout identity.
3. Decide clock semantics explicitly for script and telemetry paths. The implementation difference is established; gameplay impact has not been measured.
4. Preserve rand's state/thread/seed schedule. Its arithmetic already matches this UCRT and original Lua math.random is absent.
5. Qualify ordinary byte/string success and ASCII same-directory filesystem operations only as far as caller constraints support. Retain error, overlap, encoding and bounds qualifications.

Validation: original-call verifier checked 22 direct CALL claims with 0 failures. Its 2 unchecked prose claims (integer parsing and secure-copy dispatch) were independently body-read; 2 range warnings concern this audit scope crossing function boundaries, not an asserted whole function. Body/assembly reads, primary raw rel32/absolute scan and a supplemental scan of the formatter mode global/accessors were performed. Ten representative names receive additive audit evidence while retaining existing names; no reconstruction ledger, tags, Ghidra names/comments or Source/build registrations are changed. Remaining original ABI/runtime/gameplay equivalence is unproved.
