# cc13-sweepC: leftover sweep of segments 30, 50, 54-91

Packet `cc13-sweepC` (2026-10-16). It closes out the functions earlier cc13 waves left without a
reconstruction record in segments 30, 50, 54, 58, 60-65, 69-71, 73-75, 77, 79-83, 86, 87, 89, 90
and 91. Segments 30 and 50 were mostly "hosted references not re-verified" in
`docs/CC13_SEG30.md`; each was checked against its host and recorded here.

Status vocabulary: "reconstructed_build_tested" means the routine is in `src/cc13_sweepC.cpp`
and builds. None of it is ABI-compatible, fixture-tested or game-validated, and none of it is
bound into `bsp_game`. Names are hypotheses, not recovered symbols.

## Model

`include/bsp/cc13_sweepC.hpp` declares every routine in `bsp::cc13_sweepC`. Each routine works
on the original object as raw bytes with the image's offsets. Every engine call goes through
`SweepCHost`, whose methods are named after the image routine or virtual slot they stand for,
with the register inputs in the comment. Calls between routines reconstructed here use the C++
directly (for example `006CC5C0` calls `air_ops_publish_slot_006bf150`). Constants carry their
image address and width; the floats and doubles were read from the PE on disk.

Common points, also stated per routine:

- The engine's tracked lock (`EnterCriticalSection` then `+18h += 1`, and the reverse) is
  `lock_enter` / `lock_leave`.
- Debug-iterator range checks call `invalid_iterator_00bf6713` at the same points as the image.
- Copies the image makes with x87 `FLD`/`FSTP` float pairs are plain float copies (they differ
  only for a signalling NaN). x87 arithmetic is written in `double`, which matches the image under
  the 53-bit precision control MSVC sets; any double rounding is stated where it can occur.
- A frame dword the image passes as an out argument without initialising it is seeded with what
  the image leaves there (the slot of an entry `PUSH ECX`), not with zero.
- Vendor bodies (CRT, Lua, STL instantiations, compiler-generated deleting destructors) are out of
  scope: they are called through host methods where a reconstructed routine needs them, and are
  recorded by name only.

Census evidence ("no caller") is `tools/callsite_census.py` (rel32 CALL/JMP plus absolute dwords
in .text, .rdata and .data) with a positive control in the same run, as each row says.

## Adoption notes (gameplay hosts not edited)

1. `006BF150` (the slot publication) is not called by any host: the air-ops slot fill
   (`air_operations.cpp` `air_ops_fill_slot_006c0f00`, on a class change), the land-task retire
   (`game_hosts_units.cpp` 7246-7287) and the stock trim (`script_natives_fix5_cc13.cpp`
   `air_base_remove_stock_006c7b10`, which also omits the final `00984EB0` stock notice) all skip
   it. The publication reaches the session (`0077C7B0`) and the slot observers (`00696350`); in a
   single-player session its visible effect is the slot notification. LIVE: not established (the
   hosts model no session peers); no RNG involvement.
2. `00968550`: `update_warning_deadlines` reports the hit-text expiry through its return value
   and `game_hosts_mission_frame.cpp` 712-723 records it instead of calling
   `[[[00E198C4]+C4h]+60h]->vtable[34h](0)` (presentation only).
3. `unit_state_message.hpp` names `unit+110Ch` as the source of the flooded byte; the listing
   (00813D5D) compares `unit+10D0h` with 0.5f.
4. `0080F9A0` / `006D20E0` IsKindOf tables (`unit_kind_query.cpp`) omit the `[unit+C4h]` compare.
   For an MAirfield it is the same answer (`006D1C20` stores 45h there).
