# Genuine-provider Icon delayed singleton qualification

This is one private host-driven fixture of the already-reconstructed AB5700
getter and D5C4B8/AB57C0 terminal, using the accepted process service and actual
VFS/string/manager/deletion graph. It adds no body credit, raw Icon/widget,
queue, UI activation, production lazy caller or Original ABI claim.

Before entry the host prepares the permanent process metadata and installs the
SAME genuine deletion service, as in `CODEX_GUI_ICON_PROCESS_HOST_LINK.md`.
The private C++ constant `kGuiIconDelayedLifecycleQualificationCc16Bound`
defaults OFF. Its qualification build invokes AB5700 once after metadata bind;
no public switch, environment flag, native test substitute, manual unregister
or terminal call is introduced. This early host-driven fixture is not proof
of the original Icon caller schedule.

Admission requires a nonnull same publication and a completed getter operation
with its actual allocation identity, entered/completed captured manager section
and returned registration. The host keeps an ADDRESS ONLY for later comparison;
the existing manager remains the native owner. Every fixture failure closes the
log and exits while retaining the provider graph, without guessed rollback.

Real shared drain must pop that owner through the existing D5C4B8 dispatcher.
Only after full renderer/fallback return and idle/null-publication/null-manager/
same-deletion-service checks does the fixture inspect the retained independent
operation metadata. It requires scalar-delete, complete, the SAME address,
flags1, and backing/object free entry followed by completed operation return.
There is no post-free payload read. A later repeated host drain does not claim
another native retirement. Nonempty cancellation, delayed delivery, failures,
flags0, destructive reentry, reuse and game/visual behavior remain unproven.

Pre-registration: freeze one qualification-ON executable/DLL plus source and
configuration hashes; run exactly one 60-frame startup/teardown case at Normal
runner priority on slot4/core10. Keep DEATH_TABLE/RNG_STREAMS1 and otherwise
clear BSP variables. Preserve its full log/manifest. Require exit0, one getter
and one retirement record, full-drain-before-retirement order, and final COM0/0.
This is not a paired OFF/ON gameplay or activation gate; the earlier idle
smoke is separate metadata evidence. Restore the route OFF and rebuild before
publication. Source review, build and runtime results are pending.
