# Native VFS search groups (BD)

These three source interfaces write the **actual** `00BE1DC0` manager's `+60` intrusive search-group list. They accept an actual A0h manager and actual eight-byte pooled string headers, borrowing its existing `ActualNativeStringPoolStorage` and returning invalid-parameter callback. They do not use `VfsCandidateRegistrations`, `std::map`, a projected mount context or a second lifetime manager.

The `+60` list's head is `+64`, count `+68`. Each allocated 28h group node has links at `+0/+4` and a 20h payload at `+8`: counted group name at `+8/+C`, extension list at `+10` (head `+14`, count `+18`), directory list at `+1C` (head `+20`, count `+24`). The opaque list-owner `+0` words are left untouched, including in native temporary payloads. The existing 004C3020 sentinel allocator supplies each nested 10h head; 004CE6F0 and 004CE780 supply actual pooled value nodes and the 1FFFFFFF list-count guard. The new outer group uses the BE1A20/BE13E0 reached allocation/copy behavior from an actual 20h temporary payload, including a second pair of sentinels, then the BEDED80 07FFFFFF count guard. On success, the detached node is linked before the old first node; the temporary payload and lowercased group copy are destroyed before the value node is allocated. A later count error leaves the detached node allocated as in the native call sequence.

`00BE25E0` forwards `(group,extension,selector=0)` without copying either header. `00BE2600` copies the directory, lowercases it, replaces backslashes, appends a slash if needed, then forwards selector 1 to `00BE2310`; the common routine copies/lowercases it again and selects the directory list. `00BE2310` first scans the outer group list using a separate lowercased group copy and equal counted length plus case-insensitive comparison. New groups prepend. An existing group keeps its position. Values append immediately before the selected list sentinel, retaining registration order; equal counted length and case-insensitive match suppress a duplicate. Selector 0 uses extension list, selector 1 directory list. The source mirrors the valid initialized-manager, nonempty-directory domain; native `directory[length-1]` is unsafe for an empty directory and no safe default is invented.

Original ABI: `00BE25E0` and `00BE2600` take ECX manager plus two stack DWORDs and end in RET8; `00BE2310` takes ECX manager plus three stack DWORDs and ends in RET0C. The C++ APIs add explicit storage/callback borrowing and are not binary replacements. Live Ghidra program was verified as `/battlestationspacific.exe`; disk/live bytes, contiguous Capstone decoding, saved listing and per-instruction saved owner agree for `BE25E0[20]` 7/7, `BE2600[242]` 82/82, `BE2310[684]` 231/231. The report records 31 direct calls within those bodies and 32 external direct startup callers, with owner-checked callsites. No saved-body gap was found.

The separate `00BE1480` `+54` extension-prefix tree route and the 14 KB `00738360` literal registration body remain dependencies for full application startup. This packet only provides storage operations for source callers that supply exact actual headers and manager cells. Native FH3/SEH and legacy exception identity, malformed list accesses, and concurrent publication mutation are outside this bounded source interface. A Win32 build is source validation, not archive/game execution.
