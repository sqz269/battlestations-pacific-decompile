# Segments 19 and 21: session browser, loading screen, mission tree groups, movie screens (cc13-seg19-21)

Segment 19 is 0056D9A0-00580530, segment 21 is 005C57D0-005CCE70. Code:
`include/bsp/frontend_seg19_21_cc13.hpp`, `src/frontend_seg19_21_cc13.cpp`. Status: **reconstructed
and Win32 build-tested only**. No fixture, nothing run in game, not ABI-compatible. Names are
hypotheses (the ledger's Ghidra names; FUN_005CAFF0 and FUN_005CB160 got names here). No agent/argon*
branch adds addresses in either range (checked against origin/main on 2026-10-13) and the lease
table had no other holder.

Conventions follow docs/CC13_SEG20.md: objects are raw image storage (`Raw::at`), every engine routine
the image calls is a named `Seg19_21Host` method invoked at the same point, vtable pointers are written
as their image addresses. Native string temporaries are built exactly as the image inlines them
(`native_string_build`: a zeroed {0, null}, 0041DD40(length, 1), memcpy of length + 1 when a buffer came
back) and released through 00419CC0 / 00BD1510(buffer, length + 1, 1). CRT `memcpy` / `memset` are
called directly. SEH unwind paths (destroying partly built objects when a callee throws) are not
modelled anywhere in this file.

## Notes on the arithmetic

- 0057BF10 sums the six weights at 00E08764 (0.04, 0.15, 0.3, 0.25, 0.25, 0.01) below `phase`. The loop
  is unrolled by four when phase >= 4, and each partial sum is stored to a float. The last term
  `weight[phase] * fraction + sum` is rounded once. +30h becomes max(old, value). +2Ch is raised to
  `trunc(value * 128.0)` (00CEF258). The x87 register still holds the new value at that point, not the
  maximum. The C++ does the last term in double rather than 64-bit x87, so a last-bit double-rounding
  difference is possible.
- 005CBD90: opening adds seconds * 0.0625 (double 00CEF290) and closing subtracts seconds / 20.0
  (double 00CE3D88). The bytes `DE E9` at 005CBDE6 are FSUBP ST1,ST0, which computes value minus
  quotient. The bytes `DE E1` at 005CBE8E are FSUBRP ST1,ST0, which computes 1 - value. Other
  constants: -0.01f (00D7A300), 0.0f (00D7A218), -1.0f (00D7A260) and -20.0f (00CF180C). The same
  double-versus-extended caveat applies.
- The MovCam divisions are x87 float / float rounded to float. These give the same result as a float
  division.
- 005CBA50 reads its argument with FILD (an integer) and multiplies it by the double
  1.5707963705062866 at 00CE3830. The earlier ledger note ("time scaled") did not account for that.
